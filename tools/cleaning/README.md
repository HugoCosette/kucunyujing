# 网布总表清洗合并工具

以【产品资料】为 SKU 全集，按唯一标识左连接各分表（出入库明细、库存结存表、欠货表、生产排单），输出总表。
每一列的计算口径见下方「总表每一列怎么算」，业务规则原文见 [清洗提示词.txt](./清洗提示词.txt)。

> **清洗口径只有这一份**：[engine.mjs](./engine.mjs)。
> 网页的「导入分表」通过 `src/cleaning/engine.js`（一行转发）引用同一个文件；
> `clean-merge.js` 是本目录的命令行入口（定位文件、SheetJS 读表、写 `output/`）。
> 改清洗逻辑 = 改 `engine.mjs`，网页和命令行同时生效。

## 单独复制走使用

本目录是自包含的（`engine.mjs` 就在里面），整个复制到别处即可直接运行：

```powershell
cd <新位置>/cleaning
npm install      # 首次
npm run clean    # 读取 data\，输出 output\总表_清洗结果.xlsx 和 output\销售表.xlsx
```

> 注意：网页侧通过 `src/cleaning/engine.js` 引用本目录的 `engine.mjs`，
> 所以**本目录不要从应用仓库里删除或改名**；要改位置就同步改那一行转发。

```powershell

npm install      # 首次运行

| `output/销售表.xlsx` | 销售表 | 44 | `唯一标识、品名、颜色` + `月均条数、订单总数、动销月份、动销客户、累积条数` + `1月条数、1月重量、1月订单数 … 12月条数、12月重量、12月订单数` |

```

销售表：唯一标识 | 品名 | 颜色 | 月均条数 | 订单总数 | 动销月份 | 动销客户 | 累积条数 | 1月条数 | 1月重量 | 1月订单数 | … | 12月条数 | 12月重量 | 12月订单数

`columnOrder` 和各输出表都没用到的已配置列不会输出，日志同样会提示。

## 两张表的计算规则

行集合：以【产品资料】的全部 SKU 为基准（31684 行），再加上各分表里"基准完全没有"的 SKU（当前 9 行），共 **31693 行**。

| 列 | 数据来源 | 计算口径 |
| --- | --- | --- |
| 唯一标识 | 产品资料 | `品名｜颜色`：两段各自去掉首尾空格、换行统一为 `\n` 后用 `\|` 连接；产品资料内部按它去重，只保留首次出现的那行 |
| 品名 | 产品资料 `品名` | 原值输出；追加行取该分表原文 |
| 颜色 | 产品资料 `颜色` | 原值输出；追加行取该分表原文 |
| 色彩 | 推导列 | 唯一标识含「本白」「大白」「黑白」「黑色」任一 → **黑白**，其余 → **彩色**；不参与唯一标识拼接 |
| 生产中 | — | **暂无数据源，整列 0**（见下方"暂时缺数据的列"） |
| 欠货 | 欠货订单导出 `欠货总数量` | 同一 SKU **求和**；按 `产品名 + 颜色` 关联；`"130 KG"` 这类带单位文本取前面的数字，`"-"` 记 0 |
| 周消耗 | 本表 `月均条数` | `月均条数 ÷ 4`（一个月按 4 周计），四舍五入保留 **2 位小数**。`月均条数` 本身只输出到销售表，这里仍按内部值计算。**注意**：月均条数现为「累积条数 ÷ 动销月份」，所以周消耗比 1.4.x 时期小约 4 倍（旧版误把累积条数当成了月均） |
| 周转入 | — | **暂无数据源，整列 0** |
| 在途库存 | productionScheduling `进仓重量` | 同一 SKU **求和**；`品名` 或 `天鸿颜色` 为空的行整行忽略；同一品名下颜色尾部多出符号/英文的并入基准那一行 |
| 在仓库存 | 库存结存表 `数量` | 同一 SKU **求和**（一个 SKU 在多个仓库有多行会累加）；匹配不到填 0 |
| 总出库数量 | 出入库明细 `出库数量` | 同一 SKU **求和**；**只统计出库数量 > 0 的行**（销售退货、纯入库行不计） |
| 累积条数（销售表） | 出入库明细 `出库数量` | `总出库数量 ÷ 单位换算系数`：`单位=码 → ÷100`、`单位=公斤 → ÷20`，其它单位（件/条/空）记 **0**；结果**四舍五入到整数**。即该 SKU 历史累计出货多少条（1.4.x 的「月均条数」就是这个算法） |
| 月均条数（销售表） | 本表 `累积条数` ÷ `动销月份` | `累积条数 ÷ 动销月份`，保留 **2 位小数**；动销月份为 0 时记 0 |
| 订单总数（销售表） | 出入库明细 | 该 SKU 在明细里的**行数**（同样只算出库数量 > 0 的行），1 行 = 1 单 |
| 动销月份（销售表） | 出入库明细 `做账日期` | 每行解析出「年-月」→ 去重 → 取**最长连续月份段**的长度；中间断开就取最长那一段，跨年（12 月→次年 1 月）算连续 |
| 动销客户（销售表） | 出入库明细 `客户` | 该 SKU 的**去重客户数**（`agg: "distinct"`，空值不计）；明细表没有「客户」列时整列填 0，不会报缺列 |
| 1月条数 … 12月条数（销售表） | 出入库明细 `出库数量` | 该月出库数量**换算成条**：该 SKU `单位=码 ÷100`、`单位=公斤 ÷20`，其它单位（件/条）记 0；按「SKU + 月份」汇总后四舍五入到整数；只算 2026 年、出库数量 > 0 的行；该月没有记录填 0 |
| 1月重量 … 12月重量（销售表） | 出入库明细 `出库数量` | 该月**公斤单位**的出库数量求和（码单位的产品这一列填 0），保留 2 位小数；同样只算 2026 年、出库数量 > 0 的行 |
| 1月订单数 … 12月订单数（销售表） | 出入库明细 | 该月**有效行数**（1 行 = 1 单，与订单总数同口径），只算 2026 年、出库数量 > 0 的行；该月没有记录填 0。Σ(1-12月订单数) = 订单总数 |

所有数值列在两个场景下填 `0`：该分表里没有这个 SKU、或该行的值解析不出数字。

### 计算示例

`H硬特美|31#浅米黄`（单位=码，出入库明细共 142 行，其中 2 行出库数量为 0）：

- 总出库数量 = 22728 码（140 行求和）
- 累积条数 = 22728 ÷ 100 = 227.28 → **227**
- 动销月份 = **9**（2026-02 ~ 2026-10 连续 9 个月）
- 月均条数 = 227 ÷ 9 = **25.22**
- 周消耗 = 25.22 ÷ 4 = **6.31**（内部按未取整值计算，6.3055 → 6.31）
- 订单总数 = **140**（140 行出库），月度订单数例如 2月 6、3月 22、4月 20…（合计 140）
- 在仓库存 = 库存结存表里该 SKU 的数量之和 = 7730

> 1.4.x 的「月均条数」其实就是现在的「累积条数」。改成真月均后，周消耗约为旧值的 1/动销月份，
> 备货红线/正常/峰值随之下降，已有系数（如 2/4/6）需要按新口径重新校准。

### 匹配与清洗细节

1. **数字解析**：空值/空白/`-` 记 0；`"1,200"` 去千分位；`"130 KG"`、`"1.5米"` 取前面的数字。
2. **唯一标识比较**：关联时忽略大小写与全半角差异（`NFKC` + 转小写），但输出仍用产品资料原文。
3. **颜色为空的行**（仅生产排单）：无法定位 SKU，整行忽略。
4. **宽松合并**（欠货、生产排单）：同一品名下，分表颜色 = 基准颜色 + 尾部符号/英文（`-CC`、`S`、`（H）`，不含中文且 ≤6 字符）→ 并入基准那一行；多候选取最长，仍并列则不合并。
5. **追加新行**（欠货、生产排单）：基准里完全没有的 SKU 追加到最后，`品名/颜色` 用分表原文、`色彩` 重新推导、其它列只填它自己那几列，其余为 0。
6. 出入库明细、库存结存表未开启宽松合并/追加，未匹配的 SKU 直接丢弃（当前均为 0 个）。

### 出入库明细的配置写法

```js
{
  label: "出入库明细",
  rowFilter: (row) => toNumber(row["出库数量"]) > 0,   // 退货/纯入库行不参与
  columns: [
    { field: "出库数量", as: "总出库数量" },
    { field: "出库数量", as: "月均条数", divideBy: { field: "单位", map: { 码: 100, 公斤: 20 } }, digits: 0 },
    { as: "周消耗", divideFrom: { column: "月均条数", by: 4 }, digits: 2 },
    { as: "订单总数", agg: "rows" },
    { field: "做账日期", as: "动销月份", agg: "months" },
    { field: "客户", as: "动销客户", agg: "distinct", optional: true },
  ],
  // 按月展开 24 列：1月条数、1月重量、2月条数、2月重量…自动追加到总表末尾
  monthlyColumns: {
    dateField: "做账日期",
    year: 2026,
    columns: [
      { field: "出库数量", as: "{月}月条数", divideBy: { field: "单位", map: { 码: 100, 公斤: 20 } }, digits: 0 },
      { field: "出库数量", as: "{月}月重量", onlyUnits: { field: "单位", include: ["公斤"] }, digits: 2 },
    ],
  },
}
```

- `digits`：保留小数位，`0` 即四舍五入到整数；换算在取整之前完成
- `divideBy`：先求和再按另一列（单位）取系数换算；未命中的单位记 0，需要兜底可加 `default: <除数>`
- `divideFrom`：由同表另一列换算（`周消耗 = 月均条数 ÷ 4`），不参与逐行累加
- `distinct`：按文本去重后计数（`动销客户`），空值不计入
- `optional: true`：源表缺这一列时按 0 处理，不报「表头缺少列」（历史明细表没有「客户」列也能照常清洗）
- `monthlyColumns`：列名里的 `{月}` 依次替换成 1~12，展开顺序为「同一月份的所有模板」（1月条数、1月重量、2月条数…），自动接在 `CONFIG.columnOrder` 之后；`year` 不写则取数据里最新年份
- `onlyUnits`：只统计指定单位的行（`1月重量` 只要公斤单位的产品）

> 按月列只出现在销售表里：`OUTPUTS` 第二项的 `columns` 用了 `"{按月}"` 占位，运行时会展开成 24 个列名；
> `月均条数、订单总数、动销月份、动销客户` 也已从总表移到销售表（排在按月列左边）。
> 若想让某些列也进总表，把列名加进 `CONFIG.columnOrder`（或改写 `OUTPUTS[0].columns`）即可。

要增减列时改 `JOINS` 里的 `columns` 和 `CONFIG.columnOrder` 即可，汇总只计算配置里出现的列。

## 模拟「客户」列（只用于测试数据）

`simulate-customers.js` 给明细表补一列 `客户`，让销售表的 `动销客户` 有数据可算（真实业务表不需要跑这个脚本）：

```bash
node simulate-customers.js                          # 就地写回 docs/测试数据/演示数据 的出入库明细
node simulate-customers.js <输入.xlsx> [输出.xlsx]   # 指定文件；省略输出则覆盖输入
node simulate-customers.js --dry-run                # 只打印统计，不写文件
node simulate-customers.js --seed 20261109 --customers 3000
```

造数规律：

- 客户按**单号**赋值，一张销售单只有一个客户；同一单的多行 SKU 共用该客户；
- `加工出库` 填加工厂（染整/定型/印花…，因为 `订单总数` 把这些行也算作订单），`销售退货*` 留空；
- 去重客户数随订单数次线性增长：1~2 单只给 1 个客户，之后 ≈ `round(订单数 ^ 0.58)`，上限 200；
- 热销 SKU 由少数大客户反复下单（复购比可达 10~20 单/客户），冷门 SKU 多是一单一个散户；
- 固定随机种子，重跑结果一致；除新增的 `客户` 列外不改任何单元格（日期/数字格式、列宽都保留，写回后重新压包，体积与原始导出相当）。

## 新增分表

在 `JOINS` 里加一段即可，`label` 同时是文件名关键字：

```js
{ label: "欠货", columns: [{ field: "欠货总数量", as: "欠货" }] }
```

若分表的主键列名和基准表不一致（例如欠货表叫 `产品名`、`颜色`），有两种写法：

```js
// 1) 只给这张表指定主键列
{ label: "欠货", keyFields: ["产品名", "颜色"], columns: [...] }

// 2) 给 CONFIG.keyFields 加别名，所有表通用（脚本已默认配置「品名 ← 产品名」「颜色 ← 天鸿颜色」）
keyFields: [
  { field: "品名", aliases: ["产品名"] },
  { field: "颜色", aliases: ["天鸿颜色"] },
]
```

别名按 `field → aliases` 顺序取第一个非空值，所以同一张表里同时有 `颜色` 和 `天鸿颜色` 时优先用 `颜色`。

数量列里的 `"130 KG"`、`"380 米"` 这类带单位文本会自动取前面的数字；纯文本（如 `"-"`）记 0。
若某分表整表一行都没匹配上，运行日志会给出警告，提示检查主键列名。

## 唯一标识的匹配规则

1. **归一化比较**：比对时会忽略大小写与全半角差异（`NFKC` + 转小写），总表里的唯一标识仍用基准（产品资料）的原文。
   例：排单表 `韩国网|223#深栗红（固色）s` 能对上产品资料的 `…（固色）S`。
   这种「仅写法不同」的匹配会在日志里单独统计：`其中 N 个仅大小写/全半角写法不同`。
2. **主键缺字段**：分表配置 `skipIncompleteKey: true` 时，主键任一段为空的行直接忽略（例如天鸿颜色为空，无法定位 SKU）。日志会打印忽略行数。
3. **宽松合并**：分表配置 `mergeSimilarKeys: true` 时，同一品名下若分表颜色 = 基准颜色 + 尾部多出的符号/英文（如 `-CC`、`S`、`（H）`），视为同一个 SKU，直接合并进基准那一行（数值照常累加）。
   - 尾部多出的部分不含中文，且长度 ≤ 6；多个候选取最长（最具体）的一个，仍有并列则不合并；
   - 每次合并都会打印：`宽松合并 N 个（颜色尾部多出的符号/英文已忽略）：xxx → yyy`。
4. **基准里完全没有的 SKU**：分表配置 `appendUnmatched: true` 时，无法精确匹配、也无法宽松合并的 SKU 才追加到总表末尾：
   - `唯一标识`、`品名`、`颜色` 取自该分表原文，`色彩` 按黑白/彩色规则重新推导；
   - 该分表的数值列填它自己的汇总值，其它表对应的列填默认值 0。
   日志会列出明细，并打印 `基准里没有的 SKU：追加 N 行`。
5. 未开启 `appendUnmatched` 的分表，未匹配的 SKU 按左连接规则丢弃。

## 在应用里直接清洗（主面板「导入分表」）

库存系统用的是同一份清洗引擎：主面板「导入分表」一次选择这 5 张分表，页面按文件名自动认领，
在 Web Worker 里流式解析并汇总出「总表 + 销售表」，确认后直接覆盖主面板数据，不需要先跑脚本再导入
`output/` 里的结果。

```
tools/cleaning/engine.mjs     ★ 口径：配置 / 唯一标识 / 汇总 / 关联 / 宽松合并（全项目只有这一份）
  ├─ src/cleaning/engine.js     一行转发：export * from '../../tools/cleaning/engine.mjs'
  │     └─ src/utils/cleanMerge.js   页面入口：fflate 流式读表 → 引擎
  └─ tools/cleaning/clean-merge.js   脚本入口：SheetJS 读表 → 引擎 → 写 output/
```

- 改口径（列、聚合方式、换算系数、宽松合并规则）只改 `tools/cleaning/engine.mjs`，页面与脚本同时生效。
- 两边只是「读文件」的方式不同：页面按行流式解析（出入库明细解压后约 150MB），脚本用 SheetJS 整表读入并写 xlsx。
- 脚本仍然保留：需要导出 `output/*.xlsx` 给别处使用、或要离线核对数据时继续用 `npm run clean`；
  它还会打印基准 SKU 数、各分表汇总 SKU 数、未匹配与追加行数，排查数据问题比页面方便。

## 作为模块调用
```js
const { cleanMerge } = require("./clean-merge.js");

const rows = await cleanMerge({ outputFile: null });                        // 只返回数据，不写文件
await cleanMerge({ files: { 库存结存表: "D:/其它/库存.xlsx" } });             // 覆盖某个数据源
await cleanMerge({ inputDir: "D:/原始", outputDir: "D:/结果" });              // 自定义目录
```

`cleanMerge` 现在是异步的（内部按需 `import` 共享引擎）。只想拿「总表」数据行就取返回值；
需要两张表的结构（列 + 行）时调用引擎：

```js
const engine = await import("./engine.mjs");   // 本目录里就是唯一那份
const { tables, stats } = await engine.runCleaning({ readRecords });
// tables["总表"] / tables["销售表"] → { columns, rows }
```

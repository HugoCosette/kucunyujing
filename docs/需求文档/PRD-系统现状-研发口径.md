## 1. 产品概述

### 1.1 目标

把「布料 SKU 的库存 / 销量 / 订单」三类数据合并成一张可决策的表，自动判定备货模式与系数，给出预警灯与建议补货量，并把「需安排 → 拆单 → 下单 → 到货」串成闭环，避免重复下单与静默丢单。

### 1.2 用户角色

| 角色 | 主要操作 |
|---|---|
| 主管 | 导入数据、看预警、批量/紧急补货、采纳需安排、回滚快照 |
| 下单员 | 在 `/purchase` 按染厂拆分订单、确认下单、登记到货 |
| 配置员 | 在 `/config` 调模式区间、系数、评分、SPU 分级、缸规则、染厂/人员/分类 |

### 1.3 使用场景

1. 每周/每月导入 5 张分表 → 清洗出总表 + 销售表 → 主面板看预警。
2. 主管勾选 SKU 批量补货或对红灯 SKU 紧急补货 → 写入「需安排」→ 跳转采购下单。
3. 下单员按染厂拆单、按缸取整 → 确认下单 → 回写主面板「已下单/已到货」。
4. 到货后在订单弹窗登记 → 待收扣减；撤销订单回补需安排。

### 1.4 术语

| 术语 | 定义 |
|---|---|
| SKU | 唯一标识 = `品名 \| 颜色` |
| 需安排 (planned) | 主管锁定的补货公斤数，唯一可编辑列 |
| 理论库存 | 在仓 + 生产中（导入事实） |
| 预计库存 | 理论库存 + 需安排（评估态） |
| 日库销比 | 预计库存 ÷ 日销量（天），仅热销/常规 |
| 累积下单 | Σ active 订单 quantity |
| 待收 | 累积下单 − 已到货 |

## 4. 数据模型

### 4.1 总表（13 列，清洗输出）

`唯一标识 | 品名 | 颜色 | 色彩 | 树形分类 | 出码率 | 公斤系数 | 欠货 | 周销量 | 周转入 | 生产中 | 在仓库存 | 总出库数量`

- `生产中` = 生产排单「进仓重量」（公斤）；`周转入` 暂无数据源，整列 0。
- `周销量` 单位 公斤/周。
- 主面板「在途库存」**不来自清洗**，由订单流水的累积下单派生。

### 4.2 销售表（45 列）

`唯一标识 | 品名 | 颜色 | 累计客户 | 订单总数 | 动销月份 | 累积条数 | 累积销量 | 客户CR5率 | 1月条数/1月销量/1月订单数 … 12月条数/12月销量/12月订单数`

- `N月销量` 与 `累积销量` 单位 公斤；`N月条数` 与 `累积条数` 是换算值（码÷100、公斤÷20），仅展示/折线图/模式判定。
- 客户CR5率 = 前 5 名客户销量 ÷ 总销量（0~1），只在销售表展示，不写回主面板、不进备货配置。

### 4.3 关联键

跨导入一律按 `skuId`（唯一标识）关联；需安排/撤销快照存 `meta.workspace`；分订单以唯一标识为键。不使用行 `id`（导入后会重排）。

### 4.4 订单流水模型

```js
{
  id, batchId, taskId, skuId, product, color,
  factoryId, factoryName, assignee, quantity,
  vatCount, kgPerVat, note,
  status,            // 'active' | 'cancelled'
  month,            // 'YYYY-MM'
  createdAt, updatedAt, confirmedAt, receivedAt,
  receipts: [{ qty, at, ... }]   // 到货记录
}
```

- 日常追加；修改留 `updatedAt`；作废用 `status='cancelled'`；历史页支持物理删除单张或整批（级联删除到货/改单明细）。

### 4.5 备货方案（config.json v4）

```json
{
  "version": 4,
  "activeProfileId": "production",
  "profiles": [{
    "id": "...", "name": "...",
    "config": {
      "salesWindow": { "weights": [{ "months": 1, "weight": 0.5 }, ...] },
      "scoring": { "scores": {...}, "total": {...}, "dimensions": {...} },
      "spuGrades": { "tiers": [...] },
```

## 5. 核心业务流程

### 5.1 导入与清洗

入口：主面板「导入分表」→ 5 张分表（4 必选 + 2 可选缓存）→ Worker 清洗 → 预览确认。

- 必选：出入库明细 / 库存结存表 / 欠货 / 生产排单；可选：产品资料 / 出码率（未选走 `tools/cleaning/cache/`）。
- 唯一标识 = `品名 | 颜色`；出码率按品名匹配。
- 单位换算：公斤单位系数=1；码单位系数=1÷出码率；其他单位（条/件/米/空）剔除。
- 剔除：基准 30,991 → 保留 22,312（剔除 8,679）；总表「公斤系数为空」= 0。
- 输出总表（13 列）+ 销售表（45 列）；销售表页无导入入口，空态指向主面板。

### 5.2 备货模式判定

仅看导入的 `月均条数`（= 累积条数 ÷ 动销月份），不看加权月销量。

| 序 | 模式 | 月均条数区间 | 比较方式 | 系数（流通品） |
|---|---|---|---|---|
| 1 | 热销 | 30 ~ ∞ | 日库销比（天） | 黑白 20/40/60、彩色 15/30/45 |
| 2 | 常规 | 10 ~ 30 | 日库销比（天） | 黑白 15/30/45、彩色 10/20/30 |
| 3 | 按量 | 3 ~ 10 | 库存公斤数 | 黑白 40/80/200、彩色 40/80/120 |
| 4 | 尾货 | 0.01 ~ 3 | — | 仅标注 |
| 5 | 滞销 | 0 ~ 0.01 | — | 仅标注 |

- 专属品：热销/常规/按量命中时，`累计客户 = 1` → 标记「·专属品」，不取系数、不参与计算；`≥2` 或缺失按流通品。
- 模式顺序即判定优先级；端点同时落进相邻两段时更靠前优先；空档退回「下限最高且不高于该值」的模式。
- 模式数量与 key 固定 5 个，配置页只能改名称/阈值/系数。

### 5.3 健康度评分

6 维：客户数CR5(15%)、累计客户数(10%)、销售环比率(20%)、本次进销比(30%)、动销月份(10%)、预估月消耗(15%)。三档得分默认 40/60/80；综合分 = Σ(得分×权重)÷参与维度权重合计；区间默认 <50 红、50~70 黄、>70 绿。

- 按量模式走 `evaluateBulkScoring()`：只判 2 项（本次进销比 40%~60%、累积客户 5~10），不做综合分，显示「—」。
- 专属品/尾货/滞销/订单货/模式缺省 → 「不参与」。
- 销售环比率按打开系统日期：≥26 号取「本月 vs 上月」，≤25 号取「上月 vs 前月」。

### 5.4 SPU 分级

品名汇总行模式列显示 S+/S/A/B/C/Z 徽标，按「该品名全部 SKU 月均条数之和」判定。默认阈值 2500/300/100/30/1 + Z 兜底，配置页可改（固定 6 档）。

### 5.5 需安排 / 采纳 / 撤销

- 「需安排」是唯一可编辑列（`ElInputNumber`），草稿存 `inventoryView` store。
- 采纳：`writePlanned(plans)` 覆盖写 `item.planned`（绝对值），记 `plannedUndoHistory`，清草稿与预览色。
- 采纳后锁定（输入框禁用 + 锁图标），不可勾选；确认下单后清零并解锁。
- 撤销：恢复原值（草稿态，不锁），预警退红。
- 建议值：`max(0, ceil(正常库存 − 理论库存 − 累积下单))`（`src/utils/inventory.js` 的 `getSuggestedPlanned`）。
- 批量补货：勾选行 → 浮动条「确认补货」→ 只认勾选行「需安排」里填着的数字 → 写入 → 跳转 `/purchase`（带 `?sku=`）。
- 紧急补货：红区 SKU → 填新增量（追加）→ 留在主面板。

### 5.6 采购下单

- 下单列表直接由 `planned > 0` 派生（按唯一标识），无第二份清单。
- 缸规则（`src/purchase/vat.js`）：月均条数 1-119 → 80 公斤/缸；120-199 → 160；≥200 → 240。一张分订单只用一种缸型，不拼缸。
- 进 SKU 面板若无分订单，自动带出一张按缸规则换算的建议单（同一 SKU 只自动带一次；筛选导致的自动回落不预填）。
- 点「添加分订单」也带默认值。
- 确认下单：草稿 → active + batchId；需安排清零、解锁；累积下单 +=。
- 到货：在订单弹窗登记，`1 ≤ 本次 ≤ 待收`；待收 = 累积下单 − 已到货。
- 撤销订单：作废（累积下单/到货扣回），需安排 += 该单公斤（草稿态）。
- 填量颜色（`src/purchase/fillTone.js`）：不足八成黄 / 八成~100% 绿 / 超一缸内绿 / 超过一缸红。

### 5.7 屏蔽 / 删除

「删除」是屏蔽：写 `src/stocking/hiddenSkus.json`，源表与销售数据不动，解除在 `/hidden`。导航入口不带数字，数量按 SKU 计（整组屏蔽的品名按当前数据里该品名的 SKU 数展开）。

### 5.8 手动 SKU

- 「添加SKU」是唯一手动录入入口：唯一标识 `MANUAL-0001` 递增并跳过屏蔽清单用过的标识；库存与销量按公斤录入（公斤系数=1）。
- 手动策略：自定系数（人工填红/正/峰公斤，按库存公斤比较）/ 订单货（按客户订单填量，不计预警与评分，需安排填多少就下多少）。
- 命中手动清单即短路，不跑模式判定；归属存 `src/stocking/manualSkus.json`，跨导入/刷新/方案有效。

### 5.9 导出

所有导出走 `src/utils/xlsxWrite.js` 的 `saveWorkbook(sheets, fileName)`（`sheets = [{ name, rows, widths }]`）。下单历史导出当前筛选结果，文件名带范围。

### 6.4 预警灯两态

- 数据态：只由导入数据 + 订单派生（把需安排清零重算），`dataStateOf()` / `dataTone()`；用于筛选/计数/紧急补货清单。
- 预计展示态：把需安排算进去，`getPlannedTone()`；用于灯色与需安排格底色。

### 6.5 预警灯颜色

| 条件（热销/常规看天数；按量看公斤） | 灯 |
|---|---|
| 指标 < 红线 | 🔴 紧急补货 |
| 指标 > 峰值 | 🟣 降低库存 |
| 正常 × 80% ~ 120% | 🟢 无需补货 |
| 其余 | 🟡 常规补货 |
| 尾货/滞销/专属品/订单货/模式缺省 | 灰（不参与） |

## 7. 计算口径

### 7.1 单位换算

```
公斤单位：数量 = 公斤，公斤系数 = 1
码单位：公斤 = 码 ÷ 出码率，公斤系数 = 1 ÷ 出码率
其他单位：剔除
```

出码率含义：1 公斤 = N 码。生产中取「进仓重量」本身就是公斤。在仓/欠货/周转入展示时统一乘公斤系数。

### 7.2 加权月销量

```
基准月 M0 = 数据里最后一个有销量的月份
某档窗口 = mean(销量(M0 … M0-N+1))，缺失月按 0
加权月销量 = Σ(各档月均 × 该档权重)   默认：近1月 50% / 近3月月均 30% / 近12月月均 20%
日销量 = 加权月销量 ÷ 30
```

档位可增删，每档「近 N 个月」可填 1-12，权重合计必须 100%。

### 7.3 日库销比（热销/常规）

```
日库销比(天) = 预计库存(公斤) ÷ 日销量(公斤)
预计库存 = 理论库存 + 已采纳的需安排
加权月销量 = 0 → 日库销比 = ∞ → 直接判「降低库存」（紫）
```

按量模式比的是公斤库存（指标 = 预计库存本身），主面板「日库销比」列在按量行显示 `--`。

### 7.4 三档库存 / 缺口 / 建议需安排

```
热销/常规：红线库存(条) = 日销量 × 系数天数
按量：红线库存(条) = 系数条数
三档库存(公斤) = 日销量(公斤/天) × 系数天数（按量直接取系数公斤）
缺口量 = 正常库存(数量) − 预计库存(数量)
缺口率 = 缺口量 ÷ 正常库存(数量)
建议需安排 = ceil(正常库存(数量) − 理论库存(数量))
```

绿色带上下限 = 正常库存 × 80% / × 120%，中位 = 正常库存，所以建议目标位是补到正常库存。

### 7.5 健康度评分（详见模式与系数设置.md §12）

6 维 + 按量 2 项；区间两端都含，留空不限；端点重叠按 中→高→低 取第一条命中；缺失因子显示「无数据」不参与加权。综合分区间 `scoring.total` 默认 <50 红、50~70 黄、>70 绿。

### 7.6 SPU 分级

按品名全部 SKU 月均条数之和判定，6 档固定（S+/S/A/B/C/Z），阈值存方案 `spuGrades`。

### 7.7 缸规则

月均条数 1-119 → 80 公斤/缸；120-199 → 160；≥200 → 240。一张分订单只用一种缸型，不拼缸。按缸时下单量 = 缸数 × 缸型；按公斤时直接输入。

### 7.8 填量颜色

不足八成黄 / 八成~100% 绿 / 超一缸内绿 / 超过一缸红（`src/purchase/fillTone.js`）。

## 9. 持久化与数据层

### 9.1 IndexedDB（`kucun-persist`，v1）

| Store | keyPath | 说明 |
|---|---|---|
| `meta` | key | 元信息（workspace、快照索引） |
| `snapshots` | id | 导入快照（索引 `byCreatedAt`），最多保留 5 份 |
| `documents` | key | 整份文档（订单 `purchaseOrders` 等） |

### 9.2 localStorage

| Key | 内容 |
|---|---|
| `stocking-config:v4` | 备货方案缓存 |
| 下单设置 / 手动清单 / 屏蔽清单 | 小体量设置类 |

### 9.3 快照与计划层

- 快照只存事实层（导入的库存 + 销售表），gzip 后约 4-6 MB/份，最多 5 份，滚动淘汰。
- 计划层（需安排）与执行层（订单）单独存，按 `skuId` 挂接；回滚快照只回滚事实，人的决定保留。
- 同一份文件重复导入（内容哈希相同）不新建快照，只更新时间。

### 9.4 启动加载

```
有快照 → 载入最新快照 → 叠加计划层（需安排）→ 渲染
无快照 → 用 src/data/inventoryItems.js 种子
```

### 9.5 数据访问层

页面/store 只调 `src/data/repo.js` 导出的方法，不直连 IndexedDB/localStorage。阶段二多人协作时把实现换成 `httpRepo.js`，调用方一行不用改。

## 10. 边界条件与异常处理

### 10.1 清洗剔除

| 情况 | 处理 |
|---|---|
| 公斤单位 | 保留 |
| 码单位 + 有出码率 | 保留 |
| 码单位 + 无出码率 | 剔除 |
| 条/件/米/空单位 | 剔除 |
| 欠货/生产排单追加的 SKU 无法换算 | 兜底剔除 |

### 10.2 缺出码率

网页端：该行显示「缺出码率」，不参与计算；清洗阶段已剔除无法换算的 SKU，不会进入主面板。

### 10.3 不参与计算的模式

尾货/滞销/专属品：三档库存、缺口量、缺口率、日库销比显示 `—`，灰灯，不进紧急补货、无建议值、父行汇总时跳过，但仍可人工填需安排。

### 10.4 锁定与草稿

- 未锁的需安排只是草稿（`plannedDrafts`），显示在格子里、可编辑，但**不计入预计库存**。
- 撤销订单后回补的数字落在草稿层，预警退红。
- 采纳后锁定，不可勾选；确认下单清零并解锁。

### 10.5 性能边界

- 3 万行：确认→可用 1.55s，DOM 节点 1,373，JS 堆 52~130MB。
- 虚拟滚动：固定行高 34px，上下各 8 行缓冲；滚动事件 rAF 合并。
- 筛选防抖 250ms；预警计数单遍历；`itemById` Map O(1)。
- 配置页：≤500 行树形展示，>500 行扁平+分页（每页 60）。

### 10.6 已知未实现（数据持久化方案 §4.4）

- [ ] 按月统计（`orderStats`）：订单量未到需要预聚合的规模，先不做。
- [ ] 任务清单（`tasks` 系列）：留给阶段二多人协作。

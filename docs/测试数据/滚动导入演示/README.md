# 滚动导入演示数据（7 天）

配套口径：[采购下单流程.md](../../功能说明/采购下单流程.md) 3.11「在途对账」。
生成方式见文末；改口径后可重跑脚本重新生成。

---

## 1. 这是什么

`day-01` … `day-07` 每天一个文件夹，各 6 张分表，模拟「每天早上导入一次、截止昨天的分表」：

| 文件 | 角色 |
| --- | --- |
| `产品资料.xlsx` | 基准（决定行集合） |
| `出码率.xlsx` | 码 → 公斤 |
| `出入库明细（销售+加工）.xlsx` | 出库（销量）+ 入库（生产入库 / 退货入库） |
| `库存结存表.xlsx` | 在仓库存 |
| `欠货订单导出.xlsx` | 欠货 |
| `productionScheduling.xlsx` | 生产排单（生产中） |

**每一天的文件都是「截止当天」的累计快照，不是增量。** 别把 day-02 当成「第二天新增的行」导入。

### 数据长什么样

- **规模**：造 130 个 SKU（12 个品名 × 10 色 + 6 个场景 SKU + 4 个脏数据 SKU），进表 128 个（缺出码率 / 按条单位那 2 个会被清洗剔除），合计 4.3 MB。
- **日期**：预置历史 `2026-08-01 … 10-24` + 回放窗口 `10-25 … 10-31`。历史横跨 3 个自然月，`动销月份` 才是 3，月均条数才有意义（只给 7 天数据会把月均条数压到 1/4，全部掉进尾货 / 滞销）。
- **模式分布**（回放 D7 实测，比例对齐真实 22k SKU：尾货≈73%、按量≈15%、常规≈6%、热销≈2%）：热销 14 / 常规 16 / 按量 26 / 尾货 65 / 滞销 7，其中 4 个是「只有 1 个客户」的专属品（不参与备货）。
- **预警分布**（导入 `day-01` 后实测）：紧急 12 / 常规 4 / 正常 11 / 超库存 19 / 不参与 82；**需安排建议 > 0 的有 30 个左右**，打开主面板就能直接走「预警 → 需安排 → 下单」。
- **场景 SKU 只在历史里出库、10-25 之后不再出库**：在仓 7 天里保持不动，下面剧本里的数字才对得上。

## 2. 怎么导入

1. 主面板（需求表）→ 顶部「导入分表」→ 选中 `day-01` 里**全部 6 个文件** → 开始清洗。
2. 清洗完成会直接写入（没有二次确认弹窗）。
3. 第二天重复：选中 `day-02` 的 6 个文件 → 导入。**必须按 01 → 07 的顺序**，不能跳、不能倒。

文件名里的关键字（产品资料 / 出码率 / 出入库明细 / 库存结存表 / 欠货 / Scheduling）是自动认领用的，不要改名。

## 3. 主剧本：场景A品 / 1#黑（必做）

| 天 | 你要做的 | 预期 |
| --- | --- | --- |
| D1 | 导入 `day-01` → 搜索「场景A品」→「需安排」填 **500** → 点「采纳」→ 顶部「采购下单」→ 选中该 SKU → 把分订单改成「按公斤」并填 **500** → 「确认下单」→ 回主面板 | 在仓 1000 / 已安排 **500** / 生产中 0 / 在途 **500** / 预计 1500 |
| D2 | 导入 `day-02`（排单里出现这 500） | 在仓 1000 / 已安排 **0** / 生产中 **500** / 在途 500 / 预计 **1500（不跳）** |
| D3 | 导入 `day-03`（出入库明细里出现「生产入库 500」） | 在仓 **1500** / 已安排 0 / 生产中 0 / 在途 **0** / 预计 1500 |

三个关键点：

- **预计库存在 D1 下单后到 D3 到仓之间始终是 1500**，同一批货只是在「已安排 → 生产中 → 在仓」之间挪，不会重复计算。
- 「下单量」请用**按公斤 500**。默认缸规则会把 500 就近取整成 2 缸 × 240 = 480，那 已安排 就是 480。
- 需安排必须在「采购下单」里**确认下单**才会变成已安排；只采纳不确认，已安排仍是 0。

> 场景A 是「热销」模式（月均 70 条），D1 的建议需安排约 120（补到正常库存），直接在输入框里改成 500 即可。
> 主面板「已安排 / 生产中 / 在途」在**入口 / 库存(公斤)** 两组里直接可见；
> 「累积下单 / 待收 / 到货」在「备货」组，默认折叠，点表头展开。

## 4. 附剧本（可选，各占一个 SKU）

| SKU | 剧本 | 看点 |
| --- | --- | --- |
| 场景B品 / 1#黑 | D1 下单 480（两张 240）→ D2 排单 480 → D3 入库 240 → D4 入库 240 | 部分到货：在途 240 → 0 |
| 场景C品 / 1#黑 | D1 下单 500 → D2 排单 600 → D3 入库 600 | 超产：D2 在途跳到 600（多出的 100 是真实在产） |
| 场景D品 / 1#黑 | 不下单；D3 有「销售退货入库 100」 | 在途不动，只让在仓 500 → 600 |
| 场景E品 / 1#黑 | D1 下单 300 → D2 在「采购下单」里撤销该 SKU | 在途回退 300 → 0 |
| 场景F品 / 1#黑 | D1 下单 500 → D2 排单**没有**这行 → D3 直接生产入库 500 | 排单漏记也能归零（`max(下单, 排单)` 兜住） |
| 松散品 / 1#黑 | D2 排单颜色写成 `1#黑-CC` | 宽松合并：仍计入「松散品/1#黑」的生产中 200 |
| 无码率品 / 按条品 | — | 缺出码率 / 非公斤单位 → 清洗阶段直接被剔除，表里不会出现 |

「松散品/1#黑」到 D7 仍留在途 200（有排单、没有入库），这是正确的：排单上了但货没到。

## 5. 想重来一遍

设置 → 数据 → 本机数据存储：

- **「重置在途基线」**：只清基线，下次导入按当次数据重新起算（推荐，订单与需安排都不动）。
- **「清空本机数据」**：连导入数据、需安排、订单一起清掉，之后从 `day-01` 重新导。

## 6. 这份数据怎么生成的

```bash
cd tools/cleaning
node simulate-rolling.mjs --skus 120 --days 7 --out ../../docs/测试数据/滚动导入演示
```

脚本会先清掉输出目录里的 `day-*` 再重写（README 不会被删），同时把 7 天逐日回放一遍（清洗 → 对账 → 断言），断言不通过会直接以非零码退出：

```bash
node simulate-rolling.mjs          # 1000 SKU × 7 天，2 万余项断言
node simulate-rolling.mjs --no-files   # 只跑内存回放，不落 xlsx
```

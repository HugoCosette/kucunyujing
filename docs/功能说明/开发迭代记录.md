# 布料库存规划 Demo｜开发迭代记录

按阶段记录项目从截图原型到当前库存规划 Demo 的主要实现与口径变更。为控制篇幅，只保留每次迭代的结论，验证细节与代码级实现从略；现行口径以[需求文档1.1](../需求文档/需求文档1.1.md)、[模式与系数设置](./模式与系数设置.md)、[数据清洗规则](./数据清洗规则.md)、[采购下单流程](./采购下单流程.md)为准。

## 一、原型与早期交互（1–8）

- **1 项目起点**：
  - 参照用户提供的图片，用 Element Plus 制作静态库存表格，Vite 提供本地开发与热更新；随需求扩展为 Vue 3 + Element Plus + Pinia + Vue Router，导出用 `fflate` 在浏览器内组装 XLSX。
  - 数据只存浏览器运行时内存，刷新即回初始数据。
- **2 表格原型与库存计算**：
  - 建立分组表头（商品 / 入口 / 出口 / 库存 / 数据反馈），示例扩为 20 条颜色记录并支持逐行编辑，品名中文在前、同品名内黑色优先。
  - 红线 / 正常 / 峰值由模式系数计算，系数缺失显示缺省；预警按「低于红线 → 紧急补货（红）／高于峰值 → 降低库存（紫）／正常库存 80%~120% → 无需补货（绿）／其余 → 常规补货（黄）」判定，系数缺省不参与四色判断。
- **3 分组与共享数据**：颜色记录改为「品名父行 → 颜色子行」可折叠结构，父行汇总数量，缺口率与库销比按汇总后的分子分母重算；主面板放日常操作、配置信息页放策略配置，两页独立路由并用 Pinia 共享运行时数据，切路由不丢修改。
- **4 紧急补货 / 新增商品 / 导出**：
  - 紧急补货弹窗固定打开瞬间的紧急 SKU 清单，推荐量 `max(0, ceil(正常库存 × 80% − 当前预计库存))`，新增计划为追加量、确认才累加进需安排。
  - 「新增商品」表单已于 1.2.2 移除，新增记录只能靠导入。
  - 「保存 Excel」导出全量数据与计算指标，只作下载副本、不当持久化。
- **5 筛选与行选择**：品名 / 颜色关键词与四色预警多选组合（同类为「或」、跨维度为「且」），父行只在有匹配子行时显示并按可见子行重算，计数仍按全量 SKU；父行点击折叠、SKU 点击只提示自身。
- **6 需安排草稿与采纳**：移除「已安排」，预计库存 = 需安排 + 生产中 + 在仓库存；需安排先存 SKU 级草稿、只改格子浅色预览，点「采纳」才写入并锁定输入，按钮切「撤销」可回滚原值；采纳与紧急补货提交都写「本次采购清单」，撤销同步还原清单行。
- **7 边界约定**：计算与预警以颜色 SKU 为单位、父行只做汇总；未采纳草稿不参与任何正式计算；Excel 不替代持久化，刷新不能从 Excel 恢复。
- **8 验证方式**：每轮改动都执行 `npm run build` 并做浏览器实测（路由联动、筛选、折叠、草稿预览、导出结构等），本文此后不再逐条罗列验证细节。

## 二、列结构与指标演进（9–13）

- **9 在途库存与理论库存**：库存分组改为「在仓库存 / 在途库存 / 理论库存」，在途 = 需安排 + 生产中、理论 = 在仓 + 在途，与旧「预计库存」同值；预警、缺口、紧急补货改按理论库存计算。
- **10 品名列独立**：商品分组的品名与颜色拆成两列，品名固定最左；父行在品名列折叠，子行重复显示所属品名，便于横向滚动后识别 SKU。
- **11 主面板与示例面板**：新增 `/example` 示例面板复用同一套组件与计算，库存、采购清单与撤销记录按面板 key 独立存放（该面板于第 74 条整体删除）。
- **12 示例数据区与导航分组**：顶部导航分主面板组 / 示例数据组，导航抽成共享组件、路由 props 传 `panelKey`；新增 `AGENTS.md` 约束只改主面板与配置信息。
- **13 Excel 导入与 3 万行性能改造**：
  - 新增「导入Excel / 导入模板」，按「品名 + 颜色」识别 SKU 整表替换，需安排、撤销快照与采购清单按 SKU 保留，确认前预览并逐行报错。
  - 表格改为自研滚动虚拟化（行高 44px、上下各 8 行缓冲）+「单行缓存 + 增量刷新」：3 万行导入 33.2s → 1.55s、DOM 103 万 → 约 1400 节点、堆 2.29GB → 约 130MB、预警筛选从无响应 → 约 70ms（详见[主面板性能优化](./主面板性能优化.md)）。
  - 配置页超过 500 行改扁平分页（每页 60 行）。

## 三、在途 / 预计库存与全面板（14–24）

- **14 在途库存改为导入值**：在途改为与生产中、在仓库存同级的导入项，理论库存 = 在仓 + 在途；需安排退出库存计算，只做计划记录，建议值与草稿预览色随之移除（第 15 条又接回）。
- **15 预计库存：把「需安排 → 预警」的反馈接回来**：理论库存（事实层）+ 需安排 = 预计库存（评估层），预警、缺口、紧急补货按预计库存判定，理论库存不被需安排改写；草稿预览、建议值与撤销交互恢复；库存列顺序定为「在仓 → 周转入 → 在途 → 理论 → 预计」，导出新增预计库存列、导入忽略该列，避免回导重复计数。
- **16 表格紧凑化与移除加入商品**：
  - 数据行高 44px → 34px；列宽改为 `minmax(宽度px, 宽度fr)`，剩余空间按比例分摊，右侧不再出现空白列。
  - 移除「加入商品」入口与表单，新增记录只走导入；工具栏按钮与筛选合并一行。
- **17 配置信息品名与颜色拆列**：配置页表头与主面板对齐（品名 100px + 颜色 140px），扁平分页模式同样两列显示，超长省略并悬停显示完整内容。
- **18 全面板：全量数据只读视图**：
  - 新增 `/all` 只读展示主面板导入的全部 SKU，写入仍只在主面板，右侧附配置页的备货详情。
  - 沿用虚拟化与 `shallowRef` 行数据，3 万行约 0.33s 可交互；工具栏支持搜索（250ms 防抖）。
- **19 Excel 全量导入与评分因子改为动销指标**：导入时把 Excel 原始整表存入 `importedSheet` 供全面板原样展示（该机制于第 24 条删除）；评分因子收敛为 4 个动销指标（月均条数 / 订单总数 / 动销月份 / 累计客户），模板与表头识别同步，旧模板缺列按 0。
- **20 全面板品名（SPU）汇总**：全面板改为两级结构，品名父行汇总数量列、颜色子行折叠其下并默认展开；汇总字段与主面板共用白名单，未识别列不参与求和。
- **21 全面板汇总扩展与排序**：汇总列改为「所有全为数字（或空 / 占位）的列」自动参与；默认排序改为「品名按聚合月均条数降序 → 同品名内按月均条数降序 → 颜色」。
- **22 评分配置默认阈值调整**：热销A 默认因子改为「月均条数 ≥ 200 且订单总数 ≥ 10」，常规A 仍为月均条数 ≥ 0；种子数据按周消耗折算以适配。
- **23 全面板改为销售表**：`/all` 改为 `/sales`，列固定为品名、颜色 + 4 个动销指标 + 1-12 月条数与重量（30 列），动销指标取主面板值；「导入销售表」按「品名 + 颜色」把月度条数与重量叠加到 SKU，文件里的动销指标一律忽略，未匹配 / 空白 / 错误行分别统计，无匹配时禁止确认，月份列可缺省且缺列显示为空。
- **24 导入改为「总表 + 销售表」双文件**：两个入口共用一条导入流程，一次可选总表 + 销售表并按表头自动识别角色；销售表的 4 个动销指标改为写回主面板并重算评分，缺列沿用总表值；整表替换逻辑抽到 `inventoryApply.js`，SKU 键统一为 `createSkuKey`；删除 `importedSheet` 等全面板遗留代码。

## 四、备货策略配置化（25–30）

- **25 备货模式重构：模式 → 评分档 → 系数**：
  - 新增自包含模块 `src/stocking/`（字段 / 默认值 / 校验 / 引擎 / 持久化 / `config.json`），删除散落的 `heatRules.js`、`stockingRules.js`。
  - 判定三层：模式因子定归属 → 每条模式自选评分因子与 S/A/B/C 阈值 → 档位取系数。
  - 开发态把配置写回 `src/stocking/config.json` 并屏蔽该文件 HMR；SKU 关联键改为「唯一标识」，改品名或颜色不再丢数据。
- **26 修复：保存配置后主面板仍显示旧模式名**：原因是模式 / 档位 id 是导入时写回库存行的快照，保存配置只换了配置、未回写行数据；改为渲染时按当前配置现算（`evaluateItem` 拷贝后评估），store 与导入不再存储派生字段。
- **27 配置页防误删与撤销 / 重做**：
  - 删除模式改二次点击确认（3 秒内再点生效），其余高频操作不做确认、由撤销兜底。
  - 撤销 / 重做用 JSON 快照实现（连续输入 600ms 合并成一步、结构性操作单独成步、栈深 50），支持 `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`，输入框内不拦截；`draftVersion` 作为卡片 key 解决撤销后输入框残留旧值。
- **28 修复：改默认模式 / 档名称后系数全部显示「缺省」**：原因是评估结果只有 id、系数另按 id 二次查表，两次归一化各自生成档位 id 对不上；`evaluate()` 直接返回命中档位的系数，行数据新增 `strategyIssue` 说明缺省原因（未命中档位 / 色彩未填 / 缺某色彩系数 / 系数未填全 / 周消耗为 0）。
- **29 四列「缺省」换成简短原因**：红线 / 正常 / 峰值 / 系数四列直接写短原因（`strategyIssueShort`），悬停看完整说明；父行在有子行缺省时显示「子行缺省」。
- **30 唯一标识不再作为界面列**：主面板与销售表去掉唯一标识列，配置页本就不展示；导入模板与导出仍保留该列以维持关联。

## 五、分表清洗与工具归并（31–33）

- **31 主面板新增「导入分表」**：一次多选产品资料 / 出入库明细 / 库存结存表 / 欠货 / 生产排单，按文件名认领、缺一张不允许开始；清洗在 Worker 执行并回传整轮与逐表进度，完成后进入同一个确认弹窗；出入库明细解压约 150MB，Excel 读取改为流式逐行解析，并修复带 `xml:space` 属性的值节点读成空格的问题。
- **32 清洗口径收敛到单一引擎**：口径（配置 / 唯一标识 / 汇总 / 关联 / 宽松合并）抽成一份引擎，文件读取由调用方注入（页面用 fflate 流式解析、脚本用 SheetJS 读写）；引擎新增表头校验（缺列直接报错）与统计信息供命令行诊断。
- **33 清洗工具并入 `tools/cleaning/`**：
  - 目录更名，口径文件为 `engine.mjs`，网页侧只保留一行转发 `export * from '../../tools/cleaning/engine.mjs'`，脚本直接 `import('./engine.mjs')`，删除生成副本与同步脚本。
  - 该目录因此成为网页构建依赖（不可删除 / 改名）；整目录复制到别处 `npm install && npm run clean` 即可独立运行。

## 六、配置页与 SKU 弹窗（34–39）

- **34 颜色单元格新增 SKU 配置信息弹窗**：颜色单元格右侧 ⓘ 打开 `SkuDetailDialog.vue`，展示模式 / 评分档 / 系数、逐因子等级方块与 1-12 月条数 + 重量图（ECharts），弹窗内现算、不新增存储；ECharts 首次打开才按需引入并只注册必需模块，主包约 1.09MB → 559kB。
- **35 术语统一为「评分档 / 评分因子」**：界面、导出列头、提示文案与文档全部改口径；导入表头别名同时接受「评分档」与旧的「热度」，新旧导出文件都能回导。
- **36 新增策略层：自动策略 / 手动策略**：
  - 配置升 v2，`rules` 改为 `strategies[]`（自动 / 手动），v1 自动包成自动策略并补全手动策略。
  - 手动清单单独存 `src/stocking/manualSkus.json`（唯一标识 → 模式 / 系数），不写进 config.json、不挂在 SKU 行上，重新导入与刷新都保留，评估器命中即短路。
  - 内置「自定模式」（按系数比较）与「滞销模式」（不参与备货）。
- **37 策略入口上移 + 配置页输入失焦还原修复**：策略单选移到弹窗标题行；修复数值输入失焦即还原（原读取函数每次返回新对象，v-model 写入被下一次渲染丢弃）。
- **38 弹窗标题行与按钮文案**：关闭按钮回右上角、策略单选紧邻其左，元信息固定一行四列；「重置」更名为「放弃修改」并补齐悬停说明。
- **39 配置页底部动作布局**：五个次要按钮靠左、确定靠右，全部加悬停说明（禁用态用外层 `span` 保证提示可见）。

## 七、批量补货与只读化（40–44）

- **40 主面板批量补货**：首列复选框 + 表头全选（只作用于当前筛选结果），品名父行全选 / 半选，选择状态只存 SKU 标识、虚拟滚动不丢；底部浮动条 → 确认弹窗（默认量取 `getSuggestedPlanned`）→ 统一经 `applyRestockPlans` 覆盖写「需安排」并进采购清单，紧急补货先在调用处把追加换算成绝对量再走同一函数。
- **41 导入值全部改为只读，仅「需安排」可填**：生产中、欠货、周消耗、周转入、在途库存、在仓库存、品名、颜色都改为纯文本展示，面板内改名与数值编辑入口一并删除；要改数据请重新导入或改源表。
- **42 新增「累积条数」与「每月订单数」，月均条数改为真月均**：累积条数 = Σ 出库数量 ÷ 换算系数，月均条数 = 累积条数 ÷ 动销月份，周消耗 = 月均条数 ÷ 4（语义变化，系数需重新校准）；每月新增订单数列（该月有效行数），Σ 月度订单数 = 订单总数；累积条数成为第 5 个动销指标。
- **43 SKU 弹窗「色彩」移到标题行并按色调区分**：黑白用灰阶样式、彩色用低饱和彩虹渐变，判定与清洗口径一致（分类含「黑白」即灰阶）。
- **44 主面板整行点击即勾选**：SKU 行点击整行等于勾选，品名父行等于整组全选 / 全不选；勾选列、需安排输入、采纳 / 撤销、详情按钮各自 `@click.stop`。

## 八、多方案、校准与指标扩容（45–48）

- **45 配置方案（多套配置隔离）+ 按当前数据校准**：
  - `config.json` 升 v3（`{ version, activeProfileId, profiles[] }`，方案内部仍是 v2 单份配置），配置页顶部方案栏切换 / 复制 / 重命名 / 删除，底部导入导出整份方案文件，切换对两页同时生效。
  - 「按当前数据校准」取已导入行非零值分位（S≈p90 / A≈p70 / B≈p40），全 0 列提示「无有效数据」跳过，可勾选按 S 个数重建评分档，校准只改草稿。
  - 内置「演示配置」与生产配置互不覆盖。
- **46 累计客户接通数据源**：出入库明细汇总新增可选的「客户」列，按文本去重计数（`distinct`），缺列时整列为 0、历史数据仍可清洗；`tools/cleaning/simulate-customers.js` 按单号造客户（固定种子可复现），加工出库填加工厂。
- **47 新增「客户CR5率」**：引擎新增 `topShare` 聚合（前 5 客户销量 ÷ 该 SKU 总销量，0~1 比例），只在销售表按百分比展示，不写回主面板、不进评分；父行按累积条数加权平均。
- **48 「动销客户」改称「累计客户」**：只改显示名与导出列名、字段键不变，新增别名映射，旧表头仍可导入。

## 九、需求 1.5：模式 → 系数重构（49–58）

- **49 系数配置重构**：
  - 删除「模式 → 评分档 → 系数」，改为「月均条数 → 5 个固定模式（热销 / 常规 / 按量 / 尾货 / 滞销）→ 系数」：热销与常规按日库销比、按量按库存条数比较，尾货、滞销与专属品（累计客户 = 1）只标注不取系数。
  - 库存与销量统一换算成条比较（1 条 = 100 码 = 20 公斤），清洗引擎总表新增「条换算系数」。
  - 加权月销量 = 近 1 个月 ×50% + 近 3 个月月均 ×30% + 近 12 个月月均 ×20%（可改，须合计 100%）；配置升 v4、旧配置整份丢弃取内置默认。
  - 主面板删评分档 / 等级列，新增「日库销比（天）」，配置页改为 5 张模式卡片。
- **50 需求 1.5.1：5 维健康度评分 + 建议补货改补到绿带中位**：
  - 5 维（客户 CR5、累计客户、销售环比、本次进销比、预估月消耗）各配中风险区间与权重，综合分 50~70 为中风险，存 `config.scoring` 并由配置页「评分设置」改区间 / 权重 / 三档得分（只改草稿）。
  - 建议补货由 `ceil(正常库存 × 80% − 理论库存)` 改为 `ceil(正常库存 − 理论库存)`，函数移到 `utils/inventory.js` 供主面板与弹窗共用。
- **51 评分设置独立成组件**：「评分设置」独立为 `ScoringSettings.vue`；每个维度改为低 / 中 / 高三条区间（端点留空表示不限），端点同落两档按「中 → 高 → 低」取第一条命中；修正本次进销比方向（< 20% 低、20%~30% 中、> 30% 高，原实现反了）。
- **52 SPU 分级**：品名父行按「月均条数合计」分六档 S+ / S / A / B / C / Z（≥2500 / ≥300 / ≥100 / ≥30 / ≥1 / 其余），与 SKU 级模式判定互不影响，整个品名无月均值显示「—」；阈值存方案 `spuGrades.tiers`（仍 v4，老配置自动补默认），配置页「SPU 分级」可改，主面板父行模式列渲染等级徽标。
- **53 配置信息页重排**：整页改为「吸顶工作条 + 模式工作区（左列表 / 右编辑）+ 三张折叠卡片」，长说明收进 ⓘ tooltip，删除「备货详情」结果表（结果统一在主面板查看）；页面高度由 7280px 收进一屏。
- **54 模式判定改成月均条数区间**：5 个模式由单一「≥ 阈值」改为 `range { from, to }`（空表示不限），按顺序取第一条命中，落在空档时退回「下限最高且不高于该值」的模式；旧配置自动迁移。

- **56 SKU 弹窗折叠月度订单数图**：默认只显示月度销量图，下方折叠行「月度订单数」点击展开（`grid-template-rows 0fr → 1fr` 纯 CSS 过渡），关闭弹窗即复位为折叠。

## 十、手动策略与评分细化（59–62）

- **59 手动「滞销模式」更名为「排除模式」**：行为 `slow` → `exclude`、模式 id `manual-slow` → `manual-exclude`，语义为「不参与备货策略：不计预警、不进紧急补货、不给建议值」，仍可人工填需安排；旧配置与旧手动清单自动迁移。
- **60 手动「自定模式」更名为「自定系数模式」**：仅改内置名称（行为与 id 不变），与配置页行为列「自定系数」对齐；旧名称自动迁移、自定义名称不被覆盖。
- **61 新增手动「订单货模式」**：行为 `order`（`manual-order`）：不参与预警与评分，需安排填多少就下多少（占位「按订单填写」），采纳后进采购清单并在 `/purchase` 同路下单；该类行仍按销量排序、不沉底。
- **62 销售环比率按系统日期取月份**：不再读销售表基准月，≥26 号取「本月 vs 上月」、≤25 号取「上月 vs 前月」；跨年缺月返回无数据并说明缺哪两个月；上期为 0 记 +100%、本期为 0 记 0%、两期都为 0 记无数据；悬停写明比的是哪两个月。

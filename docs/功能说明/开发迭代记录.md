# 布料库存规划 Demo｜开发迭代记录

按阶段记录从截图原型到当前 Demo 的实现与口径变更，每条只留结论；验证一律为「`npm run build` 通过 + 浏览器或 Node 实测」，不再逐条罗列。现行口径以[需求文档1.1](../需求文档/需求文档1.1.md)、[模式与系数设置](./模式与系数设置.md)、[数据清洗规则](./数据清洗规则.md)、[采购下单流程](./采购下单流程.md)为准。

## 一、原型与早期交互（1–13）

- **1 起点**：Element Plus 静态库存表 → Vue 3 + Element Plus + Pinia + Router，导出用 fflate 在浏览器内组装 XLSX；数据只在内存，刷新回初始。
- **2 表格原型**：分组表头（商品 / 入口 / 出口 / 库存 / 数据反馈）＋模式系数算红线 / 正常 / 峰值，预警四色（紧急红 / 降低库存紫 / 无需补货绿 / 常规补货黄），系数缺省不参与判定。
- **3 分组与共享数据**：品名父行 → 颜色子行可折叠，父行汇总数量、缺口率与库销比按汇总分子分母重算；主面板 + 配置页共享 Pinia，切路由不丢修改。
- **4 紧急补货 / 导出**：弹窗固定打开瞬间的清单，推荐量 `max(0, ceil(正常库存 × 80% − 预计库存))`；「保存 Excel」只作下载副本，不当持久化。
- **5 筛选与行选择**：关键词 + 四色多选（同类为或、跨维为且），父行只在有匹配子行时显示并按可见子行重算，计数仍按全量 SKU。
- **6 需安排草稿与采纳**：需安排先存草稿、只做浅色预览，采纳才写入并锁定，撤销回滚原值；采纳与紧急补货同写采购清单。
- **7 边界**：计算与预警以颜色 SKU 为单位，父行只汇总；未采纳草稿不参与正式计算。
- **8 验证方式**：每轮 `npm run build` + 浏览器实测，此后不再逐条罗列。
- **9 库存分层**：在仓 / 在途 / 理论库存，在途 = 需安排 + 生产中、理论 = 在仓 + 在途；预警、缺口与紧急补货改按理论库存计算。
- **10 品名列独立**：品名与颜色拆两列、品名固定最左，父行在品名列折叠、子行重复显示品名。
- **11–12 示例面板与导航分组**：示例面板复用同一套组件、按 `panelKey` 隔离数据；导航抽成共享组件（示例面板于第 74 条整体删除）。
- **13 Excel 导入与 3 万行性能改造**：按「品名 + 颜色」整表替换、确认前预览逐行报错；表格改自研虚拟化 + 单行缓存增量刷新，3 万行导入 33.2s → 1.55s、DOM 103 万 → 约 1400 节点、堆 2.29GB → 约 130MB（见[主面板性能优化](./主面板性能优化.md)）；配置页超 500 行改扁平分页。

## 二、库存口径与全面板（14–24）

- **14–15 预计库存**：在途改为导入项，理论 = 在仓 + 在途；再把需安排接回为评估层——预计库存 = 理论库存 + 需安排，预警 / 缺口 / 紧急补货按预计判定，理论库存不被改写；列序定为在仓 → 周转入 → 在途 → 理论 → 预计，导出多一列、导入忽略该列以防重复计数。
- **16–17 紧凑化**：行高 44 → 34px，列宽 `minmax(宽度px, 宽度fr)` 按比例分摊；移除「加入商品」，新增只能靠导入；配置页品名 / 颜色拆两列与主面板对齐。
- **18–22 全面板（只读全量视图）**：两级结构（品名汇总 + 颜色折叠）、数字列自动参与汇总、默认按品名聚合月均降序排序，3 万行约 0.33s 可交互；评分因子收敛为 4 个动销指标并调整热销A 默认阈值。
- **23–24 销售表与双文件导入**：`/all` 改 `/sales`，列固定为品名 / 颜色 + 动销指标 + 1-12 月条数与重量；导入改为「总表 + 销售表」按表头自动识别角色，销售表 4 个动销指标写回主面板重算评分，整表替换抽到 `inventoryApply.js`。

## 三、备货策略配置化（25–30）

- **25 模式 → 评分档 → 系数**：新增自包含模块 `src/stocking/`（字段 / 默认值 / 校验 / 引擎）；模式因子定归属 → 每条模式自选评分因子与 S/A/B/C 阈值 → 档位取系数；开发态写回 `config.json` 并屏蔽其 HMR；SKU 键改为「唯一标识」。
- **26 修复保存配置后主面板仍用旧模式**：派生字段改为渲染时按当前配置现算，store 与导入不再存快照。
- **27 防误删与撤销 / 重做**：删除两段确认（3 秒内再点生效），其余操作靠撤销兜底（JSON 快照、600ms 合并、栈深 50、支持快捷键）。
- **28–29 修复改名后系数全「缺省」**：`evaluate()` 直接返回命中档位系数，行数据带 `strategyIssue`；四列缺省改显示短原因，悬停看完整说明。
- **30 唯一标识不再作为界面列**（导入模板与导出仍保留以维持关联）。

## 四、清洗引擎与配置页（31–39）

- **31 导入分表**：一次多选 5 张分表、按文件名认领、缺一张不允许开始；清洗在 Worker 执行并回传进度，出入库明细（约 150MB）改流式逐行解析。
- **32–33 口径收敛到单一引擎**：清洗口径抽到 `tools/cleaning/engine.mjs`，网页侧只剩一行转发、脚本直接 import；该目录成为构建依赖，不可删除或改名。
- **34–35 SKU 弹窗与术语**：颜色单元格 ⓘ 打开 `SkuDetailDialog.vue`，现算模式 / 系数、因子等级与 1-12 月图（ECharts 按需引入，主包 1.09MB → 559kB）；术语统一为「评分档 / 评分因子」，导入同时认旧表头。
- **36–39 策略层与配置页交互**：配置升 v2，`rules` 改 `strategies[]`（自动 / 手动），手动清单单独存 `manualSkus.json`、评估命中即短路；策略单选移到弹窗标题行；修复数值输入失焦还原；配置页次要按钮靠左、确定靠右并补悬停说明。

## 五、批量补货、只读化与多方案（40–48）

- **40 批量补货**：首列复选框 + 表头全选（只作用当前筛选结果）、品名父行全选 / 半选，选择只存 SKU 标识、虚拟滚动不丢；底部浮动条 → 确认弹窗（默认量取 `getSuggestedPlanned`）→ 统一经 `applyRestockPlans` 覆盖写「需安排」，紧急补货先换算成绝对量再走同一函数。
- **41 导入值全部只读**：品名 / 颜色 / 库存 / 销量等一律纯文本，面板内的改名与数值编辑入口删除，要改数据就重新导入或改源表。
- **42 指标扩容**：累积条数 = Σ出库数量 ÷ 换算系数，月均条数 = 累积条数 ÷ 动销月份，周消耗 = 月均条数 ÷ 4（语义变化，系数需重校）；新增每月订单数，Σ 月度订单数 = 订单总数。
- **43–44**：弹窗「色彩」移到标题行并按色调区分（黑白灰阶、彩色低饱和彩虹）；主面板整行点击即勾选，品名父行等于整组全选 / 全不选。
- **45 多方案**：配置升 v3（`{ version, activeProfileId, profiles[] }`），方案栏切换 / 复制 / 重命名 / 删除 + 整份导入导出；「按当前数据校准」取非零值分位（S≈p90 / A≈p70 / B≈p40），只改草稿。
- **46–48 客户指标**：出入库明细新增可选「客户」列（去重计数），缺列整列为 0；新增「客户CR5率」（前 5 客户销量 ÷ 总销量，只在销售表按比例展示、父行按累积条数加权平均）；「动销客户」改名「累计客户」并保留旧表头别名。

## 六、需求 1.5：模式与评分（49–58）

- **49 模式重构**：改为「月均条数 → 5 个固定模式（热销 / 常规 / 按量 / 尾货 / 滞销）→ 系数」，热销与常规比日库销比、按量比库存条数，尾货 / 滞销 / 专属品只标注不取系数；库存与销量统一换算成条（1 条 = 100 码 = 20 公斤）；加权月销量 = 近 1 月 ×50% + 近 3 月月均 ×30% + 近 12 月月均 ×20%（可改，须合计 100%）；配置升 v4、旧配置整份丢弃；主面板删评分档 / 等级列、新增「日库销比（天）」。
- **50 5 维健康度评分**：客户 CR5 / 累计客户 / 销售环比 / 本次进销比 / 预估月消耗各配区间与权重，综合 50~70 为中风险；建议补货改 `ceil(正常库存 − 理论库存)`。
- **51 评分设置独立成组件**：每个维度改低 / 中 / 高三条区间（端点留空表示不限，同落两档按中 → 高 → 低取第一条命中）；修正本次进销比方向。
- **52 SPU 分级**：品名父行按月均条数合计分 S+ / S / A / B / C / Z（≥2500 / ≥300 / ≥100 / ≥30 / ≥1 / 其余），与 SKU 级模式互不影响，阈值存 `spuGrades.tiers`。
- **53 配置页重排**：「吸顶工作条 + 模式工作区（左列表 / 右编辑）+ 三张折叠卡片」，长说明收进 ⓘ，删掉结果表，页面高度由 7280px 收进一屏。
- **54 模式判定改区间** `range { from, to }`，按顺序取第一条命中，落空档退回「下限最高且不高于该值」的模式。
- **55 按量模式也分流专属品**：累计客户 = 1 时标「按量·专属品」，不取系数、不参与计算。
- **56 弹窗月度订单数图默认折叠**（纯 CSS 过渡），关弹窗复位。
- **57 出码率接入、统一公斤口径**：码 ÷ 出码率 = 公斤，无法换算的 SKU 在基准表阶段剔除；三档 / 缺口 / 建议量全按公斤，删除条换算系数；销售表每月「条数 / 销量(公斤) / 订单数」三列 + 累积销量，评分同步改公斤口径。
- **58 按量模式的健康度定制**：改「本次进销比（<40% 低 / 40%~60% 正常 / >60% 高）」+「累计客户数（<5 高 / 5~10 中 / >10 低）」两项判定、不算综合分，阈值存模式 `healthScoring`，规则文案随阈值生成。

## 七、手动策略（59–62）

- **59 手动「滞销模式」改名「排除模式」**（`slow` → `exclude`）：不计预警、不进紧急补货、不给建议值，仍可人工填需安排；旧配置与旧手动清单自动迁移。
- **60–61**：手动「自定模式」改名「自定系数模式」；新增「订单货模式」（`order`），不参与预警与评分，需安排填多少就下多少。
- **62 销售环比按系统日期取月**：≥26 号比「本月 vs 上月」，≤25 号比「上月 vs 前月」；缺月、上期为 0、两期都为 0 各有专门文案。

- **66–69**：空行不再被归一化丢弃（`keepBlankEntries` 运行时开关）；`settings.json` 升 v2 新增独立分单人员表；分类改「分类下拉 + 人员勾选」；分类未分配人员时回退到人员表全部。
- **70 屏蔽 SKU / 品名**：写 `src/stocking/hiddenSkus.json`，只影响主面板展示（行、父行合计、计数、批量与紧急补货、导出），源表与销售数据不动；解除在 `/hidden`。

- **73 缸规则初版**：`settings.json` 升 v3，规则 = 判据 + 分档（`skip` / `fixed` / `vat` / `round`），需求 > 0 时至少 `minVats` 缸；缸只作用于下单，不改需安排与建议值。
- **74–75**：删除示例面板与 `panelKey`；屏蔽列表抽成独立页 `/hidden`（分组树、多选、逐个 / 全部解除、搜索）。
- **76 删除手动「排除模式」**：旧方案文件里的 `exclude` / `slow` 模式加载时丢弃，旧手动清单记录随之清除（SKU 回到自动策略）。
- **77 缸规则改为「按缸型就近取整」**：一个 SKU 是一组缸型（如 80 / 160 / 240），就近取整、正好一半向上、超最大缸取模、最少 1 缸，临界点（120 / 200 / 360）由缸型推导而非手写；不拼缸，一张分订单只用一种缸型；下单页缸数只收整数，非整缸只提示。
- **78 分订单默认带值**：`addEntry()` 用缸规则对「需安排 − 已下单」换算并带出公斤与缸数，染厂 / 人员沿用上一张；进面板或「去下单」弹窗时也自动带一张（同一 SKU 只带一次，删掉不再补），「按建议添加」按钮删除。
- **79 「状态」改「下单数量」+ 新颜色口径**：颜色收敛到 `src/purchase/fillTone.js`——未下单灰 → <80% 黄 → 80%~100% 绿 → 超一缸内绿 → 超过一缸红，列表、右面板进度、底部差额与弹窗共用。
- **80 采购下单页排版**：左栏 322 → 460px、品名 / 颜色拆两列、数字居中；列表撤销改两段式（首点变「确认撤销」，点别处取消，⋯ 菜单仍弹窗确认）；颜色规则收进悬停，不再占版面画图例。

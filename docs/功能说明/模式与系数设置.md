# 模式与系数设置（v1.5）

> 状态：已实现并验证（2026-11-10）。本文是「模式 → 系数 → 预警」的**唯一口径说明**，也是交接给其他对话 / Agent 的入口文档。
> 需求来源：[需求文档1.5.md](../需求文档/需求文档1.5.md)。
> 数据从哪来、怎么清洗、每一列怎么算：见 [数据清洗规则.md](./数据清洗规则.md)。

---

## 1. 一句话概述

```
月均条数 → 判定 5 个模式之一
         ├─ 热销 / 常规：日库销比（够卖多少天）与系数比较
         ├─ 按量：库存公斤数与系数比较（系数单位 = 公斤）
         └─ 尾货 / 滞销 / 专属品：只在模式列标注，不参与计算
        → 三档库存、缺口、预警灯
```

**没有评分因子、没有评分档（S/A/B/C）、没有校准**。旧的三层结构（模式 → 评分档 → 周倍数系数）已在本次重构中整体删除。

---

## 2. 五个模式（顺序即判定优先级，模式固定不可增删）

| 序 | 模式 | 判定（月均条数区间） | 比较方式 | 系数 |
|---|---|---|---|---|
| 1 | **热销** | 30 ~ 不限 | 日库销比（天） | 流通品：黑白 20/40/60、彩色 15/30/45；专属品不设系数 |
| 2 | **常规** | 10 ~ 30 | 日库销比（天） | 流通品：黑白 15/30/45、彩色 10/20/30；专属品不设系数 |
| 3 | **按量** | 3 ~ 10 | 库存公斤数（公斤） | 流通品：黑白 40/80/200、彩色 40/80/120；专属品不设系数 |
| 4 | **尾货** | 0.01 ~ 3 | — | 仅标注 |
| 5 | **滞销** | 0 ~ 0.01 | — | 仅标注 |

- 判定只看**导入的 `月均条数`**（清洗口径：`累积条数 ÷ 动销月份`），不看加权月销量。
- 每个模式是一段**月均条数区间**，可在配置页改；端点留空表示不限（下限按 0、上限按正无穷）。引擎按模式顺序取第一条「区间包含该值」的模式，所以端点同时落进相邻两段时更靠前的模式优先；若值落在所有区间的空档里，退回「下限最高且不高于该值」的模式。
- **专属品**：命中热销 / 常规 / 按量时，若 `累计客户 = 1` → 标记为「热销·专属品」「常规·专属品」「按量·专属品」，不取系数、不参与计算。`累计客户 ≥ 2` 或缺失按流通品处理。

## 3. 单位口径：统一到「条」

库存列（在仓 / 在途）的导入单位是**码**或**公斤**，销量是**条**，两者不能直接相除。

```
公斤 = 码 ÷ 出码率；公斤单位直接取原值
```

- 清洗引擎按品名查出码率，输出 `出码率` 与 `公斤系数`（码 = 1 ÷ 出码率，公斤 = 1）；条 / 件 / 米等无法换算的 SKU 直接被清洗剔除。
- 网页端：`库存公斤 = 库存数量 × 公斤系数`；在途库存取进仓重量，本身就是公斤。
- 公斤系数缺失（旧模板 / 漏选出码率文件）→ 该行显示「缺出码率」，不参与计算。

> 为什么不用重量：`产品资料` 没有克重与门幅，码无法换算成公斤；而「条」是清洗引擎已有的统一口径。

## 4. 计算链

### 4.1 加权月销量（配置页可调权重）

```
基准月 M0 = 数据里最后一个有销量的月份（salesSheet.baselineMonth）
M1   = 销量(M0)
M3   = mean(销量(M0 … M0-2))      缺失月按 0
M12  = mean(销量(M0 … M0-11))     12 个月全平均，含 0

加权月销量 = w1 × M1 + w3 × M3 + w12 × M12     默认 50% / 30% / 20%
日销量     = 加权月销量 ÷ 30
```

三档权重必须合计 100%；配置页会把它们展开成 12 个月权重供核对（最新月 61.67%、前两月各 11.67%、其余各 1.67%）。

### 4.2 日库销比（热销 / 常规）

```
日库销比(天) = 预计库存(公斤) ÷ 日销量(公斤)
预计库存     = 理论库存 + 已采纳的需安排     （需安排为 0 时两者相同）
加权月销量 = 0 → 日库销比 = ∞ → 直接判「降低库存」（紫）
```

### 4.3 预警灯（沿用 20% 绿区）

| 条件（热销/常规看天数；按量看条数） | 灯 |
|---|---|
| 指标 < 红线 | 🔴 紧急补货 |
| 指标 > 峰值 | 🟣 降低库存 |
| 正常 × 80% ～ 120% | 🟢 无需补货 |
| 其余 | 🟡 常规补货 |

预警灯纯给人看：默认（需安排为 0）比的是理论库存，采纳需安排后自动比预计库存。

### 4.4 三档库存 / 缺口 / 建议需安排

```
热销/常规：红线库存(条) = 日销量 × 系数天数；按量：红线库存(条) = 系数条数
三档库存(公斤) = 日销量(公斤/天) × 系数天数（按量模式直接取系数公斤）
缺口量   = 正常库存(数量) − 预计库存(数量)
缺口率   = 缺口量 ÷ 正常库存(数量)
建议需安排 = ceil(正常库存(数量) − 理论库存(数量))
```

绿色带的上下限是「正常库存 × 80% / × 120%」，中位就是正常库存本身，所以建议需安排的目标位是补到**正常库存**（不是绿带底线）。

三档库存与缺口都换回**数量**（码 / 公斤），才能和「理论库存」「需安排」同单位比较。

### 4.5 主面板各列的单位

| 列 | 单位 |
|---|---|
| 生产中 / 欠货 / 周转入 / 在途库存 / 在仓库存 | 数量（码 / 公斤，导入原值） |
| **周销量** | **公斤/周**（清洗直接按公斤输出） |
| 理论库存（在仓+在途）/ 预计库存（理论+需安排）/ 缺口量 | 数量 |
| 日库销比 | 天 |
| 缺口率 | % |

全表库存类列统一到「公斤」，避免码与条、码与公斤混比。缺少出码率的行在清洗阶段就已剔除，不会进入主面板。

### 4.6 不参与计算的模式

**尾货 / 滞销 / 专属品**：三档库存、缺口量、缺口率、日库销比显示 `—`，灰灯，不进紧急补货、无建议值、父行汇总时跳过，但**仍可人工填需安排**。

父行（品名汇总）只加总**有数据**的子行，不再「一个子行缺省就整父行缺省」；日库销比按「汇总条数 ÷ 汇总日销量」还原。

## 5. 手动策略

保持原有的两种行为，SKU 归属存 `src/stocking/manualSkus.json`：

| behavior | 含义 | 计算表现 |
|---|---|---|
| `custom` | 自定系数 | 人工填的红 / 正 / 峰，按**条**比较（与按量模式同一口径） |
| `exclude` | 排除 | 不参与备货策略：不计预警、不进紧急补货、无建议值 |
| `order` | 订单货 | 为特定厂家订做、需求不明晰：同样不参与备货策略，额外按订单记录订单名 / 订单厂家 / 数量 / 备注（一个 SKU 可挂多张订单） |

命中手动清单即短路，不跑模式判定。清单独立成文件，跨导入、跨刷新、跨方案有效。

`exclude` 原名「滞销」（`slow`，模式 id `manual-slow`）：归一化时 behavior 与 id 一并迁移成 `exclude` / `manual-exclude`，旧配置、旧缓存与旧手动清单里的记录继续有效；名称为旧内置名「滞销模式」的，跟随改名为「排除模式」，其它自定义名称不动。

`custom` 的内置名从「自定模式」改为「自定系数模式」（模式 id `manual-custom` 不变）：归一化时把旧内置名「自定模式」改写成「自定系数模式」，自定义名称同样保留。选择该模式的 SKU 在弹窗里人工填红线 / 正常 / 峰值（单位公斤），按库存公斤数比较。

订单货模式（`modeId: manual-order`）的条目多带一个 `orders` 数组，保存 `{ name, factory, quantity, note }`：

```json
"唯一标识": {
  "modeId": "manual-order",
  "orders": [
    { "name": "红色加厚·指定LOGO", "factory": "东华纺织", "quantity": 1200, "note": "加急" }
  ]
}
```

订单在 SKU 弹窗里增删改（可挂多张），四个字段全空的占位行会被丢弃；配置页手动清单只显示「订单货：N 单」并把明细放在悬停提示里。订单信息只做记录，不参与任何备货计算。

## 7. 配置结构（v4）

```jsonc
{
  "version": 4,
  "activeProfileId": "production",
  "profiles": [{
    "id": "production",
    "name": "生产配置",
    "config": {
      "version": 4,
      "salesWindow": { "weights": { "m1": 0.5, "m3": 0.3, "m12": 0.2 } },
      "spuGrades": { "tiers": [
        { "key": "sPlus", "label": "S+", "minMonthlyAvg": 2500 },
        { "key": "s",     "label": "S",  "minMonthlyAvg": 300 },
        { "key": "a",     "label": "A",  "minMonthlyAvg": 100 },
        { "key": "b",     "label": "B",  "minMonthlyAvg": 30 },
        { "key": "c",     "label": "C",  "minMonthlyAvg": 1 },
        { "key": "z",     "label": "Z",  "minMonthlyAvg": null }
      ] },
      "strategies": [
        { "id": "auto", "behavior": "auto", "modes": [
          { "key": "hot",    "name": "热销", "range": { "from": 30, "to": null }, "metric": "days",
            "participates": true, "splitByCustomer": true,
            "coefficients": { "流通品": { "黑白": {"redLine":20,"normal":40,"peak":60},
                                          "彩色": {"redLine":15,"normal":30,"peak":45} },
                              "专属品": null } },
          { "key": "normal", "name": "常规", "range": { "from": 10, "to": 30 }, "metric": "days",  "...": "..." },
          { "key": "bulk",   "name": "按量", "range": { "from": 3, "to": 10 }, "metric": "stock",
            "healthScoring": { "ratio": { "normalFrom": 40, "normalTo": 60 },
                               "customers": { "normalFrom": 5, "normalTo": 10 } },
            "coefficients": { "流通品": { "黑白": {"redLine":40,"normal":80,"peak":200},
                                          "彩色": {"redLine":40,"normal":80,"peak":120} } } },
          { "key": "tail",   "name": "尾货", "range": { "from": 0.01, "to": 3 }, "metric": "none", "participates": false },
          { "key": "slow",   "name": "滞销", "range": { "from": 0, "to": 0.01 }, "metric": "none", "participates": false }
        ] },
        { "id": "manual", "behavior": "manual", "modes": [ /* 自定系数模式 / 排除模式 / 订单货模式 */ ] }
      ]
    }
  }]
}
```

要点：

- 模式 key 固定为 `hot / normal / bulk / tail / slow`，顺序即优先级；归一化时按此顺序重建，缺失的补默认值。
- `metric`：`days`（比天数）/ `stock`（比条数）/ `none`（不参与）。
- 系数按「客户类别 → 色彩 → 红/正/峰」分组；不分流的模式只有「流通品」一组。
- `healthScoring` 只存在于「按量」模式：SKU 弹窗里两项判定的阈值 —— `ratio`（本次进销比，`%`，`< normalFrom` 低风险、`normalFrom ~ normalTo` 正常、`> normalTo` 高风险）与 `customers`（累积客户数，`< normalFrom` 高风险、`normalFrom ~ normalTo` 中风险、`> normalTo` 低风险）。默认 `40 ~ 60` / `5 ~ 10`，在配置页「按量」模式的系数表下方直接编辑；老配置 / 老缓存缺这一段时由 `normalizeConfig` 补默认。
- `spuGrades` 是 SPU（品名）分级：固定 6 档、固定顺序（`sPlus / s / a / b / c / z`），只存名称与「月均条数下限」，末档 `z` 的 `minMonthlyAvg` 恒为 `null`（兜底收下低于上一档的 SPU），阈值必须从高到低严格递减。等级只按「该品名全部 SKU 的月均条数之和」判定、只用于主面板品名汇总行的模式列展示，不参与任何备货计算。新增该段不升版本号：老配置 / 老缓存缺 `spuGrades` 时由 `normalizeConfig` 补默认。
- **旧版本配置（v1 / v2 / v3）整份抛弃**：`normalizeConfig` 遇到非 v4 直接返回内置默认，不写迁移代码。
- 演示方案已封禁：`persistence.js` 会把 id 为 `demo` 的方案从方案列表剔除（源文件与缓存都过滤）；模拟逻辑保留在 `src/stocking/demoProfile.js`，下次启用从这里开始。

## 8. 校验规则

`validateConfig(config)` → `{ ok, errors, warnings }`（[validate.js](../../src/stocking/validate.js)）

**errors（阻断保存）**
- 模式名称为空 / 重复
- 阈值必须从热销到滞销严格递减
- 参与计算的模式：系数缺失、为负、或违反 `红线 ≤ 正常 ≤ 峰值`
- 按量模式健康度：本次进销比 / 累积客户数的正常区间下界大于上界
- 三档权重之和不等于 100%
- SPU 分级：等级名称重复，或阈值没有从高到低严格递减
- 手动模式名称重复、自定系数模式默认系数不完整 / 为负 / 顺序错

**warnings（提示不阻断）**
- 参与计算但比较方式为「不参与」

## 9. 模块与 API

```
src/stocking/
├─ config.json      唯一配置（v4 多方案文件）
├─ constants.js     色彩、系数三键、条换算表、动销指标、权重默认值
├─ defaults.js      createDefaultConfig() / createDefaultAutoModes()（恢复默认的唯一依据）
├─ validate.js      normalizeConfig / normalizeProfileFile / validateConfig / getAutoModes …
├─ engine.js        createEvaluator / evaluateItem / summarizeEvaluation / weightedMonthlySales / findBaselineMonth
├─ spuGrades.js     SPU（品名）分级：默认六档 / normalizeSpuGrades / validateSpuGrades / resolveSpuGrade
├─ persistence.js   load / save / reset / export / import（多方案；dev 写盘、prod 缓存）
├─ manual.js        手动清单读写
├─ demoProfile.js   演示配置占位（已封禁）
└─ index.js         门面
```

`createEvaluator(config, { manualOverrides, baselineMonth })` → `evaluate(item)`；
`evaluateItem(item, evaluator)` 返回的行新增：`modeKey / modeName / modeLabel / modeMetric / modeParticipates / stockingCoefficients / monthlySales / dailySales / exclusive / excluded / strategy / manualBehavior`。

`src/utils/inventory.js` 的 `calculateInventoryRow(row)` 再产出：`unitFactor / theoreticalUnits / projectedUnits / dailySales / daysOfStock / redLineStock / normalStock / peakStock / shortage / shortageRate / strategyAvailable / strategyIssue / excluded / urgencyText / urgencyTone`。

`resolveSpuGrade(月均条数合计, grades)` 返回 `{ key, label, tone, minMonthlyAvg } | null`（月均缺失时返回 null，界面显示「—」）；`describeSpuGradeThresholds(grades)` 返回 `{ sPlus: '≥ 2500', …, z: '< 1' }`，供配置页摘要与主面板悬停说明拼文案。

## 10. 配置页 UI

```
配置信息（/config，示例配置 /example/config 共用）
├─ 吸顶工作条：配置方案（下拉 复制 重命名 删除）｜ 已保存 / 有未保存的修改、撤销 / 重做 / 放弃、方案文件（导出 / 导入 / 恢复默认）、确定
├─ 模式工作区
│  ├─ 策略标签：自动策略（5 个模式）｜ 手动策略（N 个 SKU）
│  ├─ 【自动策略】左列模式列表（名称 + 命中数 + 按天数 / 按条数 / 仅标注）
│  │                右列当前模式：名称 + 判定口径徽标 + 命中数
│  │                            → 月均条数 ≥ X（附区间说明）
│  │                            → 系数表：流通品（黑白 / 彩色 × 红线 / 正常 / 峰值），表头只写一次
│  │                            → 健康度判定（仅按量模式）：本次进销比 40% ~ 60%、累积客户数 5 ~ 10 个
│  └─ 【手动策略】手动模式（名称 / 行为 / 说明 / 默认系数）+ SKU 清单
├─ 销量加权（折叠）：近1月 / 近3月月均 / 近12月月均 + 合计校验，展开看 12 个月展开值
├─ 评分设置（折叠）：5 维评分「维度 × 权重 × 低 / 中 / 高」表格 + 编辑弹窗
└─ SPU 分级（折叠）：S+ / S / A / B / C / Z 六档阈值与命中数 + 编辑弹窗
```

长说明（判定口径、加权公式、评分与分级规则、手动策略规则）统一收进标题旁的 `ⓘ` tooltip；折叠卡片的标题行只保留一行结论摘要。页面不再提供「备货详情」结果表，结果统一在主面板查看。

`tools/check-stocking.mjs` 覆盖 8 种场景（商品单位 100 码 / 20 公斤）：

| SKU | 月均条数 | 库存 | 结果 |

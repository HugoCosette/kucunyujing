# 模式与系数设置（v1.5）

> 状态：已实现并验证（2026-11-10）。本文是「模式 → 系数 → 预警」的**唯一口径说明**，也是交接给其他对话 / Agent 的入口文档。
> 需求来源：[需求文档1.5.md](../需求文档/需求文档1.5.md)。
> 数据从哪来、怎么清洗、每一列怎么算：见 [数据清洗规则.md](./数据清洗规则.md)。

---

## 1. 一句话概述

```
月均条数 → 判定 5 个模式之一
         ├─ 热销 / 常规：日库销比（够卖多少天）与系数比较
         ├─ 按量：库存公斤数与系数比较（系数单位 = 公斤）
         └─ 尾货 / 滞销 / 专属品：只在模式列标注，不参与计算
        → 三档库存、缺口、预警灯
```

**没有评分因子、没有评分档（S/A/B/C）、没有校准**。旧的三层结构（模式 → 评分档 → 周倍数系数）已在本次重构中整体删除。

---

## 2. 五个模式（顺序即判定优先级，模式固定不可增删）

| 序 | 模式 | 判定（月均条数区间） | 比较方式 | 系数 |
|---|---|---|---|---|
| 1 | **热销** | 30 ~ 不限 | 日库销比（天） | 流通品：黑白 20/40/60、彩色 15/30/45；专属品不设系数 |
| 2 | **常规** | 10 ~ 30 | 日库销比（天） | 流通品：黑白 15/30/45、彩色 10/20/30；专属品不设系数 |
| 3 | **按量** | 3 ~ 10 | 库存公斤数（公斤） | 流通品：黑白 40/80/200、彩色 40/80/120；专属品不设系数 |
| 4 | **尾货** | 0.01 ~ 3 | — | 仅标注 |
| 5 | **滞销** | 0 ~ 0.01 | — | 仅标注 |

- 判定只看**导入的 `月均条数`**（清洗口径：`累积条数 ÷ 动销月份`），不看加权月销量。
- 每个模式是一段**月均条数区间**，可在配置页改；端点留空表示不限（下限按 0、上限按正无穷）。引擎按模式顺序取第一条「区间包含该值」的模式，所以端点同时落进相邻两段时更靠前的模式优先；若值落在所有区间的空档里，退回「下限最高且不高于该值」的模式。
- **专属品**：命中热销 / 常规 / 按量时，若 `累计客户 = 1` → 标记为「热销·专属品」「常规·专属品」「按量·专属品」，不取系数、不参与计算。`累计客户 ≥ 2` 或缺失按流通品处理。

## 3. 单位口径：统一到「条」

库存列（在仓 / 在途）的导入单位是**码**或**公斤**，销量是**条**，两者不能直接相除。

```
公斤 = 码 ÷ 出码率；公斤单位直接取原值
```

- 清洗引擎按品名查出码率，输出 `出码率` 与 `公斤系数`（码 = 1 ÷ 出码率，公斤 = 1）；条 / 件 / 米等无法换算的 SKU 直接被清洗剔除。
- 网页端：`库存公斤 = 库存数量 × 公斤系数`；生产中取生产排单的进仓重量，本身就是公斤。
- 公斤系数缺失（旧模板 / 漏选出码率文件）→ 该行显示「缺出码率」，不参与计算。

> 为什么不用重量：`产品资料` 没有克重与门幅，码无法换算成公斤；而「条」是清洗引擎已有的统一口径。

## 4. 计算链

### 4.1 加权月销量（配置页可调权重）

```
基准月 M0 = 数据里最后一个有销量的月份（salesSheet.baselineMonth）
某档窗口 = mean(销量(M0 … M0-N+1))      缺失月按 0，N 为该档「近 N 个月」

加权月销量 = Σ(各档月均 × 该档权重)     默认三档：近 1 个月 50% / 近 3 个月月均 30% / 近 12 个月月均 20%
日销量     = 加权月销量 ÷ 30
```

档位可增删，每档的「近 N 个月」可填 1–12（数据只有 12 个月），各档权重必须合计 100%。
默认三档展开到 12 个月的权重是：最新月 61.67%、前两月各 11.67%、其余各 1.67%。

### 4.2 日库销比（热销 / 常规）

```
日库销比(天) = 预计库存(公斤) ÷ 日销量(公斤)
预计库存     = 理论库存 + 已采纳的需安排     （需安排为 0 时两者相同）
加权月销量 = 0 → 日库销比 = ∞ → 直接判「降低库存」（紫）
```

日库销比只对热销 / 常规有「天」的口径；**按量模式比的是公斤库存**（指标就是预计库存本身），与「预计库存」列完全重复、还容易被误读成天数，所以主面板「日库销比」列在按量行显示 `--`（指标仍参与预警灯与缺口计算，只是不再重复展示）。

### 4.3 预警灯（沿用 20% 绿区）

| 条件（热销/常规看天数；按量看条数） | 灯 |
|---|---|
| 指标 < 红线 | 🔴 紧急补货 |
| 指标 > 峰值 | 🟣 降低库存 |
| 正常 × 80% ～ 120% | 🟢 无需补货 |
| 其余 | 🟡 常规补货 |

预警灯纯给人看：默认（需安排为 0）比的是理论库存，采纳需安排后自动比预计库存。

### 4.4 三档库存 / 缺口 / 建议需安排

```
热销/常规：红线库存(条) = 日销量 × 系数天数；按量：红线库存(条) = 系数条数
三档库存(公斤) = 日销量(公斤/天) × 系数天数（按量模式直接取系数公斤）
缺口量   = 正常库存(数量) − 预计库存(数量)
缺口率   = 缺口量 ÷ 正常库存(数量)
建议需安排 = ceil(正常库存(数量) − 理论库存(数量))
```

绿色带的上下限是「正常库存 × 80% / × 120%」，中位就是正常库存本身，所以建议需安排的目标位是补到**正常库存**（不是绿带底线）。

三档库存与缺口都换回**数量**（码 / 公斤），才能和「理论库存」「需安排」同单位比较。

### 4.5 主面板各列的单位

| 列 | 单位 |
|---|---|
| 生产中 / 欠货 / 周转入 / 在仓库存 | 数量（码 / 公斤，导入原值） |
| **周销量** | **公斤/周**（清洗直接按公斤输出） |
| 理论库存（在仓+在途）/ 预计库存（理论+需安排）/ 缺口量 | 数量 |
| 日库销比 | 天 |
| 缺口率 | % |

全表库存类列统一到「公斤」，避免码与条、码与公斤混比。缺少出码率的行在清洗阶段就已剔除，不会进入主面板。

### 4.6 不参与计算的模式

**尾货 / 滞销 / 专属品**：三档库存、缺口量、缺口率、日库销比显示 `—`，灰灯，不进紧急补货、无建议值、父行汇总时跳过，但**仍可人工填需安排**。

父行（品名汇总）只加总**有数据**的子行，不再「一个子行缺省就整父行缺省」；日库销比按「汇总条数 ÷ 汇总日销量」还原。

## 5. 手动策略

保持原有的两种行为，SKU 归属存 `src/stocking/manualSkus.json`：

| behavior | 含义 | 计算表现 |
|---|---|---|
| `custom` | 自定系数 | 人工填的红 / 正 / 峰（公斤），按库存公斤数比较 |
| `order` | 订单货 | 按客户订单填量：不计预警、不做健康度评分、无建议值；需安排填多少就按多少下单 |

命中手动清单即短路，不跑模式判定。清单独立成文件，跨导入、跨刷新、跨方案有效。

`order` 是第二种内置行为（模式 id `manual-order`，默认名「订单货模式」，说明「按客户订单填量：不计预警、不做评分，需安排填多少就下多少」）：命中后 `participates = false`、`excluded = true`，主面板模式列显示「订单货模式」，预警灯为灰（悬停「订单货：按客户订单填量，不参与预警与评分」）、评分「不参与」、缺口 / 库销比显示 `—`，但**不跟着尾货沉到列表底部**（仍按销量排序）。它的「需安排」就是客户电话报的量（公斤），输入框占位「按订单填写」并加绿色实线框，填完采纳即写入需安排（**不跳转**，行内只锁定输入框与按钮切「撤销」；要去拆单自己点顶部「采购下单」），与普通 SKU 一样按缸规则换算整缸、按染厂拆分订单；刷新 / 重新导入后与其他需安排一样按唯一标识保留。

SKU 弹窗切到「手动」时，模式下拉**默认落在「订单货模式」**（方案里没有订单货时回落到第一个手动模式），自定系数模式作为次选；两种手动模式在主面板「模式」列都只显示模式名本身（不带「手动」前缀，列宽已按 6 个汉字留足），模式筛选与悬停提示同样取 `modeLabel`。

两种行为各保留一个内置模式（配置页不能删），旧方案文件里缺失的内置模式由 `normalizeConfig` 自动补上，不升版本号。

旧版「排除模式」已删除（`behavior: exclude`，旧名 `slow` / 模式 id `manual-slow`）：加载旧方案时该模式整条丢弃，旧手动清单里指向它的 SKU 一并清除、回到自动策略。

`custom` 的内置名从「自定模式」改为「自定系数模式」（模式 id `manual-custom` 不变）：归一化时把旧内置名「自定模式」改写成「自定系数模式」，自定义名称同样保留。选择该模式的 SKU 在弹窗里人工填红线 / 正常 / 峰值（单位公斤），按库存公斤数比较。

## 7. 配置结构（v4）

```jsonc
{
  "version": 4,
  "activeProfileId": "production",
  "profiles": [{
    "id": "production",
    "name": "生产配置",
    "config": {
      "version": 4,
      "salesWindow": { "weights": { "m1": 0.5, "m3": 0.3, "m12": 0.2 } },
      "spuGrades": { "tiers": [
        { "key": "sPlus", "label": "S+", "minMonthlyAvg": 2500 },
        { "key": "s",     "label": "S",  "minMonthlyAvg": 300 },
        { "key": "a",     "label": "A",  "minMonthlyAvg": 100 },
        { "key": "b",     "label": "B",  "minMonthlyAvg": 30 },
        { "key": "c",     "label": "C",  "minMonthlyAvg": 1 },
        { "key": "z",     "label": "Z",  "minMonthlyAvg": null }
      ] },
      "displayFilters": { "lowPlanned": { "enabled": true, "minKg": 30 } },
      "strategies": [
        { "id": "auto", "behavior": "auto", "modes": [
          { "key": "hot",    "name": "热销", "range": { "from": 30, "to": null }, "metric": "days",
            "participates": true, "splitByCustomer": true,
            "coefficients": { "流通品": { "黑白": {"redLine":20,"normal":40,"peak":60},
                                          "彩色": {"redLine":15,"normal":30,"peak":45} },
                              "专属品": null } },
          { "key": "normal", "name": "常规", "range": { "from": 10, "to": 30 }, "metric": "days",  "...": "..." },
          { "key": "bulk",   "name": "按量", "range": { "from": 3, "to": 10 }, "metric": "stock",
            "healthScoring": { "ratio": { "normalFrom": 40, "normalTo": 60 },
                               "customers": { "normalFrom": 5, "normalTo": 10 } },
            "coefficients": { "流通品": { "黑白": {"redLine":40,"normal":80,"peak":200},
                                          "彩色": {"redLine":40,"normal":80,"peak":120} } } },
          { "key": "tail",   "name": "尾货", "range": { "from": 0.01, "to": 3 }, "metric": "none", "participates": false },
          { "key": "slow",   "name": "滞销", "range": { "from": 0, "to": 0.01 }, "metric": "none", "participates": false }
        ] },
        { "id": "manual", "behavior": "manual", "modes": [ /* 自定系数模式 / 订单货模式 */ ] }
      ]
    }
  }]
}
```

要点：

- 模式 key 固定为 `hot / normal / bulk / tail / slow`，顺序即优先级；归一化时按此顺序重建，缺失的补默认值。
- `metric`：`days`（比天数）/ `stock`（比库存公斤）/ `none`（不参与）。
- 系数按「客户类别 → 色彩 → 红/正/峰」分组；不分流的模式只有「流通品」一组。
- `healthScoring` 只存在于「按量」模式：SKU 弹窗里两项判定的阈值 —— `ratio`（本次进销比，`%`，`< normalFrom` 低风险、`normalFrom ~ normalTo` 正常、`> normalTo` 高风险）与 `customers`（累积客户数，`< normalFrom` 高风险、`normalFrom ~ normalTo` 中风险、`> normalTo` 低风险）。默认 `40 ~ 60` / `5 ~ 10`，在配置页「按量」模式的系数表下方直接编辑；老配置 / 老缓存缺这一段时由 `normalizeConfig` 补默认。
- `spuGrades` 是 SPU（品名）分级：固定 6 档、固定顺序（`sPlus / s / a / b / c / z`），只存名称与「月均条数下限」，末档 `z` 的 `minMonthlyAvg` 恒为 `null`（兜底收下低于上一档的 SPU），阈值必须从高到低严格递减。等级只按「该品名全部 SKU 的月均条数之和」判定、只用于主面板品名汇总行的模式列展示，不参与任何备货计算。新增该段不升版本号：老配置 / 老缓存缺 `spuGrades` 时由 `normalizeConfig` 补默认。
- `displayFilters.lowPlanned` 是主面板的**小额补货门槛**（`src/stocking/displayFilters.js`）：只作用于「紧急 / 常规」两个预警筛选按钮与紧急补货清单，判据是 `getSuggestedPlanned(row) < minKg`（补到正常库存即绿区中位的差额，已扣累计下单，与「需安排」格的占位建议同一口径）。`enabled: false` 或 `minKg` 为空时按不过滤处理；「全部」「正常」「超库存」以及表格数据、父行合计、采购清单与下单页都不受影响。它和 `spuGrades` 一样只影响展示、不参与备货计算，新增该段同样不升版本号，缺省即开启且门槛 30 公斤。
- **旧版本配置（v1 / v2 / v3）整份抛弃**：`normalizeConfig` 遇到非 v4 直接返回内置默认，不写迁移代码。

## 8. 校验规则

`validateConfig(config)` → `{ ok, errors, warnings }`（[validate.js](../../src/stocking/validate.js)）

**errors（阻断保存）**
- 模式名称为空 / 重复
- 阈值必须从热销到滞销严格递减
- 参与计算的模式：系数缺失、为负、或违反 `红线 ≤ 正常 ≤ 峰值`
- 按量模式健康度：本次进销比 / 累积客户数的正常区间下界大于上界
- 三档权重之和不等于 100%
- SPU 分级：等级名称重复，或阈值没有从高到低严格递减
- 手动模式名称重复、自定系数模式默认系数不完整 / 为负 / 顺序错

**warnings（提示不阻断）**
- 参与计算但比较方式为「不参与」

```
├─ engine.js        createEvaluator / evaluateItem / summarizeEvaluation / weightedMonthlySales / findBaselineMonth
├─ spuGrades.js     SPU（品名）分级：默认六档 / normalizeSpuGrades / validateSpuGrades / resolveSpuGrade
├─ scoring.js       健康度评分：createDefaultScoring / evaluateScoring / evaluateBulkScoring / resolveGrowthMonths（见第 12 节）

```

`createEvaluator(config, { manualOverrides, baselineMonth })` → `evaluate(item)`；
`evaluateItem(item, evaluator)` 返回的行新增：`modeKey / modeName / modeLabel / modeMetric / modeParticipates / stockingCoefficients / monthlySales / dailySales / exclusive / excluded / strategy / manualBehavior`。

## 12. 健康度评分（`scoring.js`）

需求 1.5.1。主面板「评分」列与 SKU 弹窗共用一套结果：口径只有 `src/stocking/scoring.js` 一份，输入因子由 `src/utils/skuHealth.js` 的 `buildScoringMetrics()` 拼装、`evaluateRowHealth()` 按模式分流。

### 12.1 六个维度（默认值，配置页可改）

| 维度 | 权重 | 低风险 | 中风险 | 高风险 | 因子来源 |
|---|---|---|---|---|---|
| 客户数 CR5 | 15% | ≤ 40% | 40% ~ 60% | ≥ 60% | 销售表 `customerCr5`（0~1 比例） |
| 累计客户数 | 10% | ≥ 21 个 | 11 ~ 20 个 | ≤ 10 个 | 主面板「累计客户」 |
| 销售环比率 | 20% | ≥ +10% | -10% ~ +10% | ≤ -10% | 1-12 月条数，按月规则见 12.2 |
| 本次进销比 | 30% | ≤ 20% | 20% ~ 30% | ≥ 30% | 建议补货(公斤) ÷ 累积销量(公斤) |
| 动销月份 | 10% | ≥ 6 个月 | 3 ~ 5 个月 | ≤ 2 个月 | 销售表「动销月份」（有出库的月份集合中最长连续段） |
| 预估月消耗 | 15% | < 0 | = 0 | > 0 | 加权月销量 −（理论库存 + 建议补货），均公斤 |

> 「动销月份」的 10% 是从「预估月消耗」里划出来的（原 25% → 15%），合计仍是 100%。老配置（5 维）由 `normalizeScoring()` 自动补这一维并从预估月消耗里扣 10%，不需要重新导入方案。
>
> 单位：预估月消耗的实测值、三档区间、弹窗小卡与 hover 浮层一律写 **公斤**（`SCORING_DIMENSIONS` 的 `unit`）；「条」只用于按条数定义的口径（月均条数、累积条数、SPU 分级下限）。
>
> 展示精度：弹窗与「评分」列的实测值 / 综合分一律取整（`formatValue()`、`totalText`），hover 浮层里的区间端点、环比两个月销量、进销比与预估月消耗的操作数也取整（减法用 `≈`）。`decimals` 只决定分档前的取整精度与配置页输入步长，不影响展示。

- 三档得分默认 40 / 60 / 80（`scoring.scores`）；权重合计必须 100%。
- 每个维度的三个区间各存 `from` / `to`，**两端都含**，留空表示不限（`-∞` / `+∞`）；端点重叠时按 **中 → 高 → 低** 取第一条命中，三条都没命中兜底中风险。
- 综合分 = Σ(得分 × 权重) ÷ 参与维度权重合计；缺失因子显示「无数据」且不参与加权。综合分区间 `scoring.total` 默认 < 50 红（高风险）、50 ~ 70 黄（中风险）、> 70 绿（低风险）。
- 本次进销比的方向是「越大越危险」：补货多而累积销量小才安全。
- 区间 / 权重 / 三档得分 / 综合分区间都存在方案的 `scoring` 段，入口「设置 → 备货配置 → 评分 → 编辑评分规则」（`src/components/ScoringSettings.vue`：摘要 + 编辑弹窗），SKU 弹窗只读。

### 12.2 销售环比率的取月规则

- 严格按**打开系统时的日期**：≥ 26 号取「本月 vs 上月」，≤ 25 号取「上月 vs 前月」（`resolveGrowthMonths()`）；与销售表基准月无关，基准月只用于加权月销量。
- 1 月跨年时去年 12 月 / 11 月的数据不在本年 1-12 月里，按无数据处理；卡片悬停提示写明比的是哪两个月（含两边销量）或缺哪个月。
- 上期为 0、本期有销量记 +100%；本期为 0、上期有销量记 −100%（落高风险）；两期都为 0 按无数据。

### 12.3 按量模式的专属判定

按量（`modeKey === 'bulk'`）走 `evaluateBulkScoring()`：只判 2 项、**不做综合评分**。

| 项 | 低风险 | 正常 | 高风险 |
|---|---|---|---|
| 本次进销比 | < 40% | 40% ~ 60% | > 60% |
| 累积客户数 | > 10 个 | 5 ~ 10 个 | < 5 个 |

两项阈值存在方案的按量模式 `healthScoring` 段（`ratio` / `customers` 各一组 `normalFrom` / `normalTo`），入口「设置 → 备货配置 → 模式与系数 → 按量 → 系数表下方 → 健康度判定」。改动只影响弹窗与「评分」列展示，不参与备货计算。

### 12.4 展示与不参与

- 主面板「评分」列只显示综合分（红 / 黄 / 绿底色，悬停给出分数与风险档）；逐维度明细只在 SKU 弹窗。
- 专属品、尾货、滞销、订单货、模式缺省一律「不参与」（由 `strategyAvailable` / `excluded` 决定）；按量模式没有综合分，列里显示「—」。
- 展示位置与弹窗结构见 [前端视图与交互.md](./前端视图与交互.md) 第 4 节。

### 12.5 本次补货风险（以「中」为基准的净偏离合计）

SKU 弹窗把「需安排」与「本次补货风险」收进同一个「补货风险提示」面板：卡顶给低 / 中 / 高结论，下面一排四张等高卡（需安排 + 三个因子），回答「按这个数补，风险多大」。三个因子各自落「低 / 中 / 高」档，以「中」为 0 点算净偏离：**高 +1、中 0、低 −1**，三项相加后 **> 0 高风险、= 0 中风险、< 0 低风险**。不设权重、不设特例，结论能拿三张因子卡自己复核。

| 因子 | 口径 | 取哪份实现 |
|---|---|---|
| 日库销比（补货后） | 把补货量当成已采纳重算一行，再取预警灯 | `calculateInventoryRow()` 的 `urgencyTone`，与主面板「日库销比」列同一条 |
| 补货进销比 | 补货量 ÷ 累积销量 × 100 | 与评分因子同一个 `ratio` 区间（`matchScoringTier()`），只把分子从建议值换成补货量 |
| 综合评分 | 现有综合分档位 | `evaluateRowHealth()`；按量模式没有综合分，取两项判定里更差的一项（卡面叫「按量健康度」，只显示较差项的数值，hover 里列两项） |

**各自落档**：日库销比分四态 —— 正常带（绿「无需补货」）→ 低、偏离（黄「常规补货」）→ 中、偏多（紫「降低库存」）与偏少（红「紧急补货」）→ 高；另两项按各自区间落低 / 中 / 高。偏多与偏少同为高（+1），方向只影响句子与动作 —— 偏多要下调、偏少要上调。

**计分与门槛**（`REPLENISH_TIER_DEVIATION` / `REPLENISH_RISK_THRESHOLDS`）：高 +1、中 0、低 −1；合计 **≥ 1 高风险、= 0 中风险、≤ −1 低风险**。

三个指标各三档，顺序无关共 **10 种组合**，全表如下（`REPLENISH_RISK_LEVELS` 定档位名与配色）：

| 组合 | 合计 | 结论 |
|---|---|---|
| 高 + 高 + 高 | +3 | 高风险 |
| 高 + 高 + 中 | +2 | 高风险 |
| 高 + 高 + 低 | +1 | 高风险 |
| 高 + 中 + 中 | +1 | 高风险 |
| 高 + 中 + 低 | 0 | 中风险 |
| 中 + 中 + 中 | 0 | 中风险 |
| 中 + 中 + 低 | −1 | 低风险 |
| 高 + 低 + 低 | −1 | 低风险 |
| 中 + 低 + 低 | −2 | 低风险 |
| 低 + 低 + 低 | −3 | 低风险 |

- 一句话记法：**比「中」多的部分与比「中」少的部分相抵，剩哪边就是哪档。**
- 对称的代价（已知取舍）：库存天数偏多 / 偏少只值 +1，可能被另外两项的 −1 抵掉（「偏多 + 两项都低」= −1 → 低风险）。若要「库存天数定下限」，在 `evaluateReplenishRisk()` 定档后对 level 取更严的一档即可，其余不动。
- 缺项也算得通：没有累积销量时只剩两项（`高 + 低 = 0` → 中风险、`中 + 低 = −1` → 低风险），不需要任何特例。
- 卡面上只出低 / 中 / 高三个字；hover 里给一张**计分表**：三行「因子 / 档位 / 分」（如 `日库销比 高 · 偏多 +1`、`补货进销比 高 +1`、`综合评分 低 −1`）+ 末行「合计 +1 分 → 高风险」，表下一句规则「高 +1，中 0，低 −1；三项相加 > 0 高风险，= 0 中风险，< 0 低风险」；因子卡 hover 的档位标签带「· +1 分」。
- 档位名与配色由 `REPLENISH_RISK_LEVELS` 定（低绿 / 中黄 / 高红）；不参与计算的场景固定显示「不参与」。
- 「中风险」是真实结论档：`高 + 中 + 低`、`中 + 中 + 中` 都落在这一档。
- 动作句只在需要改量时出现、写在结论 hover 里：偏多「降到 X 公斤」、偏少「补到 X 公斤」（结论已是高风险时改为「先小批试补，别一次补到建议值」）、偏离「对齐 X 公斤」、正常带但结论高风险「分批下单或缩量」。X 即 `getSuggestedPlanned()`。
- 面板结构（高度不随输入变化）：头部只有「盾牌图标 + 补货风险提示」；下面一排四张等高卡，按「日库销比 → 补货进销比 → 综合评分」排（顺序就是 `factors` 的输出顺序：先看结果、再看这次下的注、最后看底子）。第一张是「需安排」卡：卡顶是结论（圆勾 / 感叹号 + 低 / 中 / 高，依据与动作在 hover），下面一行是「需安排 + 输入框（公斤在框外）+ 采纳建议 / 撤销」；卡底色、左侧 3px 色条与描边跟着结论档位走（绿 / 黄 / 红 / 灰）。后三张因子卡只排两行：「标签」与「数值（单位小一号）+ 圆点档位」。四张卡等高、宽度固定，输入数字只换数值、档位与整块的色相，不会让面板跳高度或换行。
- 已采纳后整块底色仍随风险档位，只把输入框压成只读态并显示锁图标，卡顶加「已采纳」徽标、按钮换成「撤销」，其余卡不变。
- 判定句、动作句、计分表与规则句放结论 hover，计算式与判定区间放各因子卡 hover。没有因子时（专属品 / 订单货 / 无建议值）面板只留「需安排」这一张卡；没有输入卡（只读场景）时结论挪到面板头部右侧。
- 专属品 / 尾货 / 滞销 / 订单货 / 模式缺省一律「不参与」，不出结论（徽标灰、hover 说明原因）；缺累积销量时「补货进销比」那一项直接不出现，也不计分。
- 实现：`src/stocking/replenishRisk.js` 的 `REPLENISH_TIER_DEVIATION`（档位 → 净偏离）与 `REPLENISH_RISK_THRESHOLDS`（高 / 低门槛）是唯一来源，`REPLENISH_RISK_RULE_TEXT` 是 hover 里那句话的唯一文案；`REPLENISH_RISK_LEVELS` 管档位名与配色。弹窗只读，不参与备货计算，也不影响「评分」列。

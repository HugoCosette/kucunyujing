# 离线打包说明（Windows 桌面版）

把同一份纯前端代码装成 Windows 桌面程序，供**内网 / 无网络单机**使用，数据仍然只存在本机浏览器存储（IndexedDB + localStorage）里，不接任何后端。线上 GitHub Pages 部署与桌面版是两条互不影响的构建路径。

## 1. 命令一览

| 目的 | 命令 | 产物 | 本机实测 |
| --- | --- | --- | --- |
| 桌面开发（改代码即热更新） | `npm run desktop:dev` | Electron 窗口加载 Vite 开发服务器 | 启动约 3 秒 |
| 只出桌面前端 | `npm run build:desktop` | `dist-desktop/`（约 4.3 MB） | 2 秒 |
| 前端更新包 | `npm run web-update` | `release/web-update.zip`（约 0.83 MB） | 3 秒 |
| 免安装目录版 | `npm run pack:win:dir` | `release/win-unpacked/`（约 314 MB） | 20 秒（二进制已缓存） |
| 安装包（NSIS） | `npm run pack:win` | `release/kucunyujing-<版本>-setup.exe`（约 108 MB） | 首次约 105 秒（含下载 NSIS），之后约 45 秒 |
| 线上构建（不受影响） | `npm run build` | `dist/`，`base` 仍是 `/kucunyujing/` | 2 秒 |

- 耗时主要花在 Electron 运行时的下载与压缩上，**与代码量无关**：前端只有 4 MB，改一次代码重新出包也就是 1 分钟。

## 2. 与线上部署的隔离（别改成无条件生效）

| | 线上（GitHub Pages） | 桌面离线版 |
| --- | --- | --- |
| 构建模式 | `vite build`（`mode=production`） | `vite build --mode desktop` |
| 资源前缀 `base` | `/kucunyujing/` | `./` |
| 路由 | `createWebHistory` + `dist/404.html` 兜底深链 | `createWebHashHistory`，不依赖服务端 |
| 产物目录 | `dist/` | `dist-desktop/`（已 gitignore） |
| 页面 origin | `https://<user>.github.io` | `app://kucunyujing`（固定） |

开关只有两处：

- [vite.config.js](../vite.config.js)：`mode === 'desktop'` 时 `base` 与 `outDir` 换分支；
- [src/router/index.js](../src/router/index.js)：`import.meta.env.MODE === 'desktop'` 时用 hash 历史。

`npm run build` 走的仍是原来的分支，URL、深链、`404.html` 兜底都不变，所以推 `main` 的 Pages 工作流不需要任何改动。

## 3. 首次准备

```powershell
npm install

# 国内网络下 `npx electron .` 会长时间卡在 “Downloading Electron binary...”，
# 用镜像手动装一次（之后走缓存，只做一次）：
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
node node_modules/electron/install.js

# 打包时 electron-builder 还要下 NSIS / winCodeSign，同样给镜像：
$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'
```

镜像只作为临时环境变量使用，**不要写进 `.npmrc`** —— 线上构建只用 Vite，不需要这两个包；CI（[deploy-pages.yml](../.github/workflows/deploy-pages.yml)）已通过 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 跳过 Electron 二进制下载，推 `main` 不会因此变慢。

## 4. 桌面开发：改代码不用打包

```powershell
npm run desktop:dev
```

脚本（[electron/dev.mjs](../electron/dev.mjs)）用 Vite 的 API 起开发服务器，再把实际地址通过 `VITE_DEV_SERVER_URL` 交给 Electron；端口被占用时 Vite 自动换端口，Electron 跟着换，不会撞车。改 `.vue` / `.js` 保存即热更新，和浏览器里一样。

- 需要调试主进程或看控制台：`$env:ELECTRON_DEVTOOLS='1'; npm run desktop:dev`（打开独立 DevTools 窗口）。
- 透传 Electron 参数：`npm run desktop:dev -- --remote-debugging-port=9335`。
- 不会额外弹系统浏览器；关掉 Electron 窗口时脚本会一并关掉开发服务器。

## 5. 打包

```powershell
npm run pack:win       # 安装包：可选安装目录、写注册表、建快捷方式
npm run pack:win:dir   # 免安装目录：release\win-unpacked\备货决策系统.exe 直接双击
```

产物结构（重点：前端在 asar **外面**）：

```
release/win-unpacked/
├─ 备货决策系统.exe
└─ resources/
   ├─ app.asar        # 只有 electron/main.cjs + package.json，约 10 KB
   └─ web/            # dist-desktop 的副本：热更新替换的就是这里
      ├─ index.html
      ├─ favicon.ico
      └─ assets/...
```

- asar 里**不含** `node_modules`（`electron-builder.json` 的 `!node_modules/**/*`）：页面依赖都已打进 `web/`，主进程只用 Electron 内置模块，所以 `npm run pack:*` 不需要处理原生依赖。
- 安装包是按用户安装（`perMachine: false`），默认装到 `%LOCALAPPDATA%\Programs\备货决策系统`，不需要管理员权限。
- 没有代码签名证书，Windows 会弹 SmartScreen 提示：内网自用点「更多信息 → 仍要运行」；对外分发需要购买证书并配置 `CSC_LINK`。
- 图标目前是 Electron 默认图标。要换：放一个 256×256 的 `build/icon.ico`，在 [electron-builder.json](../electron-builder.json) 的 `win` 下加 `"icon": "build/icon.ico"`。

## 6. 前端热更新：不重装、不丢数据

```powershell
npm run web-update     # 生成 release/web-update.zip
```

交付给使用者：**关闭程序 → 把 zip 解压覆盖到 `<安装目录>\resources\web\` → 重新打开**。

- 适用：`.vue` / `.js` / 样式 / 清洗引擎 / `tools/cleaning/cache/*.json` 等任何打进前端的改动。
- 数据为什么不会丢：页面 origin 恒为 `app://kucunyujing`，IndexedDB 与 localStorage 都按 origin 存放，替换的是静态文件不是存储。这个流程已在打包版上实测：覆盖 `resources/web` 后重开，`localStorage` 与 IndexedDB 里的标记值都还在，导航、`#/config` 路由、module Worker、静态 JSON 全部正常。
- 必须重新出安装包的情况：改 `electron/main.cjs`（主进程）、图标、`productName` / `appId` / 版本号。

## 7. 数据位置与备份

- IndexedDB / localStorage 都在 `%APPDATA%\备货决策系统\`（按 `productName` 取名；开发态 `npm run desktop:dev` 用的是 `%APPDATA%\kucunyujingdemo\`，两者数据独立）。
- 覆盖安装、替换 `resources/web`、卸载（未开启 `deleteAppDataOnUninstall`）都不会删这个目录。
- 备份 = 复制整个目录；或在应用内「设置 → 数据 → 本机数据存储」导出。
- 桌面版与网页版数据互不同步（origin 不同），迁移走「导出全部数据 → 另一侧导入」。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 双击 `dist-desktop/index.html` 白屏 | `file://` 下没有 IndexedDB，module Worker / fetch 也会失败 | 必须用 `app://` 外壳（本仓库自带）。桌面版永远不要退回 `loadFile` / `file://` |
| 首次 `npx electron .` 长时间停在 “Downloading Electron binary...” | Electron 二进制没下载成功 | 按 §3 用镜像跑 `node node_modules/electron/install.js` |
| 打包报 `EPERM ... rename release\win-unpacked` | 程序还在运行，或资源管理器占着目录 | 关掉程序 / 关掉该目录窗口后重跑；脚本会重试并回退到复制 |
| 覆盖 `resources/web` 后没生效 | 还在跑旧进程，或解压层级多了一层目录 | 确认 `resources\web\index.html` 直接存在，然后重启程序 |
| `npm run pack:win:dir` 后双击没反应 | 杀毒软件拦截未签名 exe | 加白名单；内网统一部署时提前下发 |
| 端口 5173 被占 | 已有 `npm run dev` 在跑 | 无需处理，`desktop:dev` 自动换端口 |

## 9. 手验清单

改打包相关文件后按此顺序验证（已全部通过）：

1. `npm run build` → `dist/index.html` 里资源仍是 `/kucunyujing/...`（线上不受影响）。
2. `npm run build:desktop` → `dist-desktop/index.html` 里是 `./assets/...`。
3. `npm run pack:win:dir` → 启动 `release\win-unpacked\备货决策系统.exe`：窗口 origin 为 `app://kucunyujing`；左侧导航「需求表 / 采购下单 / 销售表 / 配置板块 / 屏蔽列表」齐全；`#/config` 能切到配置页。
4. 页面内 `new Worker(..., { type: 'module' })` 可加载（清洗 Worker 依赖它）；`fetch` 打包内的 `rates-*.json` 成功。
5. 关闭再打开：localStorage 与 IndexedDB 数据仍在。
6. `npm run web-update` → 解压覆盖 `resources/web` → 再打开：数据仍在、页面正常。
7. `npm run pack:win` → 安装包能生成；在**干净机器**上装一次确认快捷方式与卸载正常（本机为避免留下桌面快捷方式未执行）。

## 10. 明确不做的事

- **不做在线自动更新**：`electron-updater` 需要一个放 `latest.yml` 的地址，与「离线」目标冲突。将来若有内网共享盘，可在此基础上加「检查更新」按钮。
- **不把数据改存成文件 / SQLite**：桌面版仍与网页版同一套存储口径，避免出现两份数据模型。
- **不影响线上构建**：打包只加构建分支与 Electron 外壳，`src/` 里的业务口径、清洗、评分、缸规则一行不动。

# 采购下单流程（功能说明）

> 一句话：**主面板把「需安排」定准（公斤、到个位）→ 进「本次采购清单」→ 采购下单页按品名（SPU）的缸规则折算整缸 → 按染厂拆成多张分订单 → 以唯一标识落盘 → 导出对账。**
> 原则：**缸只在「下单」环节出现**，不用来改备货建议值；分订单以「唯一标识」为键，重新导入不丢。

---

## 1. 一图看懂

```
主面板 /（InventoryPanelView）
  ├─ 单行填写「需安排」→ 采纳（锁定，可撤销）
  ├─ 批量补货：勾选 SKU → 浮动条 → 确认补货（覆盖）
  └─ 紧急补货：红区 SKU → 填新增量（追加）
              │
              ▼  applyRestockPlans()  ← 唯一写入路径（同一 SKU 只留一条）
     需安排(planned) = 精准公斤数
     本次采购清单 purchaseList（内存）
              │
              ├─ 导出 Excel（本次采购清单 + 分单明细，带缸数 / 每缸公斤）
              └─ 去下单 ─────────────┐
                                     ▼
采购下单 /purchase（PurchaseOrderView）
  左：待下单 SKU（筛选 + 只看未下单）
  右：SkuOrderEditor（同一组件也用于主面板弹窗）
      ├─ 按品名缸规则算出「建议 N 缸 × 每缸 X 公斤 ＝ Y 公斤」
      ├─ 缸数 ⇄ 数量（公斤）双向联动
      └─ 按染厂拆多张分订单（染厂 / 分单人员 / 缸数 / 数量 / 备注）
              │
              ▼  purchaseStore.setOrderEntries(skuId, entries)
     orders.json / localStorage（键 = 唯一标识，防抖 400ms 落盘）
```

## 3. 全流程分步

### 3.1 生成「需安排」（主面板，公斤、精准到个位）

| 方式 | 入口 | 数值来源 | 写入口径 |
| --- | --- | --- | --- |
| 单行填写 | 表格「需安排」列输入框 → `采纳` | 人工填写，占位提示给建议值 | **覆盖**该行 |
| 批量补货 | 勾选行（首列复选框 / 点整行 / 品名父行整组）→ 底部浮动条「确认补货」 | `getSuggestedPlanned(row)` | **覆盖**「需安排」 |
| 紧急补货 | 工具栏「紧急补货 N」→ 填「新增计划」 | `ceil(正常库存 − 预计库存)` | 在现有需安排上**追加**（调用处先换算成绝对值） |

- 建议值口径（唯一一份在 [`utils/inventory.js`](../../src/utils/inventory.js) 的 `getSuggestedPlanned`）：`max(0, ceil(正常库存 × 80% − 理论库存))`，即「补到绿色带中位」。
- **订单货**（手动策略 `behavior: 'order'`）不给建议值，占位显示「按订单填写」，按客户报量人工填；它不参与预警与评分。
- 模式缺省 / 不参与备货的 SKU 建议值为 0，需人工决定。
- 这里的数字**一律是精准公斤**，不做缸取整；占位提示会写明「下单页会再按缸规则建议整缸数量」。

### 3.2 采纳「需安排」（唯一写入路径）

```
行内「采纳」 ──┐
批量「确认补货」┼─→ applyRestockPlans(plans)
紧急「确认提交」┘        │
                         ├─ 写入 item.planned（覆盖）
                         ├─ 记 plannedUndoHistory（旧值 + 旧清单行，供撤销）
                         └─ 同步 purchaseList（同一 SKU 只保留一条）
```

- `applyRestockPlans` 只接受 `planned > 0` 的行；返回实际写入行数，主面板提示「已加入本次采购清单：N 个 SKU」。
- 采纳后该行「需安排」被锁定（输入框禁用 + 锁图标），点「撤销」恢复原值与原清单行。
- 清单条目结构：`{ id, skuId, product, color, planned }`，`id` 会随导入重排，**跨导入只认 `skuId`（唯一标识）**。

### 3.3 本次采购清单（主面板弹窗）

- 列：品名 / 颜色 / 树形分类 / 需安排 / 已下单（分单张数）/ 操作「去下单」。
- 空清单提示「暂无已采纳的采购计划」；工具栏按钮带条数角标，确认补货后会有脉冲高亮。
- 底部：「进入采购下单页 →」/「关闭」/「导出 Excel」。

### 3.4 采购下单页（按染厂拆单）

- 顶部统计：待下单 SKU / 需安排合计 / 已下单合计 / **合计缸数** / 还没下单。
- 左列表：品名 · 颜色、树形分类、「每缸 X 公斤」（X 是命中档的规则参数：`vat` 是每缸公斤，`round` 是取整步长）、需安排 / 已下单（张数 · 缸数）；支持关键词筛选与「只看未下单」。选中行随筛选自动回落到第一行。
- 右侧编辑器（[`SkuOrderEditor.vue`](../../src/components/SkuOrderEditor.vue)）：
  - 指标条：需安排 / 已下单 / 合计缸数；「N 张非整缸」告警；右侧灰字显示当前缸规则（悬停看命中区间与建议）。
  - 表格列：`#` / 染厂 / 分单人员 / **缸数** / 数量（公斤）/ 备注（缸号 / 交期）/ 删除。
  - 行表尾：合计缸数、合计公斤、与需安排的差额（一致 / 还差 / 超出）。
  - 空状态两个按钮：「＋ 添加分订单」「按建议添加（Y 公斤）」——后者直接用缸规则算出的整缸量落成第一张分订单。
  - 「清空分订单」需二次确认。
- 主面板「去下单」弹窗（`SkuOrderDialog`）复用同一个编辑器，标题 `采购下单 · 品名 颜色`，按钮「保存分订单」；两处行为一致，不要各写一份。

### 3.5 分订单落盘

| 项目 | 说明 |
| --- | --- |
| 键 | **唯一标识**（`orders[skuId] = entries[]`），不是清单 `id` |
| 单条结构 | `{ id, factoryId, factoryName, assignee, quantity, vatCount, kgPerVat, note }` |
| 缸快照 | `vatCount` / `kgPerVat` 记录下单当时的缸数与每缸公斤，导出与对账用；老数据可为 `null` |
| 写入 | `purchaseStore.setOrderEntries(skuId, entries)` → `normalizeOrders(..., { keepBlankEntries: true })` → 防抖 400ms 落盘；`pagehide` 时 flush |
| 空白行 | 运行时保留（刚点「添加分订单」的行不会被归一化掉），**落盘 / 加载 / 导出时丢弃** |
| 清空 | `clearOrderEntries(skuId)` 删掉该 SKU 的记录 |

### 3.6 导出与对账（主面板「本次采购清单 → 导出 Excel」）

文件名 `本次采购清单-{时间戳}.xlsx`，两个工作表：

| 工作表 | 列 |
| --- | --- |
| 本次采购清单 | 品名、颜色、树形分类、需安排、**缸数**、**每缸公斤**、建议下单、已下单、分单数量 |
| 分单明细（有分单时才出现） | 品名、颜色、树形分类、染厂、分单人员、**缸数**、**每缸公斤**、数量（公斤）、备注 |

- 「缸数 / 每缸公斤 / 建议下单」由导出行现算（需安排 × 品名绑定的缸规则），落盘的 `vatCount` / `kgPerVat` 用于分单明细。
- 界面上的清单**不显示**缸数列；缸数建议只出现在下单环节与导出文件里。

## 4. 缸规则（只在下单环节生效）

### 4.1 数据模型（`src/purchase/settings.json`，设置版本 v3）

```jsonc
{
  "vatRules": [
    {
      "id": "vr-standard",
      "name": "标准大货补单",
      "bandKey": "planned",              // planned | skuMonthlyAvg | spuMonthlyAvg
      "remainder": "nearest",            // nearest | floor | ceil
      "remainderThreshold": 0.5,         // nearest：余量 ≥ 50% 一缸 → 补一缸
      "minVats": 1,                      // 需求 > 0 时至少几缸
      "bands": [                         // 从低到高，最后一档必须无上限
        { "upTo": 30,  "action": "skip",  "value": 0 },
        { "upTo": 120, "action": "fixed", "value": 80 },
        { "upTo": 200, "action": "fixed", "value": 200 },
        { "upTo": null, "action": "round", "value": 100 }
      ]
    }
  ],
  "defaultVatRuleId": "vr-standard",     // 未绑定的品名用它
  "spuVatRules": { "品名A": "vr-small" }, // 品名（SPU）绑定，SKU 全部沿用
  "skuVatRules": {}                      // 例外：单个 SKU 覆盖；"__none__" = 不取整
}
```

### 4.2 判定与换算

```
规则继承：skuVatRules[skuId] → spuVatRules[品名] → defaultVatRuleId（缺失时取第一条规则）→ 没有规则才按公斤精确下单
命中分档：按判据取指标，从低到高取第一条「上限为空 或 指标 < 上限」的档（30 属于「30 至不足 120」）
换算动作：
  skip  → 0 公斤（不下单）
  fixed → 固定下单量（视为 1 缸）
  vat   → 缸数 = 需安排 ÷ 每缸公斤，再按零头策略取整；下单量 = 缸数 × 每缸公斤
  round → 同 vat，但每缸公斤 = 取整步长（10 = 整十，100 = 整百）
零头策略：nearest（默认，余量 ≥ 阈值补一缸）/ floor（只下整缸）/ ceil（不足一缸也下一缸）
下限保护：需求 > 0 时缸数至少为 minVats（默认 1 缸）
```

- 入口函数：`planOrderQuantity(need, rule, context)`，返回 `{ action, bandText, kgPerVat, rawVats, vatCount, rounded, remainderKg, deltaKg, deltaRate, warnings }`。
- 规则解析：`resolveVatRule(settings, { skuId, product })`；分档查询：`resolveVatBand(rule, context)`。
- 规则文案：`describeVatBands(rule)` / `summarizeVatRule(rule)` / `describeVatRemainder(rule)`。

### 4.3 默认两条规则（与参考系统的「下单数量规则」同构）

| 规则 | 区间与动作 |
| --- | --- |
| 标准大货补单 | 低于 30 不下单 · 30 至不足 120 固定 80 公斤 · 120 至不足 200 固定 200 公斤 · 200 及以上四舍五入到整百 |
| 小批量补单 | 低于 50 不下单 · 50 至不足 100 固定 60 公斤 · 100 及以上四舍五入到整十 |

### 4.4 换算示例（默认「标准大货补单」）

| 需安排（公斤） | 命中档 | 结果 | 说明 |
| --- | --- | --- | --- |
| 20 | 低于 30 | 0 公斤 | 规则判定不补，下单页会提示 |
| 50 | 30–<120 | 80 公斤（1 缸） | 固定量 |
| 150 | 120–<200 | 200 公斤（1 缸） | 固定量 |
| 240 | ≥200 | 200 公斤（2 × 100） | 余量 40 < 半缸，舍弃 |
| 250 | ≥200 | 300 公斤（3 × 100） | 余量 50 ≥ 半缸，补一缸 |
| 3371 | ≥200 | 3400 公斤（34 × 100） | 余量 71 ≥ 50，补一缸；与需安排差 +29 |

> 文案差异：`vat` 才叫「每缸 X 公斤」；`round` 显示「按 X 公斤取整」，`fixed` 显示「固定 X 公斤/单」——避免把「34 × 100 取整」误读成 34 个缸。

### 4.5 与备货口径的边界（重要）

- 主面板「需安排」、批量 / 紧急补货的建议值 **永远是精准公斤数**，不取整缸。
- 缸规则只作用于：采购下单页（左侧列表的规则参数、右上建议缸数、缸数⇄公斤联动）与清单导出文件里的缸数列。
- 改缸规则**不会**回溯已保存的分订单；已落盘的 `vatCount` / `kgPerVat` 是快照。

## 5. 下单设置（`/purchase/settings`）

页面用**草稿**编辑，顶部「确定」才落盘，「放弃」丢弃改动；`有未保存的修改` 状态由设置快照对比得出。点击「确定」前会校验缸规则（区间无缝、末档无上限、参数大于 0 等）。

| 分区 | 作用 |
| --- | --- |
| 缸规则 | 规则列表（区间与动作 / 生效品名数 / 默认标记）、新增 / 编辑 / 删除 / 设为默认 / 恢复默认两条；编辑弹窗含判据、零头策略、至少几缸、只填上限的链式区间、新增阈值与即时试算 |
| 品名绑定 | 搜索品名 → 逐个下拉绑定（默认 / 具体规则 / 不取整）；支持按筛选结果批量套用、清空筛选结果 |
| 染厂清单 | 分订单染厂下拉的来源；停用的染厂不出现在下拉里，但已有分订单保留原厂名；可从 Excel 导入「染厂名称」列 |
| 分单人员表 | 下单可选的员工总名单（增删人员，删除时同步清掉各分类里的同名分配） |
| 树形分类与分单人员 | 一个 SKU 只属于一个分类；先建分类，再勾选该分类的分单人员；可从产品资料导入「树形分类」列 |
| SKU 可选染厂 | 单个 SKU 限定可选染厂；未配置 = 全部启用染厂；可覆盖树形分类 |

顶部还有「导入设置文件 / 导出设置文件」（`purchaseSettings.json`，含缸规则）。

## 6. 分订单的选项口径（`resolve.js`，页面不要各写一份）

| 函数 | 口径 |
| --- | --- |
| `factoriesForSku(settings, skuId)` | 该 SKU 配了可选染厂 → 只列这些（未启用的剔除）；没配或配的都被停用 → 回退全部启用染厂 |
| `categoryForSku(settings, skuId, importedCategory)` | 人工覆盖（`skuCategoryOverrides`）优先，其次导入行自带分类 |
| `assigneesForCategory(settings, category)` | 该分类勾选的人员 |
| `assigneesForSku(settings, skuId, importedCategory)` | 分类有人 → 只列分类人员；分类没配人 → 回退分单人员表全部人员 |
| `summarizeOrders(entries)` | 分订单合计 `{ total（公斤）, counted（张数）, vats（缸数） }`，只统计 `quantity > 0` 的行 |
| `findFactoryById / findFactoryByName` | 染厂临时手输时回填 `{ factoryId, factoryName }`；手输的新厂名只用于本次下单，不写回设置 |

## 7. 数据与持久化

| 数据 | 存放 | 刷新后 | 备注 |
| --- | --- | --- | --- |
| 下单设置（含缸规则） | `src/purchase/settings.json` + localStorage `purchase-settings:v1` | ✅ | 开发态写 `settings.json`（端点 `/__purchase-settings/save`），构建产物只写 localStorage |
| 分订单 | `src/purchase/orders.json` + localStorage `purchase-orders:v1` | ✅ | 开发态写 `orders.json`（端点 `/__purchase-orders/save`）；超 5 MB 会写缓存失败（控制台 warn） |
| 需安排（`planned`） | Pinia 内存（库存行上） | ❌ | 重新导入即重置 |
| 本次采购清单（`purchaseList`） | Pinia 内存 | ❌ | 重新导入 / 刷新后清空；分订单不受影响 |
| 撤销快照（`plannedUndoHistory`） | Pinia 内存 | ❌ | 刷新后不能撤销 |

> 也就是说：**「这次要采购哪些 SKU」是临时清单，真正长期保留的是每个 SKU 的分订单**（按唯一标识）。要留痕请用「导出 Excel」。

## 8. 关键不变量（改代码前先看）

1. 需安排**只**通过 `applyRestockPlans`（批量 / 紧急）或行内「采纳」写入，不要另开写入口。
2. 分订单**只**以唯一标识为键；不要用 `purchaseList.id`（导入会重排）。
3. 缸规则**只**在 `src/purchase/vat.js` 实现；页面拿到 `planOrderQuantity` 的结果直接用，不要自己再算一遍。
4. 主面板不取整缸；缸只出现在下单环节与导出。
5. 主面板表格里只有「需安排」可编辑；品名 / 颜色 / 生产中 / 欠货 / 周消耗 / 周转入 / 在途 / 在仓都是导入值，只读。
6. 分订单编辑器只有一份（`SkuOrderEditor.vue`），主面板弹窗与 `/purchase` 共用。
7. 设置是草稿编辑，未点「确定」不落盘；缸规则在保存前会整体校验。
8. 空白分订单行运行时保留、落盘丢弃（`keepBlankEntries`），别再改成统一丢弃。
9. 示例数据区（`/example`、`/example/config`）不参与这套流程，也不要改。
10. 规则判定是「上限递增、末档无上限」；改分档时只改上限，文案会跟着重算。

## 9. 常见操作

| 想做的事 | 怎么做 |
| --- | --- |
| 把「每缸」改成真实缸容（如 240 公斤） | 下单设置 → 缸规则 → 编辑规则：判据选「SKU 月均条数」或保持「需安排」，处理方式选「按每缸公斤取整」，参数填 240 |
| 某个品名不按缸取整 | 下单设置 → 品名绑定 → 该品名选「不取整（按原样下单）」 |
| 只让个别小批量品名走小批量规则 | 品名绑定里逐个选「小批量补单」，或搜索后批量套用 |
| 某个 SKU 单独例外 | 目前界面只到品名级；SKU 级可通过 `skuVatRules`（设置文件）配置，值填规则 id 或 `__none__` |
| 看某条规则会影响多少品名 | 规则表「生效品名」列；改默认规则前先看「默认」标记 |
| 撤销刚采纳的需安排 | 主面板该行点「撤销」（仅未刷新时有效） |
| 交给染厂下单 | 主面板「本次采购清单 → 导出 Excel」，分单明细带染厂、人员、缸数、数量、备注 |
| 清空某 SKU 的分订单 | `/purchase` 右侧「清空分订单」（二次确认） |

---

## 10. 已知边界

- 采购清单与需安排是内存态：刷新 / 重新导入后需要重新勾选补货；分订单不会丢。
- 分订单数量不做「跨染厂整缸校验」：各分订单分别按缸数录入，合计可以略高于需安排（取整差额），界面会显示差额。
- 同行备注里的缸号是自由文本，系统不解析、不校验唯一性。
- 分订单落盘是**按 SKU 覆盖**的快照，没有时间线与状态流转；需要「完整订单流水」时按 [数据持久化方案](./数据持久化方案.md) 再演进。

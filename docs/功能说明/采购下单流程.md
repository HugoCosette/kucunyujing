# 采购下单流程（功能说明）

> 一句话：**主面板把「需安排」定准（公斤、到个位，采纳即锁定）→ 该锁定数传到采购下单页，按品名（SPU）的缸规则折算整缸、按染厂拆成多张分订单 → 点「确认下单」后成为「订单」，回写主面板「备货」列的「已下单」→ 逐单登记到货进「已到货」→ 撤销可回退需安排 → 导出对账。**
> 原则：**缸只在「下单」环节出现**，不用来改备货建议值；订单只追加、不物理删除，以「唯一标识」为键，重新导入不丢；**需安排与预警的判定规则一字不改**，只是「预计库存」里多算了已下单的量。

## 1. 一图看懂

```
主面板 /（InventoryPanelView）
  ├─ 单行填写「需安排」→ 采纳（锁定，可撤销）
  ├─ 批量补货：勾选 SKU → 浮动条 → 确认补货（覆盖）
  └─ 紧急补货：红区 SKU → 填新增量（追加）
              │
              ▼  applyRestockPlans()  ← 唯一写入路径（同一 SKU 只留一条）
     需安排(planned) = 精准公斤数，锁定态
     本次采购清单 purchaseList（内存）
              │
              ├─ 导出 Excel（本次采购清单 + 分单明细，带缸数 / 每缸公斤）
              └─ 去下单 ─────────────┐
                                     ▼
采购下单 /purchase（PurchaseOrderView）     ← 锁定数就是这里每个 SKU 的「需安排」
  左：待下单 SKU（筛选 + 只看未下单 + 行内撤销）
  右：SkuOrderEditor（同一组件也用于主面板弹窗）
      ├─ 按品名缸规则就近取整：「建议 N 缸 × 缸型 ＝ Y 公斤」
      ├─ 填缸数 → 公斤 = 缸数 × 缸型；填公斤 → 只回填整缸数 / 提示非整缸
      └─ 按染厂拆多张分订单（染厂 / 分单人员 / 缸数 / 数量 / 备注）
              │
              ▼  草稿：drafts[skuId]（主面板完全不知道）
     「确认下单」（单张 / 勾多个一键确认）
              │
              ▼
     订单 orders[]（只追加，按染厂各成一张单，status = active）
              │
              ▼
  ┌───────────────────── 主面板「备货」列 ─────────────────────┐
  │  已下单 = Σ active 订单 quantity（累计）                     │
  │  已到货 = Σ 订单 receipts[].qty（累计）                      │
  │  [订单] → 弹窗：左「已下订单」（每单一个到货 input + 撤销）  │
  │                右「到货订单」（实收到货记录）                │
  └───────────────────────────────────────────────────────────┘
              │
              ├─ 确认下单 → 需安排清零、解锁，已下单 +=
              ├─ 登记到货 → 待收 -=，已到货 +=（预计库存不变）
              └─ 撤销订单 → 需安排 += 该单公斤（草稿态、不锁）→ 预警回红
```

## 3. 全流程分步

### 3.1 生成「需安排」（主面板，公斤、精准到个位）

| 方式 | 入口 | 数值来源 | 写入口径 |
| --- | --- | --- | --- |
| 单行填写 | 表格「需安排」列输入框 → `采纳` | 人工填写，占位提示给建议值 | **覆盖**该行 |
| 批量补货 | 勾选行（首列复选框 / 点整行 / 品名父行整组）→ 底部浮动条「确认补货」 | `getSuggestedPlanned(row)` | **覆盖**「需安排」 |
| 紧急补货 | 工具栏「紧急补货 N」→ 填「新增计划」 | `ceil(正常库存 − 预计库存)` | 在现有需安排上**追加**（调用处先换算成绝对值） |

- 建议值口径（唯一一份在 [`utils/inventory.js`](../../src/utils/inventory.js) 的 `getSuggestedPlanned`）：`max(0, ceil(正常库存 × 80% − 理论库存 − 已下单))`，即「补到绿色带中位」，**已下单的部分视为即将到货先扣掉**，同一缺口不会被建议补两次。
- 已有订单在履约（`已下单 > 0`）时，需安排格**不再显示占位建议值**，避免引导重复补货；进度看「备货」列。
- **订单货**（手动策略 `behavior: 'order'`）不给建议值，占位显示「按订单填写」，按客户报量人工填；它不参与预警与评分。
- 模式缺省 / 不参与备货的 SKU 建议值为 0，需人工决定。
- 这里的数字**一律是精准公斤**，不做缸取整；占位提示会写明「下单页会再按缸规则建议整缸数量」。

### 3.2 采纳「需安排」（唯一写入路径）

```
行内「采纳」 ──┐
批量「确认补货」┼─→ applyRestockPlans(plans)
紧急「确认提交」┘        │
                         ├─ 写入 item.planned（覆盖）
                         ├─ 记 plannedUndoHistory（旧值 + 旧清单行，供撤销）
                         └─ 同步 purchaseList（同一 SKU 只保留一条）
```

- `applyRestockPlans` 只接受 `planned > 0` 的行；返回实际写入行数，主面板提示「已加入本次采购清单：N 个 SKU」。
- 采纳后该行「需安排」被锁定（输入框禁用 + 锁图标），点「撤销」恢复原值与原清单行。
- **锁定 = 生效**：锁定的数字就是这个 SKU 传到下单页的「需安排」总数，也是「预计库存」里唯一被采信的计划量。
- **未锁的需安排只是草稿**（现有实现即 `plannedDrafts`）：显示在格子里、可编辑，但**不计入预计库存**。撤销订单后回补的数字就落在这一层，所以预警会退回到红色。
- 清单条目结构：`{ id, skuId, product, color, planned }`，`id` 会随导入重排，**跨导入只认 `skuId`（唯一标识）**。

### 3.3 主面板「备货」三列（已下单 / 已到货 / 订单）

表头分组由 `TABLE_COLUMNS` 相邻同组自动合并，所以在「入口」与「出口」之间插三条就会长出「备货」大表头：

```
信息 · 商品 │ 入口：需安排 · 生产中 │ 备货：已下单 · 已到货 · 订单 │ 出口：欠货 · 周销量 │ …
```

| 列 | 显示 | 取数（只来自订单，不来自导入） |
| --- | --- | --- |
| 已下单 | 该 SKU **累计下单公斤** | Σ `status = active` 的 `quantity` |
| 已到货 | 该 SKU **累计到货公斤** | Σ 这些订单的 `receipts[].qty` |
| 订单 | 按钮「订单」（有单时带张数） | 打开订单弹窗（见 3.4） |

- **累计口径**：下单 800、到货 300 时两格分别显示 `800` 与 `300`；`待收 = 500` 只在弹窗里显示。
- 重新导入 / 重新清洗**不会影响这两列**，因为它们只读订单数据。
- 该 SKU 没有订单时两格显示 `0`，「订单」按钮置灰。

### 3.4 订单弹窗（已下订单 / 到货订单 / 撤销）

| 区域 | 内容 |
| --- | --- |
| 左列「已下订单」 | 每张分订单一行：染厂 · 提交时间 · 下单公斤 · **到货输入框** · 待收 · 撤销 |
| 右列「到货订单」 | 该 SKU 的实收记录：到货时间 / 公斤 / 操作人，可撤销最后一条 |

- **到货是每张订单一个输入框**：填 300 → 追加一条 `receipts` 记录 → 该行「待收」由 800 变 500，右列新增一条到货记录，主面板「已到货」+300。
- 到货**不改变预计库存**，它只是把 800 里的 300 从「待收」挪到「已到货」。
- **撤销整张分订单**：`status → cancelled`（行保留，不物理删除），该单未撤的到货记录一并作废；该单公斤数加回「需安排」，**落在未锁的草稿层**，于是预警退回「紧急补货」，需要重新采纳才算有效计划。
- 已有到货记录的分订单，撤销前必须二次确认（避免订单没了、货却在仓库）。

### 3.5 预计库存与预警（本版口径）

```
待收     = max(0, 已下单 − 已到货)
预计库存 = 在仓kg + 导入在途kg + 待收 + 已到货 + 锁定的需安排
        = 在仓kg + 导入在途kg + 已下单 + 锁定的需安排
```

- 红线 / 正常 / 峰值 的判定逻辑一字不改，仍拿预计库存与三档比较。
- 三个数各司其职、互不覆盖：**需安排 → 计划**、**已下单 / 已到货 → 执行**、**在仓 / 在途 → 事实**。
- 到货动作对预计库存**零影响**，不会出现「记一次到货、预警跳一次」。
- 确认下单后需安排清零，但那 800 由「已下单」继续顶住预计库存 —— 这就是「一下单就不再催补货」的原因。

### 3.6 本次采购清单（主面板弹窗）

- 列：品名 / 颜色 / 树形分类 / 需安排 / 已下单（公斤 · 张数）/ 已到货 / 待收 / 操作「去下单」。
- 空清单提示「暂无已采纳的采购计划」；工具栏按钮带条数角标，确认补货后会有脉冲高亮。
- 底部：「进入采购下单页 →」/「关闭」/「导出 Excel」。

### 3.7 采购下单页（按染厂拆单 → 确认下单）

- 顶部统计：待下单 SKU / 需安排合计 / 已下单合计 / **合计缸数** / 还没下单。
- 左列表：品名 · 颜色、树形分类、缸型提示（`ladder` 显示「缸型 80 / 160 / 240 公斤」，`vat` 显示「每缸 X 公斤」，`round` 显示「按 X 公斤取整」）、需安排 / 已下单（张数 · 缸数）；支持关键词筛选与「只看未下单」。选中行随筛选自动回落到第一行。每行「操作」列的**撤销**把该 SKU 从本次采购清单剔除（二次确认），清空它已填的草稿，并把主面板该行的需安排清零、解除锁定。
- 右侧编辑器（[`SkuOrderEditor.vue`](../../src/components/SkuOrderEditor.vue)）：
  - 指标条：需安排 / 已下单 / 合计缸数；「N 张非整缸」告警；右侧灰字显示当前缸规则（悬停看命中区间与建议）。
  - 表格列：`#` / 染厂 / 分单人员 / **缸数** / 数量（公斤）/ 备注（缸号 / 交期）/ 删除。
  - **缸数 ⇄ 公斤是单向硬换算 + 反向提示**：填缸数 → 公斤 = 缸数 × 缸型；填公斤 → 只有正好整缸才回填缸数，否则缸数留空。
  - 数量下方行内提示：整缸写「＝ 2 缸 × 240 公斤」；非整缸写「非整缸：1 缸 = 240 ／ 2 缸 = 480 公斤」，由下单人决定改缸数还是改公斤。
  - 行表尾：合计缸数、合计公斤、与需安排的差额（一致 / 还差 / 超出）。
  - 空状态两个按钮：「＋ 添加分订单」「按建议添加（Y 公斤）」——后者直接用缸规则算出的整缸量落成第一张分订单。
  - 「清空分订单」需二次确认。
- 主面板「去下单」弹窗（`SkuOrderDialog`）复用同一个编辑器，标题 `采购下单 · 品名 颜色`，按钮「保存分订单」；两处行为一致，不要各写一份。
- **编辑即草稿**：下单页填的行先存 `drafts[skuId]`（自动保存，防抖 400ms），主面板完全感知不到，需求表数字一格都不动。
- **确认下单**：单个 SKU 的「确认下单」，或勾选多个 SKU 的「一键确认全部」。确认时按染厂各生成一张订单（同一批共用 `batchId`），写 `submittedAt`、`status = active`，并清空该 SKU 的草稿。
- 确认后主面板该 SKU：**需安排 → 0、锁解除、格子回到空白**（不再显示占位建议值，因为已有订单在履约），「已下单」+= 本批公斤。
- 下单页行内「撤销」（**确认前**）：清空该 SKU 草稿，主面板需安排清零并解锁 —— 等同「这个 SKU 先不下了」。
- 部分下单（确认量 < 需安排）时同样清零解锁；没下够的部分由预警提示重新补货，不会自动留在需安排里。

### 3.8 订单模型与落盘

| 项目 | 说明 |
| --- | --- |
| 结构 | `{ version: 2, updatedAt, drafts: { [skuId]: Entry[] }, orders: Order[] }` |
| 草稿 | `drafts[skuId]`：下单页正在填的行，运行时可留空白行，**不算已下单** |
| 订单 | `orders[]` 扁平一行 = 一张分订单（SKU × 染厂），**只追加、不物理删除** |
| 订单字段 | `{ id, batchId, skuId, product, color, factoryId, factoryName, assignee, quantity, vatCount, kgPerVat, note, status, submittedAt, updatedAt, month, receivedQty, receipts[], revisions[], cancelledAt }` |
| status | `active` / `cancelled`；到货进度由 `receivedQty` 与 `quantity` 比较派生，不单设状态 |
| 到货 | `receipts: [{ at, qty, by }]`，`receivedQty = Σ receipts.qty`；撤销到货 = 撤掉最后一条 |
| 修订 | 允许修改已提交订单，每次保存追加一条 `revisions[]`（时间 / 操作人 / 改前 / 改后） |
| 迁移 | v1 的 `{ orders: { [skuId]: Entry[] } }` 逐条迁成 `active` 订单，`submittedAt` 取文件 `updatedAt`、`batchId = legacy-{updatedAt}` |
| 写入 | 统一走 `purchaseStore` → 防抖 400ms 落盘，`pagehide` 时 flush |
| 索引 | store 维护 `bySku` 聚合（已下单 / 已到货 / 待收 / 张数 / 单据），主面板按 `skuId` O(1) 取值，**不要逐行扫全表** |

### 3.9 导出与对账（主面板「本次采购清单 → 导出 Excel」）

文件名 `本次采购清单-{时间戳}.xlsx`，两个工作表：

| 工作表 | 列 |
| --- | --- |
| 本次采购清单 | 品名、颜色、树形分类、需安排、**缸数**、**每缸公斤**、建议下单、已下单、已到货、待收、分单数量 |
| 分单明细（有分单时才出现） | 品名、颜色、树形分类、染厂、分单人员、**缸数**、**每缸公斤**、数量（公斤）、已到货、待收、备注 |

- 「缸数 / 每缸公斤 / 建议下单」由导出行现算（需安排 × 品名绑定的缸规则），落盘的 `vatCount` / `kgPerVat` 用于分单明细。
- 界面上的清单**不显示**缸数列；缸数建议只出现在下单环节与导出文件里。

## 4. 缸规则（只在下单环节生效）

### 4.1 数据模型（`src/purchase/settings.json`，设置版本 v3）

```jsonc
{
  "vatRules": [
    {
      "id": "vr-standard",
      "name": "标准大货补单",
      "bandKey": "planned",              // planned | skuMonthlyAvg | spuMonthlyAvg
      "remainder": "nearest",            // nearest | floor | ceil
      "remainderThreshold": 0.5,         // nearest：余量 ≥ 50% 一缸 → 补一缸
      "minVats": 1,                      // 需求 > 0 时至少几缸
      "bands": [                         // 从低到高，最后一档必须无上限
        { "upTo": null, "action": "ladder", "value": 0, "sizes": [80, 160, 240] }
      ]
    },
    {
      "id": "vr-small",
      "name": "小批量补单",
      "bandKey": "planned",
      "remainder": "nearest",
      "remainderThreshold": 0.5,
      "minVats": 1,
      "bands": [
        { "upTo": 50,   "action": "skip",  "value": 0 },
        { "upTo": 100,  "action": "fixed", "value": 60 },
        { "upTo": null, "action": "round", "value": 10 }
      ]
    }
  ],
  "defaultVatRuleId": "vr-standard",     // 未绑定的品名用它
  "spuVatRules": { "品名A": "vr-small" }, // 品名（SPU）绑定，SKU 全部沿用
  "skuVatRules": {}                      // 例外：单个 SKU 覆盖；"__none__" = 不取整
}
```

- `sizes` 是**可用缸型**（公斤，归一化时升序去重，最多 8 种），只有 `ladder` 动作使用；其它动作归一化后是空数组。
- 一个 SKU 的缸型来自它命中的档：`ladder` 档自带一组缸型，`vat` / `round` 档等价于「只有一种缸型」。

### 4.2 判定与换算

```
规则继承：skuVatRules[skuId] → spuVatRules[品名] → defaultVatRuleId（缺失时取第一条规则）→ 没有规则才按公斤精确下单
命中分档：按判据取指标，从低到高取第一条「上限为空 或 指标 < 上限」的档（30 属于「30 至不足 120」）
换算动作：
  skip   → 0 公斤（不下单）
  ladder → 按缸型就近取整（推荐，见下）
  fixed  → 固定下单量（视为 1 缸）
  vat    → 缸数 = 需安排 ÷ 每缸公斤，再按零头策略取整；下单量 = 缸数 × 每缸公斤
  round  → 同 vat，但每缸公斤 = 取整步长（10 = 整十，100 = 整百）
零头策略：nearest（默认，余量 ≥ 阈值补一缸）/ floor（只下整缸）/ ceil（不足一缸也下一缸）
下限保护：需求 > 0 时缸数至少为 minVats（默认 1 缸）
```

`ladder` 的两条分支（缸型 `sizes` 升序，`top` = 最大缸型）：

```
需求 ≥ top：缸数 = 需求 ÷ top，按零头策略取整（nearest = 余量 ≥ 半个大缸补一缸）；下单量 = 缸数 × top
需求 < top：取 |需求 − 缸型| 最小的那一种（正好一半时取大缸），只下 1 缸
```

> 也就是说 `ladder` 是「就近到最近的整缸，正好一半向上」。80 / 160 / 240 的临界点因此自动落在 **120 / 200 / 360**（相邻两档的中点），不需要手写区间。

- 入口函数：`planOrderQuantity(need, rule, context)`，返回 `{ action, bandText, kgPerVat, rawVats, vatCount, rounded, remainderKg, deltaKg, deltaRate, warnings }`。
- 规则解析：`resolveVatRule(settings, { skuId, product })`；分档查询：`resolveVatBand(rule, context)`。
- 规则文案：`describeVatBands(rule)`（`ladder` 会展开成它推导出的区间）/ `summarizeVatRule(rule)` / `describeVatRemainder(rule)`。

### 4.3 默认两条规则

| 规则 | 区间与动作 |
| --- | --- |
| 标准大货补单（默认） | 低于 120 公斤 → 1 缸 × 80 · 120 至不足 200 → 1 缸 × 160 · 200 及以上 → 每缸 240 公斤，多缸就近取整 |
| 小批量补单 | 低于 50 不下单 · 50 至不足 100 固定 60 公斤 · 100 及以上四舍五入到整十 |

两者都可由生产人员在「设置 → 下单配置 → 缸规则」改；改完要点「确定」才落盘。

### 4.4 换算示例（默认「标准大货补单」，缸型 80 / 160 / 240）

| 需安排（公斤） | 建议下单 | 说明 |
| --- | --- | --- |
| 20 | 80（1 缸 × 80） | 不足最大缸型，取最近的 80 |
| 100 | 80（1 缸 × 80） | 离 80 比离 160 近 |
| 120 | 160（1 缸 × 160） | 正好一半，向上取大缸 |
| 150 | 160（1 缸 × 160） | 离 160 更近 |
| 200 | 240（1 缸 × 240） | 正好一半，向上 |
| 300 | 240（1 缸 × 240） | 余量 60 < 半个大缸（120），舍弃 |
| 360 | 480（2 缸 × 240） | 余量 120 = 半个大缸，补一缸 |
| 500 | 480（2 缸 × 240） | 余量 20，舍弃 |
| 3371 | 3360（14 缸 × 240） | 余量 11，舍弃；比需安排少 11 公斤 |

> 一张分订单**只用一种缸型**，不做拼缸：400 公斤下 2 × 240 = 480，而不是 160 + 240 = 400。跨染厂拆成多张分订单时，每张单可以各用一种缸型。
>
> 文案差异：`ladder` / `vat` 才叫「每缸 X 公斤」；`round` 显示「按 X 公斤取整」，`fixed` 显示「固定 X 公斤/单」——避免把「按 100 公斤取整」误读成 100 个缸。

### 4.5 与备货口径的边界（重要）

- 主面板「需安排」、批量 / 紧急补货的建议值 **永远是精准公斤数**，不取整缸。
- 缸规则只作用于：采购下单页（左侧列表的规则参数、右上建议缸数、缸数⇄公斤联动与行内整缸提示）与清单导出文件里的缸数列。
- 手填公斤**不受缸型约束**：可以下 300 公斤（非整缸），只是会提示相邻两档整缸；缸数只存整数，非整缸时为空。
- 改缸规则**不会**回溯已保存的分订单；已落盘的 `vatCount` / `kgPerVat` 是快照。

## 7. 数据与持久化

| 数据 | 存放 | 刷新后 | 备注 |
| --- | --- | --- | --- |
| 设置 · 下单配置（含缸规则） | `src/purchase/settings.json` + localStorage `purchase-settings:v1` | ✅ | 开发态写 `settings.json`（端点 `/__purchase-settings/save`），构建产物只写 localStorage |
| 草稿 + 订单 | IndexedDB `documents.purchaseOrders`（整份 v2 文档） | ✅ | 不再受 localStorage 5 MB 限制；开发态仍顺带写 `orders.json` 便于调试；写入失败会在界面提示，不再静默丢单 |
| 需安排（`planned`）与锁态 | IndexedDB `meta.workspace`，**按 `skuId`** | ✅ | 锁定态由撤销快照派生，一并持久化；重新导入后自动挂回新行 |
| 本次采购清单（`purchaseList`） | IndexedDB `meta.workspace`，按 `skuId` | ✅ | 挂不上（快照里没这个 SKU）的条目不显示，计划值仍保留在 `plans` |
| 撤销快照（`plannedUndoHistory`） | IndexedDB `meta.workspace`，按 `skuId` | ✅ | 刷新后仍可撤销；`pagehide` 时会把未落盘的改动 flush 一次 |

> 也就是说：**「这次要采购哪些 SKU」和「人的备货决定」都会留下来**，导入的库存与销售表另有快照（见 [数据持久化方案](./数据持久化方案.md) 第 10 节）。
> 需要留痕的是三个动作：确认下单、修改、撤销/作废 —— 分别由 `submittedAt`、`revisions[]`、`status + cancelledAt` 记下来，不做物理删除。

## 8. 关键不变量（改代码前先看）

1. 需安排**只**通过 `applyRestockPlans`（批量 / 紧急）或行内「采纳」写入，不要另开写入口。
2. 分订单**只**以唯一标识为键；不要用 `purchaseList.id`（导入会重排）。
3. 缸规则**只**在 `src/purchase/vat.js` 实现；页面拿到 `planOrderQuantity` 的结果直接用，不要自己再算一遍。
4. 主面板不取整缸；缸只出现在下单环节与导出。缸型就近取整只在 `vat.js` 的 `ladder` 分支实现。
5. 主面板表格里只有「需安排」可编辑；品名 / 颜色 / 生产中 / 欠货 / 周消耗 / 周转入 / 在途 / 在仓都是导入值，只读。
6. 分订单编辑器只有一份（`SkuOrderEditor.vue`），主面板弹窗与 `/purchase` 共用。
7. 设置是草稿编辑，未点「确定」不落盘；缸规则在保存前会整体校验。
8. 空白分订单行运行时保留、落盘丢弃（`keepBlankEntries`），别再改成统一丢弃。
9. 示例数据区（`/example`、`/example/config`）不参与这套流程，也不要改。
10. 规则判定是「上限递增、末档无上限」；改分档时只改上限，文案会跟着重算。
11. **已下单 / 已到货只统计 `status = active` 的订单**；撤销（`cancelled`）保留行但不参与任何统计，不得物理删除。
12. **到货只追加 `receipts`**，`receivedQty` 由它求和派生；不允许覆盖写。撤销到货 = 撤掉最后一条。
13. **确认下单 = 需安排清零 + 锁解除**；**撤销订单 = 该单公斤回补到未锁的需安排**。两者方向相反，别写反。
14. 预计库存里「已下单」只能出现一次（拆成待收 + 已到货两段），**不得再把已到货单独加一遍**。
15. 已有到货记录的分订单，撤销前必须二次确认。

## 9. 常见操作

| 想做的事 | 怎么做 |
| --- | --- |
| 改缸型（如 80 / 160 / 240 三种缸） | 设置 → 下单配置 → 缸规则 → 编辑规则：判据选「SKU 月均条数」或保持「需安排」，处理方式选「按缸型就近取整」，参数填 `80，160，240` |
| 只用一种缸（如每缸 240 公斤） | 同上一行，参数只填 `240`；或把处理方式改为「按每缸公斤取整」并填 240 |
| 某个品名不按缸取整 | 设置 → 下单配置 → 缸规则 → 品名绑定 → 该品名选「不取整（按原样下单）」 |
| 只让个别小批量品名走小批量规则 | 品名绑定里逐个选「小批量补单」，或搜索后批量套用 |
| 某个 SKU 单独例外 | 目前界面只到品名级；SKU 级可通过 `skuVatRules`（设置文件）配置，值填规则 id 或 `__none__` |
| 看某条规则会影响多少品名 | 规则表「生效品名」列；改默认规则前先看「默认」标记 |
| 撤销刚采纳的需安排 | 主面板该行点「撤销」（仅未刷新时有效） |
| 看某个 SKU 下了多少、到了多少 | 主面板「备货」列：已下单 / 已到货；点「订单」看逐张明细 |
| 登记到货 | 主面板「备货 → 订单」弹窗，左列对应订单行的「到货」输入框填本次到货公斤（可多次追加） |
| 到货记错了 | 同一弹窗右列「到货订单」撤掉最后一条记录 |
| 撤掉一张下错的单 | 订单弹窗左列「撤销」：该单作废、公斤数回补到需安排（未锁），预警退回红色，重新采纳即可再下 |
| 确认下单后主面板为什么还是红的 | 需安排已清零解锁；若预计库存仍低于红线，说明确实没下够，按新建议补一次 |
| 交给染厂下单 | 主面板「本次采购清单 → 导出 Excel」，分单明细带染厂、人员、缸数、数量、已到货、备注 |
| 清空某 SKU 的分订单 | `/purchase` 右侧「清空分订单」（二次确认） |

## 10. 已知边界

- 采购清单与需安排（含锁态）已随 IndexedDB 持久化：刷新 / 重开浏览器后仍在，重新导入时按 `skuId` 自动挂回新行；**订单、已下单、已到货一直不会丢**。
- 已下单 / 已到货是**累计口径**，只增不减（撤销订单才会回退）；不支持手工改历史数字。
- 到货由仓库/文员手工登记，**不与导入的「在仓库存」自动核销**：导入更新后两套数字并排看，系统不猜哪笔入库对应哪张订单（真要精确核销，得让清洗引擎额外导出入库明细）。
- 撤销订单回补的需安排是**未锁草稿**，不会自动恢复成原锁定值；要重新生效必须再点「采纳」或重新补货。
- 部分到货（待收 > 0）不阻塞下一次补货：同一 SKU 可以有"还有 500 没到"和"又补了一批"并存，靠订单弹窗逐张核对。
- 分订单数量不做「跨染厂整缸校验」：各分订单分别按缸数录入，合计可以略高于需安排（取整差额），界面会显示差额。
- 不做拼缸：一张分订单只用一种缸型，要混装只能拆成多张分订单（合计仍可能不是整缸组合）。
- 同行备注里的缸号是自由文本，系统不解析、不校验唯一性。
- 订单是 append-only 流水（`active` / `cancelled` + `receipts` + `revisions`），但没有跨人的权限与审批；多人协作、认领与入库自动核销按 [数据持久化方案](./数据持久化方案.md) 阶段二再演进。

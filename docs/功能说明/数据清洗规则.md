# 数据清洗规则（v1.7・公斤口径）

> 唯一口径文件：`tools/cleaning/engine.mjs`。网页「导入分表」与命令行 `clean-merge.js` 共用，改口径**只改它**。
> 模式判定与系数配置见 [模式与系数设置.md](./模式与系数设置.md)。
> 最后核对：2026-11-19（生产排单输出列改名「生产中」；主面板「在途库存」改由订单流水派生）。

---

## 1. 一句话

用**产品资料的 SKU 全集**做基准，把 4 张业务表按「唯一标识」并进来，所有销量与库存**统一换算成公斤**，输出「总表」与「销售表」。换算不出公斤的 SKU **直接剔除**。

```
产品资料（基准｜未上传时用 cache/productMaster.json）
  ├─ 出入库明细   → 销量、订单、客户、1-12 月
  ├─ 库存结存表   → 在仓库存
  ├─ 欠货         → 欠货
  └─ 生产排单     → 生产中（进仓重量，公斤）
出码率（可选，未上传时用 cache/rates.json）→ 只用于把「码」换算成公斤
```

---

## 2. 输入：6 张表（4 必选 + 2 可用缓存）

| 表 | 必填 | 作用 | 用到的列 |
|---|---|---|---|
| **产品资料** | ✅ 基准（可用缓存） | 决定行集合、色彩、单位 | 品名、颜色、树形分类、单位 |
| **出入库明细**（销售 + 加工） | ✅ | 全部销量口径 | 品名、颜色、单位、出库数量、做账日期、客户 |
| **库存结存表** | ✅ | 在仓库存 | 品名、颜色、数量 |
| **欠货订单导出** | ✅ | 欠货 | 品名、颜色、欠货总数量 |
| **生产排单** | ✅ | 生产中 | 品名、颜色、进仓重量 |
| **出码率** | 可选（可用缓存） | 码 → 公斤 | 品名、出码率 |

- 唯一标识 = `品名 | 颜色`（别名兼容 `产品名` / `天鸿颜色`）。
- 出码率按**品名**匹配（不区分颜色），缺表且无缓存时所有「码」单位 SKU 都会被剔除。
- 生产排单颜色为空的行直接忽略（无法定位 SKU）；欠货 / 生产排单可追加基准里没有的 SKU。

### 2.1 稳定字典缓存（`tools/cleaning/cache/`）

产品资料与出码率是「长期稳定、只增不减」的字典，放在清洗模块自己的目录里，网页与命令行共用：

| 文件 | 内容 | 生成口径 |
|---|---|---|
| `cache/productMaster.json` | `{ 品名, 颜色, 单位, 树形分类 }[]` | **只保留能换算成公斤的 SKU**（公斤单位，或码单位且出码率 > 0） |
| `cache/rates.json` | `{ 品名, 出码率 }[]` | 按品名去重，来自出码率表 |
| `cache/meta.json` | 更新时间与条数 | 写回时自动生成 |

- **优先级**：本次上传了文件 → 用文件；没上传 → 用缓存。缓存缺失且没文件才报错。
- **更新**：开发态导入时勾了产品资料 / 出码率，会自动写回（Vite 插件 `/__cleaning-cache/save`）；命令行加 `--update-cache`；生产构建的资源只读，更新走重新部署（或以后接后端上传）。
- **界面**：导入分表对话框把这两张放进「可选」组（虚线框、整组淡化，行尾写「系统缓存」），必选只剩 4 张。
- **形态**：网页用 `?url` 把 JSON 作为独立资源按需 `fetch`，不会内联进主 bundle（构建后 `productMaster` 约 2.2MB、gzip 约 154KB）。

## 3. 单位与公斤换算（核心）

```
公斤单位：数量 = 公斤，公斤系数 = 1
码 单位：公斤 = 码 ÷ 出码率，公斤系数 = 1 ÷ 出码率
其他单位（条 / 件 / 米 / 空）：无法换算 → 剔除
```

- 出码率含义：**1 公斤 = N 码**（例：芭莎网 24 → 1 公斤 = 24 码）。
- 总表输出 `出码率` 与 `公斤系数` 两列，网页只做 `数量 × 公斤系数`。
- 生产中取生产排单的「进仓重量」，**本身就是公斤**，不再乘系数。
- 在仓库存、欠货、周转入都是 SKU 自己的数量单位，展示时统一乘公斤系数。

---

## 4. 剔除规则（v1.6 新增）

在**基准表阶段**就过滤，后面的汇总与关联不会为它们白算一遍：

| 情况 | 处理 |
|---|---|
| 公斤单位 | 保留 |
| 码单位 + 有出码率 | 保留 |
| 码单位 + 无出码率 | **剔除** |
| 条 / 件 / 米 / 空单位 | **剔除** |
| 欠货 / 生产排单追加的 SKU 无法换算 | **兜底剔除** |

统计会带出 `stats.base.skippedRows`（基准剔除数）与 `stats.appendedDropped`（追加行剔除数）。
当前数据：产品资料 30,991 → 保留 **22,312**（剔除 8,679），总表内「公斤系数为空」= 0。

## 5. 汇总口径

出入库明细只统计 **`出库数量 > 0`** 的行（退货 / 纯入库不算订单、不算动销）。

| 字段 | 公式 | 精度 |
|---|---|---|
| 总出库数量 | Σ出库数量（原始单位，不换算） | 6 位 |
| **累积条数** | Σ出库数量 ÷ 单位换算系数（码 100 / 公斤 20） | 整数 |
| **累积销量** | Σ(出库数量 → 公斤) | 2 位 |
| **月均销量** | 累积销量 ÷ 动销月份 | 2 位 |
| **周销量** | 月均销量 ÷ 4 | 2 位 |
| 订单总数 / 月订单数 | 有效行数（1 行 = 1 单） | 整数 |
| 动销月份 | 有出库的月份集合中最长连续段（跨年算连续） | 整数 |
| 累计客户 | 客户去重计数（无客户列 → 0） | 整数 |
| 客户CR5率 | 前 5 名客户销量 ÷ 总销量 | 0~1，4 位 |
| 每月客户数 | 当月客户去重计数（无客户列 → 0） | 整数 |
| 每月累计客户数 | 首见月 ≤ 当月的客户去重计数（含往年客户） | 整数 |
| 每月累计销量 | 月份 ≤ 当月的公斤销量之和（含往年整年） | 2 位 |
| 每月累计条数 | 月份 ≤ 当月的条数之和（含往年整年，按单位换算系数换算） | 整数 |
| 每月累计订单数 | 月份 ≤ 当月的订单行数之和（含往年整年，1 行 = 1 单） | 整数 |
| 每月客户CR5率 | 当月前 5 名客户销量 ÷ 当月总销量；当月没有销量时**留空**（不写 0） | 0~1，4 位 |
| 在仓库存 / 生产中 / 欠货 | 同 SKU 多行求和 | 源值 |

- **累积条数只用于两处**：模式判定（月均条数 = 累积条数 ÷ 动销月份）与 SPU 展示；所有金额类计算都用公斤。
- **动销月份除参与月均条数换算外，还是健康度评分的独立维度**（3 ~ 5 个月中风险、≤ 2 个月高风险、≥ 6 个月低风险，见 [模式与系数设置.md](./模式与系数设置.md) 第 12 节），销售表原样展示该列，缺值按「无数据」不参与综合分加权。
- 客户维度按月列的基数是**原始出库数量**（与全历史「客户CR5率」同一个 `topShare` 口径，不换算公斤），所以弹窗里每月 CR5 与卡片 CR5 可以直接对比；「每月累计客户数」跨年看客户首见月，1 月就已包含往年客户，末月等于全历史「累计客户」。「每月累计销量」同理按「年*12+月」跨年累加，末月等于全历史「累积销量」。「每月累计条数」（再按单位换算系数换回条数）与「每月累计订单数」（不换算）都用全历史总量扣掉「本月之后」的月份，末月分别是「累积条数」「订单总数」的同一个累加结果，两者必定一致。
- 1-12 月按数据里**最新的年份**统计（`year: null`）：读取时按「年份 + 月份」分桶，读完一遍再取最新年份，不再为了识别年份把整张明细扫两遍。
- 色彩：唯一标识含 `本白 / 大白 / 黑白 / 黑色` → 黑白，否则彩色。

## 6. 输出

### 6.1 总表（13 列）

`唯一标识 | 品名 | 颜色 | 色彩 | 树形分类 | 出码率 | 公斤系数 | 欠货 | 周销量 | 周转入 | 生产中 | 在仓库存 | 总出库数量`

- `生产中` = 生产排单的「进仓重量」（公斤）；`周转入` 暂无数据源，整列填 0。
- `周销量` 单位是**公斤/周**。
- 主面板的「在途库存」列**不来自清洗**（由订单流水的累积下单派生），总表不再输出该列；旧版总表里的「在途库存」列仍能被导入识别为进仓重量。

### 6.2 销售表（117 列）

`唯一标识 | 品名 | 颜色 | 累计客户 | 订单总数 | 动销月份 | 累积条数 | 累积销量 | 客户CR5率 |`
`1月条数 / 1月销量 / 1月累计销量 / 1月累计条数 / 1月订单数 / 1月累计订单数 / 1月客户数 / 1月累计客户数 / 1月客户CR5率 / … / 12月客户CR5率`

- `N月销量`、`N月累计销量` 与 `累积销量` 单位是**公斤**。
- `N月条数`、`N月累计条数` 与 `累积条数` 是换算值（码 ÷ 100、公斤 ÷ 20），只用于展示、折线图与模式判定。
- `N月累计销量 / N月累计条数 / N月累计订单数 / N月客户数 / N月累计客户数 / N月客户CR5率` 只给 SKU 弹窗的月度图用，销售表页不展示这几组列。
- `累积销量` 是评分「进销比」的分母：进销比 = 本次进货量 ÷ 累积销量。

## 7. 下游计算（网页端）

```
在仓库存(公斤) = 在仓库存 × 公斤系数
理论库存(公斤) = 在仓库存(公斤) + 生产中(公斤)
预计库存(公斤) = 理论库存 + 需安排（人工按公斤填写）

日销量(公斤/天) = 加权月销量 ÷ 30
加权月销量 = Σ(各档「近 N 个月月均 × 权重」)，默认 近1月 ×50% + 近3月月均 ×30% + 近12月月均 ×20%（配置页可改，档位可增删）

热销 / 常规：日库销比(天) = 预计库存(公斤) ÷ 日销量
             三档库存(公斤) = 日销量 × 系数天数
按量：       直接用库存公斤数比系数（系数单位 = 公斤）
            主面板「日库销比」列在按量行显示 --（指标就是公斤库存，与「预计库存」重复，不重复展示）

缺口量 = 正常库存(公斤) − 预计库存(公斤)
建议需安排 = ceil(正常库存 − 理论库存 − 累积下单)
```

预警灯：低于红线 🔴、高于峰值 🟣、正常 ±20% 🟢、其余 🟡；尾货 / 滞销 / 专属品不参与（灰）。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 某批 SKU 不见了 | 单位是「码」但出码率表里没有该品名 | 补出码率后重新清洗 |
| 总表「公斤系数」整列为空 | 没选出码率文件 | 重新导入时勾上 `出码率.xlsx` |
| 生产中远大于在仓 | 进仓重量是公斤、在仓是码 | 正常现象，两者都已换算成公斤后再相加 |
| 月销量全是 0 | 销售表用的是旧模板（只有月条数/月重量） | 用新版清洗输出，或确认 `N月销量` 列存在 |
| 条数与销量对不上 | 条数是换算值（码 ÷ 100、公斤 ÷ 20），销量是公斤 | 属正常；比较时一律用公斤 |
| 出码率改了要不要重新清洗 | 要 | 出码率参与销量与库存换算，必须重新清洗 |

## 9. 维护约定

1. 改清洗口径 → 只改 `tools/cleaning/engine.mjs`，并同步本文。
2. 改字段名 / 输出列 → 同步 `src/utils/inventoryImport.js`（总表解析）与 `src/utils/salesImport.js`（销售表解析）。
3. 网页与命令行用的是同一份引擎：网页经 `src/cleaning/engine.js` 转发，命令行 `clean-merge.js` 直接引用。
4. 出码率表只增不减：某品名从出码率表里删掉，它的所有 SKU 会在下次清洗时被剔除。
5. 稳定字典缓存 `tools/cleaning/cache/` 与清洗产物同口径：产品资料只留能换算成公斤的 SKU。更新只走「导入时上传文件（开发态自动写回）/ 命令行 `--update-cache` / 重新部署」，不要手工编辑这两份 JSON 的结构。
5. 清洗只负责「算数」，列的展示与页面交互（父行聚合、比例列加权、搜索）见 [前端视图与交互.md](./前端视图与交互.md)；下游公式再往下（模式、系数、评分、缸）见 [模式与系数设置.md](./模式与系数设置.md) 与 [采购下单流程.md](./采购下单流程.md)。

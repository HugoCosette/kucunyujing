## 2. 销售表（`/sales`）

### 2.1 数据来源

- 品名 / 颜色 / 5 个动销指标（月均条数、订单总数、动销月份、累计客户、累积条数）与 1-12 月条数 / 销量 **都来自主面板那份 store**（`inventoryStore` 的库存行 + `salesSheet`），本页不重新计算，也不叠加第二份来源。只给 SKU 弹窗月度图用的按月列（`N月累计销量 / N月累计条数 / N月累计订单数 / N月客户数 / N月累计客户数 / N月客户CR5率`）也在同一份 `salesSheet.bySku` 里，本页不展示。
- 本页**没有导入入口**：未导入时的空态直接提示「请在主面板用『导入分表』清洗后导入」。历史版本里销售表自己的「导入销售表」入口已删除，不要加回来。
- 列定义：`src/data/salesFields.js` 的 `SALES_MONTH_FIELDS`（每月三列：条数 / 销量 / 订单数）、`SALES_RATIO_COLUMNS`、`SALES_TABLE_COLUMNS`。

### 2.2 行结构与聚合

- 用 `groupTableRowsByProduct()`（`src/utils/productGroups.js`）生成「品名汇总父行 + 颜色子行」两级；父行的数量列求和，**比例列按权重列加权平均**。
- 客户CR5率 = 销量前 5 客户 ÷ 该 SKU 总销量，清洗引擎输出 0~1，页面显示为百分比；它只在销售表出现，不写回主面板、不进备货配置。父行按「累积条数」加权平均（`SALES_RATIO_COLUMNS` 的 `weightKey: 'cumulativeCount'`），不做求和。
- 动销指标保留主面板导入值：销售表文件里的同名列不参与覆盖。

### 2.3 筛选

- 工具栏与主面板一致，分成「品名」「颜色」两个筛选框（`ElInput`，`clearable`，各做 250ms 防抖，`includes` 匹配），不再提供「搜索全部列」。
- 行对象预存 `searchProduct` / `searchColor` 两个小写索引，筛选只做 `includes`。
- 命中数为 0 时区分「没有匹配的数据」与「暂无数据」。

### 2.4 弹窗

颜色单元格的入口按钮与弹窗与主面板完全共用：`SkuDetailTrigger` + 页面级 `SkuDetailDialog`（见 §4），不要再写第二份。

## 3. 主面板（`/`）

### 3.1 可编辑边界

| 分组 | 列 | 交互 |
| --- | --- | --- |
| 基本信息 | 品名、颜色、色彩、树形分类 | 只读文本 |
| 数量 | 生产中（生产排单进仓重量，公斤）、在途库存（与「累积下单」同源）、欠货、周消耗、周转入、在仓库存 | 只读文本（导入 / 订单派生值） |
| 信息 | 模式、评分、加权月销量、系数、预警 | 派生展示 |
| 备货 | 需安排 | **唯一可编辑列**（`ElInputNumber`），草稿存 `inventoryView` store；输入框内按 **回车** 等同于点「采纳」（与行内按钮同一条路径，不做视觉提示）；行内「采纳」**不跳转**（留在主面板继续处理下一行），要去拆单自己点顶部「采购下单」 |

另有采购下单页的分订单数量、紧急补货弹窗的数量可以编辑。其余一律 `ElInput` / `ElInputNumber` 化都算回退，要改数据请重新导入或改源表。

#### 「需安排」的实时预览与待下单提示

「需安排」填了草稿但还没采纳时，右侧 **预计库存 / 日库销比 / 缺口量 / 缺口率** 立刻按草稿重算并进入预览态，不用等采纳（理论库存是事实层，不动）：

- 预览格：浅色底（按「补完之后的预警色」上色）+ 数字虚线下划线 + 变化量角标（`125 +63`、`31 −63`），数字每次变化有 200ms 轻微上浮淡入；悬停给出「当前 → 预览」与「采纳才写入」的完整说明。
- 预警灯同步按预览色显示，外圈套一圈虚线环表示「还没采纳」（`urgency-indicator--preview`）；已采纳、还没下单时灯色也按补完之后的颜色显示，改成实线环（`urgency-indicator--projected`）与草稿区分，悬停写明「预计（已采纳、还没下单）… 数据态仍是『紧急补货』」。
- 品名父行的预估列与需安排也一起预览（沿用子行汇总口径），不会停在旧值。
- 清空输入框或填 0 即退出预览。只有**显示值真的变了**的格子才进入预览态（父行汇总不出的日库销比不会平白染色）。

**采纳后提示不消失**：只要需安排还有数字（已采纳、还没下单），这 4 列继续标出「这一单带来的变化」——显示当前值 + 变化量角标（`212 +150`、`−56 −150`），底色与角标沿用补完之后的预警色，只去掉弹入动画（`preview-cell--adopted`）；悬停写明「已采纳但还没下单：需安排 150 公斤 … 在『采购下单』确认下单后这条提示消失」。在采购下单页**确认下单**（或撤销下单）把需安排清零、数字转到累计下单后，提示才消失。

**预警灯的两个态**：`数据态`只由导入数据 + 订单派生（把需安排清零重算，`dataStateOf()` / `dataTone()`），`预计展示态`把需安排算进去（`getPlannedTone()`）；灯色、需安排格底色用预计展示态，筛选 / 计数 / 紧急补货清单只认数据态（详见 3.6）。

- 实现：`previewOfLeaf()`（按 id 缓存草稿预览行，`buildRowWithPlanned()` 复用 `evaluateItem` + `calculateInventoryRow`）、`productPlannedPreviews`（父行按子行预览行重新汇总）、`shadowOf()`（需安排清零后的对照行，按 `id|planned|ordered|received` 缓存，整表重算时清空）、`productPlannedShadows`（父行按子行清零版汇总）、`previewPair()`（统一给出草稿层 / 采纳层的 display 与 base）、`lampRingClass()`（预警灯套虚线还是实线环）、`PREVIEW_COLUMNS`（哪几列参与）；只重算用到的行，不整表重算。SKU 弹窗的需安排走同一份草稿，所以弹窗里输入时表格也跟着预览。

品名汇总行的模式列显示 SPU 等级徽标（`S+ / S / A / B / C / Z`）：等级 = 该品名下**全部 SKU** 的月均条数之和按六档阈值判定，与当前筛选无关（阈值与口径见 [模式与系数设置.md](./模式与系数设置.md) 的 `spuGrades` 段）。

### 3.2 勾选与批量补货

「需安排」只有三个数，按钮 / 勾选 / 预览全部从它们派生：**草稿**（`plannedDrafts`，可编辑、未采纳）→ **已采纳**（`item.planned`，锁定，下单时清零）→ **建议值**（`getSuggestedPlanned()`，补到正常库存）。

| 操作 | 结果 |
| --- | --- |
| 勾选 SKU（含父行 / 全选） | 没有数字、没采纳过的行自动带入建议值（草稿） |
| 取消勾选 | 撤回「勾选带入」且没被改过的草稿，手填的数字保留 |
| 需安排填正数 / 清空 | 自动勾选 / 自动取消勾选 |
| 采纳 | 写入「正数草稿 > 建议值」（清空过也按建议值兜底），行进入锁定 |
| 确认补货 | 只提交勾选行「需安排」里填着的数字，没数字的行跳过 |
| 采购下单确认 | 需安排清零、撤销记录清掉、行解锁 |

1. 首列复选框维护 `selectedSkuIds`（**只存 SKU 标识**，行会随虚拟滚动装卸）；所有变更统一走 `applySkuSelection()`：锁定行不进选择，新勾选补建议值（`selectionAutoDrafts` 记着哪些是自动填的），取消勾选撤回自动填入。
2. 品名父行的勾选态由**可勾选子行**全选 / 半选推导；锁定 SKU 不参与父行勾选态，也不会被父行全选 / 取消操作改动。表头全选作用于**当前筛选结果**；点父行任意非复选框区域只展开 / 收起 SPU，点击父行复选框才全选 / 全不选其下可勾选 SKU；子行点击整行仍切换该 SKU 选择。
3. **锁定的行不可勾选**：已采纳（`plannedUndoHistory` 有记录）的行选择列**常驻显示锁图标**（替换复选框，直到订单提交解锁）、整行鼠标为锁形光标且点整行无效 —— 避免锁定行又被底部「确认补货」带一次；行内的「采纳 / 撤销」「SKU 弹窗」「订单弹窗」三个入口保持正常可点击光标。点这种行（整行 / 选择格 / 需安排格）不是没反应：该行的需安排输入框淡闪一圈蓝光、撤销按钮亮一圈琥珀光（`lockedHintRowId` + `.planned-input-shell--hint` / `.planned-accept-button--hint`，1.2 秒后自动收），把视线引到唯一能改的口子「撤销」上。在「采购下单」确认下单时需安排清零并解锁，之后恢复可勾选、可继续填写。
4. 有勾选时出现底部浮动条「确认补货」：**只传勾选行「需安排」里填着的数字**（勾选已自动带出建议值，不再回头取建议值兜底），没数字的行跳过；**精准公斤、不做缸取整**，点一下直接写入需安排并跳到采购下单页，没有中间弹窗；跳过去默认选中这次写入的 SKU 里**下单列表最靠上**的那条（下单列表按库存行顺序，主面板按品名月均销量重排过，两边顺序不同）。
5. 写入统一走 `writePlanned()`：**覆盖**该行的需安排（同一 SKU 一条绝对值），采购下单页按「需安排 > 0」直接列出，不再另存采购清单；单行采纳写完后会顺手把该行从勾选里摘掉。

「预计库存 / 日库销比 / 缺口量 / 缺口率」的提示也只看上面三个数：草稿层预览「填了会怎样」，采纳后改用对照行（把需安排清零重算）继续提示，直到订单提交、需安排清零才消失。

草稿层的预览是**派生出来的、不另存状态**：`previewOfLeaf()` 按 id 缓存 `{ 源行, 草稿数字, 预览行 }`，读的时候比对「源行 + 草稿数字」，任一项变了就重算（`plannedPreviews` 是普通 `Map`）。所以「需安排有数字」与「有补货提示」永远同步：勾选带入、手填、清空、采纳、撤销、撤销订单退回草稿、切到采购下单页再回来，都不需要谁记得去刷新，也不会出现「勾选还在、提示没了」这种脱节。

紧急补货弹窗走同一条写入路径：调用处先把「追加」换算成绝对需安排量，再交给 `writePlanned()`；它不跳页（一次处理多个红区 SKU 时不打断）。

### 3.3 屏蔽（「删除」的真实含义）

- 入口是**视窗右下角固定的「屏蔽选中」小按钮**：默认无勾选时隐藏，出现时按钮计数 = 勾选的 SKU 数（比底部批量补货条更低调）。
- 规则：先在表格勾选，确认后批量屏蔽——某品名当前可见的 SKU 全部勾中时记**品名级**屏蔽，否则逐条记 **SKU 级**。
- 存储：`src/stocking/hiddenSkus.json`（`{ products: 品名数组, skus: { 唯一标识: { product, color } } }`），开发态由 Vite 插件 `/__stocking-hidden/save` 写回源文件，构建产物写 localStorage 键 `stocking-hidden:v1`；跨导入、跨刷新保留。
- 只影响**展示**：表格行、品名父行合计与 SPU 等级、预警计数、模式筛选项、勾选 / 批量补货 / 紧急补货都按可见行算；源表与销售数据不动。
- 品名级屏蔽会清掉其下已有的 SKU 记录，恢复品名时整组一起回来。
- 解除在 `/hidden`（见 §9）。添加 SKU 时唯一标识会跳过屏蔽清单用过的标识，否则新行会命中屏蔽规则直接不显示。

### 3.4 添加 SKU（唯一手动录入入口）

- 组件 `src/components/AddSkuDialog.vue` + 写入逻辑 `src/utils/skuCreate.js`（`addInventorySku()`）。
- 字段与导入的总表 / 销售表一一对应：品名 / 颜色 / 色彩 / 树形分类、7 个数量列、5 个动销指标。
- 唯一标识不用人填：按 `MANUAL-0001` 递增自动生成，并跳过屏蔽清单里用过的标识。
- 库存与销量一律按公斤录入（公斤系数固定 1），不提供出码率 / 公斤系数输入；月均条数缺省时按「累积条数 ÷ 动销月份」现算。
- 校验「品名 + 颜色」不重复。
- 写入后复用主面板的 `importToast` 提示并带「查看该 SKU」按钮打开 `SkuDetailDialog`；同时清掉挡住新行的筛选、滚到该行并短暂高亮。若该 SKU 命中品名级屏蔽，提示去「屏蔽列表」解除。
- 手动添加与导入一样只存在当前页面数据里（刷新回到种子 / 快照），1-12 月销量仍只来自销售表。

### 3.5 表格渲染

品名父行 + 颜色子行的分组由 `groupTableRowsByProduct()` 统一生成；渲染走自研虚拟列表 `src/components/VirtualList.vue`。主面板颜色列展示时隐藏演示种子数据的「（演示N）」后缀，不改源数据。分组、虚拟化与增量计算的性能约定见 [主面板性能优化.md](./主面板性能优化.md)。

- 主面板「备货」表头默认折叠，隐藏「累积下单 / 待收 / 到货」三列；点击分组表头切换展开状态。折叠时保留窄占位列维持表格对齐。
- 采购订单详情按钮显示在「在途库存」列右侧；仅有订单的 SKU 行显示，品名汇总父行不显示，点击仍打开原订单详情弹窗。

### 3.6 筛选（表格上方工具条）

- 条件：品名 / 颜色两个关键词框（250ms 防抖，防抖后的值存组件里的 `appliedProductFilter` / `appliedColorFilter`）、「按SPU模式筛选」与「按SKU模式筛选」两个多选（**SPU 在左、SKU 在右**；前者是品名级 SPU 等级 `S+ / S / A / B / C / Z` + 「未分级」，后者是 SKU 级 `热销 / 常规 / 按量 / 尾货 / 滞销`），以及两组筛选 chip：第一组为**全部 → 下单中 → 已下单**，第二组为**紧急 / 常规 / 正常 / 超库存**。两个多选不渲染标签胶囊：框里只显示**一行摘要**（已选值按「、」连接，宽度不够用省略号截断，完整清单在悬停标题里），避免选两个就被压成「+1」；清空走右侧清空按钮，改选用下拉里的勾选。
- 布局分两行（`.filter-row`）：第一行是「查找」（品名 / 颜色）+「模式」（SPU / SKU 两个多选），右侧靠边放当前结果数、「清除筛选」（有任一筛选时才出现）与「全部展开 / 收起」；第二行是「采购」（全部 / 下单中 / 已下单）与「预警」（四色）两组 chip，两组之间用细竖线隔开。每组前面有 11px 的组名（`filter-group__label`），chip 高 24px、字号 12px，比原来 22px 更好点。
- **模式框的「生效态」**：任一模式多选选中后，框换成浅蓝底（`#eaf1f4`）+ 主色描边 + 左侧 2px 色条（`.mode-filter.is-filtering`），摘要末尾带一个深色小角标显示**已选几个**（`2`，表示「2 个条件生效」，不是「还有几个没显示」）；同时第二行组名变成 **「预警 · 筛选后」**并提亮（`filter-group__label--scoped`），悬停说明「计数已按『查找』与『模式』的筛选收窄，不是全量」。没有资料类条件（关键词 / SPU 模式 / SKU 模式都为空）时恢复「预警」。这只改提示，不改计数口径。
- 第一组是互斥单选：「全部」表示没有采购状态筛选；**「已下单」**（store 里的 `onlyOrdered`）命中 = 该 SKU 有未作废的分订单，即「累积下单」（`row.ordered`，来自 `orderSummaryOf(purchaseStore.orderIndex, skuId)`）> 0；**「下单中」**（`onlyOrdering`）命中 = 该 SKU 仍在 `plannedUndoHistory` 中锁定，表示需安排已采纳、等待采购页确认下单。默认选「全部」；点已选的「已下单」或「下单中」会取消它并自动回到「全部」。
- 两组 chip 的数字都按**资料类筛选**（品名 / 颜色 / SPU 模式 / SKU 模式）后的行数统计，**不含「采购状态」与「预警色」这两组互斥选择本身**（实现上就是 `scopedInventoryLeafRows`）：数字就是点下该档后表格剩下的行数，选中某档时也不会因为自己的选择而缩小。「全部」= 当前资料筛选内的可见 SKU 行数，含模式缺省 / 不参与备货的灰行，因此**四档之和小于「全部」**。第一组和第二组互斥：选择预警色会清除采购状态选择；选择「全部 / 下单中 / 已下单」会清除预警色选择。第二组全部取消后回到第一组默认「全部」。
- 点「全部」只清除采购状态与预警色选择，**保留品名、颜色、模式与 SPU 等级条件**；第一组的默认「全部」仍保持高亮，不因关键词 / 模式筛选而取消。确认下单后锁定解除，该 SKU 自动离开「下单中」；有有效分订单时进入「已下单」。
- 筛选条件一变就把表格滚回顶部；「添加SKU」定位新行时若被筛选挡住，也会整组清掉（含两个采购状态筛选）。
- **预警色按「数据态」筛**：预警有两个态 —— `数据态`只由导入数据 + 订单派生（需安排清零重算，`dataTone()`），`预计展示态`把已采纳 / 草稿的需安排算进去（`getPlannedTone()`，决定灯色与需安排格底色）。chip 的筛选、计数、紧急补货清单一律按**数据态**：采纳后行不会从「紧急 / 常规」里掉出去，灯变成补完之后的颜色（绿 / 黄，带实线环）就表示这单计划已经覆盖它；在采购下单**确认下单**把需安排清零、数字转到累计下单之后，数据态才换成订单数据，行才移出本档。计数与灯色因此可能不一致（「紧急 12」里 12 行全亮绿灯），这是有意的：数字回答「还有几个 SKU 在数据上缺货」，灯回答「这一个补到什么程度了」。
- **小额补货门槛**（`displayFilters.lowPlanned`，设置 → 备货配置 → 筛选显示规则）：启用时「紧急」「常规」两个 chip 只统计 `getSuggestedPlanned(row) >= minKg` 的行，点击后也只列这些行 —— 补几公斤的小单不值得单独开缸。「全部」「正常」「超库存」「已下单」「下单中」不受影响；`全部` 列表里仍能看到被门槛排除的 SKU，数据一行不动。紧急补货清单同一口径过滤，弹窗提示里写明排除了多少个。判据用建议值（补到正常库存即绿区中位、已扣累计下单），采纳前后不会跳。
- **SPU 模式筛选**（`selectedSpuGradeKeys`，与父行徽标同一份口径）：下拉在「按SKU模式筛选」左侧，选项是当前方案的六档档名加「未分级」，存的是**档位 key**（`sPlus` / `s` / … / `z` / `ungraded`），配置里改档名或阈值都不用迁移，改阈值后同一 SPU 换档、筛选结果随之变化。等级只按品名下全部可见 SKU 的月均条数之和判定、与其它筛选无关，所以命中是**整组保留**：品名要么整组列出、要么整组隐藏，父行合计与徽标对得上；与 SKU 模式筛选叠加时父行合计仍按命中子行汇总。「未分级」= 整个品名都没有月均条数（徽标显示「—」）。
- 筛选只影响展示：表格行、品名父行合计 / SPU 等级、预警 chip 计数、模式筛选项、勾选 / 批量补货都按当前筛选算；**紧急补货清单与 Excel 导出仍是全量**，「紧急补货」按钮悬停会写明「全量 N，当前筛选内 M」，避免以为已经全量处理完。

## 5. 视图状态（`src/stores/inventoryView.js`）

只跟「人怎么看这张表」有关的状态放这里，键包括：

| 键 | 说明 |
| --- | --- |
| `productFilter` / `colorFilter` | 关键词输入框的值 |
| `selectedWarningTones` / `selectedModeLabels` | 预警色 / 模式筛选；预警色可多选，非空时与采购状态筛选互斥 |
| `selectedSpuGradeKeys` | SPU 模式筛选，存档位 key（六档 + `ungraded`），与父行徽标同一份判定 |
| `onlyOrdered` / `onlyOrdering` | 采购状态筛选第一组的两个互斥开关：「已下单」看有备货订单（累积下单 > 0）的 SKU；「下单中」看仍由 `plannedUndoHistory` 锁定、等待确认下单的 SKU；两者都为 false 时第一组默认选中「全部」 |
| `expandedProductKeys` | `null` = 还没进过主面板（默认全展开）；`[]` = 用户主动全收起 |
| `selectedSkuIds` | 批量补货勾选，`Set<唯一标识>` |
| `selectedRowId` | 当前行：点击整行 / 行首复选框、或从行内「详情」按钮打开 SKU 弹窗时都会写入（弹窗只改高亮、不动勾选），表格里以 2px 蓝框标出 |
| `tableScrollTop` | 表格滚动位置 |
| `plannedDrafts` | 手填但未采纳的「需安排」公斤数（表格那一格与 SKU 弹窗共用同一份） |
| `selectionAutoDrafts` | 勾选时自动预填的草稿记录（`Map<唯一标识, 填入值>`）：取消勾选时只撤回没被改过的那些 |

- 放 store 的原因：`RouterView :key` 会让视图组件重建，切到采购下单 / 销售表 / 设置再回来会丢状态。
- 有意**只留内存**：刷新页面回到默认视图，不写 IndexedDB。
- 筛选的防抖副本 `appliedProductFilter` / `appliedColorFilter` 仍在视图组件里，改初始化逻辑时要连它们一起从 store 取值，否则首屏高亮与筛选结果不一致。

```
            └─ useSourceImport.js     直接写入：总表 + 销售表必须同时存在，按「唯一标识」关联
               └─ inventoryApply.js / applySourceImport.js 写 store 并落快照
```

- 主面板页头只有「导入分表 / 添加SKU / 紧急补货」三个入口，不做任何导出（模板下载与「本次采购清单」导出均已删除，导出改走 `/purchase` 与 `/purchase/history`），也没有旧版「直接选总表 + 销售表」的导入入口。其中「导入分表」紧贴页标题「需求表」右侧（同一条标题行左半段），「添加SKU / 紧急补货」仍右对齐；不要把它挪回右侧按钮组。
- 弹窗本身按「可选（产品资料 / 出码率，虚线框 + 整组淡化）」与「必选（4 张，白底实框）」两组分框，行首状态点区分已选（绿）/ 缓存（蓝）/ 待选（空心琥珀圈），组头右侧给「已齐 4/4」或「缺 N 张」；所有按钮（选择分表文件 / 清空 / 取消 / 开始清洗并导入）集中在底部灰底工具条，不要再往正文里塞说明段落。
- 清洗引擎另外支持可选的「出码率」表（缺表时码单位 SKU 会被剔除），口径见 [数据清洗规则.md](./数据清洗规则.md) 第 2 节。
- 清洗完成即写入，不再有「导入总表与销售表」的预览确认弹窗；写入后由导入成功 toast 汇总行数、SPU 数与跳过行数，需要逐行核对时请重新导出总表 / 销售表检查。
- 写入后由 `applySourceImport()` 落快照（gzip 进 `snapshots`，只留最近 5 份，内容哈希相同只更新时间），细节见 [数据持久化方案.md](./数据持久化方案.md) 第 10 节。
- 清洗口径本身只改 `engine.mjs`，见 [数据清洗规则.md](./数据清洗规则.md)。

## 8. 下单历史（`/purchase/history`，旧 `/orders`）

- 把 `orders[]` 聚成「批次（`batchId`）→ 分订单」两级，聚合与筛选全在 `src/purchase/history.js`（`buildOrderHistory()` / `filterHistory()`），页面不再自己算一遍。日期筛选（全部日期 / 按月 / 按日 / 自定义范围）按**本地确认日期**比较，`from` / `to` 两端都含；只填一头时按单边过滤。
- 版式是**单表头 + 与子行同列对齐的批次分组带**（子行缩进 24px + 左侧引导线，默认只展开最近一个批次）；不要加第二张表或第二套表头。
- 作废单灰显但不进合计，默认只显示有效单。
- 批次带「删批次」会删除该 `batchId` 下全部分订单，分订单行「删除」只删除该单；两者均二次确认，且订单关联的到货 / 改单记录一并删除。批次删除作用于完整批次，不受当前筛选结果影响。
- 删除有效单后重新派生下单 / 到货 / 待收及库存建议；删除已作废单不再次回补需安排。到货 / 改单 / 作废等日常操作仍走 `stores/purchase.js` 与主面板订单弹窗（见采购下单流程.md 第 3.4 节）。
- 「导出 Excel」导出的是当前日期 / 关键词 / 状态筛选结果，文件名带导出范围（`下单历史-{范围}-{时间戳}.xlsx`）；表格构造在 `src/purchase/historyExport.js`，与采购下单页页头「导出订单」共用同一份口径。
- 采购下单页页头另有「导出订单」：本次确认批次（本次会话最后一次确认的 `batchId`）/ 今日已确认 / 自定义日期范围，取数同样走订单流水——确认后 SKU 从待下单列表消失、列表空了也不影响导出。
- Excel 导出用 `src/utils/xlsxWrite.js` 的 `saveWorkbook(sheets, fileName)`（`sheets = [{ name, rows, widths }]`），所有导出页一律走 `saveWorkbook`。

## 9. 屏蔽列表（`/hidden`）

- 内容在 `src/components/HiddenSkusPanel.vue`；导航入口不带数字，数量在页面工具栏按 **SKU 计**：整组屏蔽的品名按当前数据里该品名的 SKU 数展开。
- 列表是按品名分组的树，可按品名 / 颜色 / 唯一标识搜索；品名可展开看 SKU；品名与 SKU 都能多选后统一解除，也支持逐个解除或全部解除。

## 10. 手验清单

1. 主面板筛选 → 切到采购下单 → 切回：筛选、展开、勾选、滚动位置、未采纳的「需安排」草稿都在（含「已下单」「下单中」开关）。
2. 主面板筛选组验证：默认「全部」高亮；点「下单中」或「已下单」仅对应状态高亮、只显示对应 SKU，再点当前状态取消后回到「全部」。点任一预警档后采购状态全部取消，预警可多选；取消最后一个预警档后恢复「全部」。两组切换不清除品名 / 颜色 / 模式 / SPU 等级条件，且两组不叠加。确认下单后 SKU 离开「下单中」，存在有效分订单时归入「已下单」。
3. SPU 模式筛选：选「S+」只留 S+ 的品名且其子行完整、父行徽标与合计对得上；再叠加「按SKU模式筛选」只缩子行、品名不丢；选「未分级」只剩徽标为「—」的品名；到设置页改一档阈值后同 key 的 SPU 换档、筛选结果跟着变；切到采购下单再回来筛选还在。
4. 点「紧急」chip 后采纳其中一行：该行**不掉出**列表，灯由红变绿 / 黄并带实线环，悬停写「数据态仍是『紧急补货』」；chip 计数不变；到「采购下单」确认下单后回来，该行才移出「紧急」。
5. 预警 chip 计数跟随筛选：选一个 SPU 模式 / SKU 模式或输入品名后，「紧急 / 常规 / 正常 / 超库存」以及「全部」的数字都变小，且点下去后表格行数与刚才的数字一致；选中「紧急」后数字不再缩小；清空这些筛选后数字回到全量。「紧急补货」按钮的数字不随筛选变化，悬停里能看到「全量 N，当前筛选内 M」。
5. 勾选若干行：右下角「屏蔽选中」出现且计数正确；确认后主面板行消失、父行合计与预警计数同步；`/hidden` 能解除并回来。
6. 导入分表：4 张必选（出入库明细 / 库存结存表 / 欠货 / 生产排单）+ 2 张可选（产品资料 / 出码率，未选走 `tools/cleaning/cache/`）→ Worker 清洗完成 → 预览弹窗显示总表与销售表行数 → 确认后主面板与销售表都有数据。
7. 主面板点颜色格旁的方形按钮：弹窗显示模式 / 评分 / 1-12 月图表；销售表同一 SKU 弹窗内容一致。
8. 「添加SKU」填最小必填项：新行出现在表格里并高亮，唯一标识是 `MANUAL-00xx`，toast 能打开弹窗。
9. 设置页改任一参数不点「确定」直接切页：有未保存提示；点「确定」后主面板对应数值变化。

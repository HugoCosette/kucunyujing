# 前端视图与交互

> 管「人怎么看这张表、点下去发生什么」：面板与导航、主面板表格、销售表、SKU 弹窗、视图状态、导入入口、设置页壳、两个辅助页。
> 计算口径不在这里：[数据清洗规则.md](./数据清洗规则.md)、[模式与系数设置.md](./模式与系数设置.md)、[采购下单流程.md](./采购下单流程.md)。

## 1. 面板与导航

| 入口 | 路径 | 视图 | 说明 |
| --- | --- | --- | --- |
| 需求表 | `/` | `src/views/InventoryPanelView.vue` | 业务主线：明细表、筛选、批量补货、添加 SKU、导入分表（代码与文档里仍叫「主面板」） |
| 采购下单 | `/purchase` | `src/views/PurchaseOrderView.vue` | 按染厂拆单、确认下单（流程见采购下单流程.md） |
| 销售表 | `/sales` | `src/views/SalesPanelView.vue` | 只读：动销指标 + 客户CR5率 + 1-12 月条数 / 销量 / 订单数 |
| 配置板块 | `/config` | `src/views/ConfigView.vue` | 一个壳两个域：备货配置 4 项 + 下单配置 5 项（代码里仍叫「设置页」） |
| 下单历史 | `/purchase/history` | `PurchaseOrderView.vue` 的 history 子面板 | 只读流水：批次 → 分订单两级 |
| 屏蔽列表 | `/hidden` | `src/views/HiddenSkusView.vue` | 顶部导航右侧的辅助入口，内容在 `HiddenSkusPanel.vue` |

- 顶部导航固定这一组顺序：**需求表 → 采购下单 → 销售表 → 配置板块**，右侧另有「屏蔽列表」。显示名只在这里改（`MAIN_PANEL.label` / `configLabel`），页面标题跟着一起用这两个值。
- 入口定义只有一处：`src/data/panels.js` 的 `MAIN_PANEL` + `mainNavEntries`（需求表 / 采购下单 / 销售表 / 配置板块）与 `utilityNavEntries`（屏蔽列表）。新增页面先改这里，不要在导航组件里硬编码。
- 文案里提到这两个页时用导航名（「需求表」「配置板块」）；代码标识仍是 `MAIN_PANEL` / `configLabel` / `ConfigView`，不要为了改名去动路由与 store。
- 旧「下单设置」`/purchase/settings` 已并入设置页，路由只保留跳转（`?panel=vat` 落到缸规则），不要再加回导航。
- `App.vue` 的 `RouterView` 带 `:key="route.path"`，**路由一变组件整体重建**。因此任何「切页还要保留」的状态不能放组件 `ref`，必须放 `inventoryView` store（见 §5）。

## 2. 销售表（`/sales`）

### 2.1 数据来源

- 品名 / 颜色 / 5 个动销指标（月均条数、订单总数、动销月份、累计客户、累积条数）与 1-12 月条数 / 销量 **都来自主面板那份 store**（`inventoryStore` 的库存行 + `salesSheet`），本页不重新计算，也不叠加第二份来源。
- 本页**没有导入入口**：未导入时的空态直接提示「请在主面板用『导入分表』清洗后导入」。历史版本里销售表自己的「导入销售表」入口已删除，不要加回来。
- 列定义：`src/data/salesFields.js` 的 `SALES_MONTH_FIELDS`（每月三列：条数 / 销量 / 订单数）、`SALES_RATIO_COLUMNS`、`SALES_TABLE_COLUMNS`。

### 2.2 行结构与聚合

- 用 `groupTableRowsByProduct()`（`src/utils/productGroups.js`）生成「品名汇总父行 + 颜色子行」两级；父行的数量列求和，**比例列按权重列加权平均**。
- 客户CR5率 = 销量前 5 客户 ÷ 该 SKU 总销量，清洗引擎输出 0~1，页面显示为百分比；它只在销售表出现，不写回主面板、不进备货配置。父行按「累积条数」加权平均（`SALES_RATIO_COLUMNS` 的 `weightKey: 'cumulativeCount'`），不做求和。
- 动销指标保留主面板导入值：销售表文件里的同名列不参与覆盖。

### 2.3 筛选

- 工具栏与主面板一致，分成「品名」「颜色」两个筛选框（`ElInput`，`clearable`，各做 250ms 防抖，`includes` 匹配），不再提供「搜索全部列」。
- 行对象预存 `searchProduct` / `searchColor` 两个小写索引，筛选只做 `includes`。
- 命中数为 0 时区分「没有匹配的数据」与「暂无数据」。

### 2.4 弹窗

颜色单元格的入口按钮与弹窗与主面板完全共用：`SkuDetailTrigger` + 页面级 `SkuDetailDialog`（见 §4），不要再写第二份。

## 3. 主面板（`/`）

### 3.1 可编辑边界

| 分组 | 列 | 交互 |
| --- | --- | --- |
| 基本信息 | 品名、颜色、色彩、树形分类 | 只读文本 |
| 数量 | 生产中、欠货、周消耗、周转入、在途库存、在仓库存 | 只读文本（导入值） |
| 信息 | 模式、评分、加权月销量、系数、预警 | 派生展示 |
| 备货 | 需安排 | **唯一可编辑列**（`ElInputNumber`），草稿存 `inventoryView` store |

另有采购清单里的分订单数量、批量补货与紧急补货弹窗的数量可以编辑。其余一律 `ElInput` / `ElInputNumber` 化都算回退，要改数据请重新导入或改源表。

品名汇总行的模式列显示 SPU 等级徽标（`S+ / S / A / B / C / Z`）：等级 = 该品名下**全部 SKU** 的月均条数之和按六档阈值判定，与当前筛选无关（阈值与口径见 [模式与系数设置.md](./模式与系数设置.md) 的 `spuGrades` 段）。

### 3.2 勾选与批量补货

1. 首列复选框维护 `selectedSkuIds`（**只存 SKU 标识**，行会随虚拟滚动装卸）。
2. 品名父行的勾选态由子行全选 / 半选推导；表头全选作用于**当前筛选结果**；点整行等同点该行复选框，父行点整行 = 全选 / 全不选其下 SKU。
3. 有勾选时出现底部浮动条 → 确认弹窗（默认数量取 `getSuggestedPlanned()`，即补到绿色带中位，**精准公斤、不做缸取整**）。
4. 确认后统一经 `applyRestockPlans()` **覆盖**写入「需安排」并进「本次采购清单」（同一 SKU 一条）。

紧急补货弹窗走同一条写入路径：调用处先把「追加」换算成绝对需安排量，再交给 `applyRestockPlans()`。

### 3.3 屏蔽（「删除」的真实含义）

- 入口是**视窗右下角固定的「屏蔽选中」小按钮**：默认无勾选时隐藏，出现时按钮计数 = 勾选的 SKU 数（比底部批量补货条更低调）。
- 规则：先在表格勾选，确认后批量屏蔽——某品名当前可见的 SKU 全部勾中时记**品名级**屏蔽，否则逐条记 **SKU 级**。
- 存储：`src/stocking/hiddenSkus.json`（`{ products: 品名数组, skus: { 唯一标识: { product, color } } }`），开发态由 Vite 插件 `/__stocking-hidden/save` 写回源文件，构建产物写 localStorage 键 `stocking-hidden:v1`；跨导入、跨刷新保留。
- 只影响**展示**：表格行、品名父行合计与 SPU 等级、预警计数、模式筛选项、勾选 / 批量补货 / 紧急补货都按可见行算；源表与销售数据不动。
- 品名级屏蔽会清掉其下已有的 SKU 记录，恢复品名时整组一起回来。
- 解除在 `/hidden`（见 §9）。添加 SKU 时唯一标识会跳过屏蔽清单用过的标识，否则新行会命中屏蔽规则直接不显示。

### 3.4 添加 SKU（唯一手动录入入口）

- 组件 `src/components/AddSkuDialog.vue` + 写入逻辑 `src/utils/skuCreate.js`（`addInventorySku()`）。
- 字段与导入的总表 / 销售表一一对应：品名 / 颜色 / 色彩 / 树形分类、7 个数量列、5 个动销指标。
- 唯一标识不用人填：按 `MANUAL-0001` 递增自动生成，并跳过屏蔽清单里用过的标识。
- 库存与销量一律按公斤录入（公斤系数固定 1），不提供出码率 / 公斤系数输入；月均条数缺省时按「累积条数 ÷ 动销月份」现算。
- 校验「品名 + 颜色」不重复。
- 写入后复用主面板的 `importToast` 提示并带「查看该 SKU」按钮打开 `SkuDetailDialog`；同时清掉挡住新行的筛选、滚到该行并短暂高亮。若该 SKU 命中品名级屏蔽，提示去「屏蔽列表」解除。
- 手动添加与导入一样只存在当前页面数据里（刷新回到种子 / 快照），1-12 月销量仍只来自销售表。

### 3.5 表格渲染

品名父行 + 颜色子行的分组由 `groupTableRowsByProduct()` 统一生成；渲染走自研虚拟列表 `src/components/VirtualList.vue`。分组、虚拟化与增量计算的性能约定见 [主面板性能优化.md](./主面板性能优化.md)。

### 3.6 筛选（表格上方工具条）

- 条件：品名 / 颜色两个关键词框（250ms 防抖，防抖后的值存组件里的 `appliedProductFilter` / `appliedColorFilter`）、「按模式筛选」多选，以及一排预警色 chip（全部 / 紧急 / 常规 / 正常 / 超库存，多选，计数 = 全部可见 SKU 里各色的行数）。
- 预警 chip 右侧的**「已下单」**是另一个维度的开关（store 里的 `onlyOrdered`，不是第五种预警色）：命中 = 该 SKU 有未作废的分订单，即「累积下单」（`row.ordered`，来自 `orderSummaryOf(purchaseStore.orderIndex, skuId)`）> 0。它和关键词 / 模式 / 预警色**取交集**，计数取当前可见行里有订单的 SKU 数。
- 点「全部」= `resetFilters()`：关键词、模式、预警色与「已下单」开关一起清空；任一条件生效时「全部」chip 取消高亮。
- 筛选条件一变就把表格滚回顶部；「添加SKU」定位新行时若被筛选挡住，也会整组清掉（含「已下单」）。
- 筛选只影响展示：表格行、品名父行合计 / SPU 等级、预警计数、模式筛选项、勾选 / 批量补货 / 紧急补货都按可见行算。

## 4. SKU 弹窗与「评分」列

- 弹窗 `src/components/SkuDetailDialog.vue` 主面板与销售表共用，传参只有 `:item` 与 `v-model:visible`；弹窗**必须挂在页面层级**，不能放进虚拟滚动行内（否则随行卸载、遮罩被裁）。
- 行内入口 `src/components/SkuDetailTrigger.vue`：24px 方形文字卡片按钮（`v-if="item && !item.isProductGroup"`），别改回 16px 的 ⓘ 小圆点。
- 弹窗内容：模式 / 加权月销量（公斤）/ 系数、健康度评分（默认 5 张维度小卡 + 1 条综合评分，红 / 黄 / 绿；按量模式改为 2 张判定卡、不显示综合评分），以及 ECharts 画的 1-12 月条数与重量。
- 主面板「评分」列（「信息」分组下紧跟「模式」）只显示综合分：红 / 黄 / 绿三档底色，悬停给出分数与风险档；不参与备货的 SKU 显示「不参与」，按量模式显示「—」。逐维度明细只在弹窗里。
- 口径与输入因子：评分算法见 [模式与系数设置.md](./模式与系数设置.md) 第 12 节，因子拼装统一走 `src/utils/skuHealth.js` 的 `buildScoringMetrics()` / `evaluateRowHealth()`，两处共用一份，不要各拼 metrics。

## 5. 视图状态（`src/stores/inventoryView.js`）

只跟「人怎么看这张表」有关的状态放这里，键包括：

| 键 | 说明 |
| --- | --- |
| `productFilter` / `colorFilter` | 关键词输入框的值 |
| `selectedWarningTones` / `selectedModeLabels` | 预警色 / 模式筛选 |
| `onlyOrdered` | 「已下单」筛选开关：只看有备货订单（累积下单 > 0）的 SKU |
| `expandedProductKeys` | `null` = 还没进过主面板（默认全展开）；`[]` = 用户主动全收起 |
| `selectedSkuIds` | 批量补货勾选，`Set<唯一标识>` |
| `selectedRowId` | 当前行 |
| `tableScrollTop` | 表格滚动位置 |
| `plannedDrafts` | 手填但未采纳的「需安排」公斤数 |

- 放 store 的原因：`RouterView :key` 会让视图组件重建，切到采购下单 / 销售表 / 设置再回来会丢状态。
- 有意**只留内存**：刷新页面回到默认视图，不写 IndexedDB。
- 筛选的防抖副本 `appliedProductFilter` / `appliedColorFilter` 仍在视图组件里，改初始化逻辑时要连它们一起从 store 取值，否则首屏高亮与筛选结果不一致。

## 6. 导入分表（唯一导入入口）

```
主面板「导入分表」
└─ ImportSplitTablesDialog.vue        选 5 张分表：产品资料 / 出入库明细 / 库存结存表 / 欠货 / 生产排单（文件名包含关键词即自动认领）
   └─ useSplitImport.js               → cleanMergeWorker.js（fflate 流式读表）
      └─ src/cleaning/engine.js       → tools/cleaning/engine.mjs 清洗出总表 + 销售表
         └─ splitTableImport.js       复用 inventoryImport.js / salesImport.js 解析
            └─ ImportSourcesDialog.vue 预览确认（总表 + 销售表必须同时存在，按「唯一标识」关联）
               └─ useSourceImport.js  → inventoryApply.js / applySourceImport.js 写 store 并落快照
```

- 主面板不再提供整表「保存Excel」导出（只留「本次采购清单」与「库存导入模板」两个导出），也没有旧版「直接选总表 + 销售表」的导入入口。
- 清洗引擎另外支持可选的「出码率」表（缺表时码单位 SKU 会被剔除），口径见 [数据清洗规则.md](./数据清洗规则.md) 第 2 节。
- 确认后由 `applySourceImport()` 落快照（gzip 进 `snapshots`，只留最近 5 份，内容哈希相同只更新时间），细节见 [数据持久化方案.md](./数据持久化方案.md) 第 10 节。
- 清洗口径本身只改 `engine.mjs`，见 [数据清洗规则.md](./数据清洗规则.md)。

| 域 | 项 | 组件 |
| --- | --- | --- |

## 8. 下单历史（`/orders`，只读）

- 把 `orders[]` 聚成「批次（`batchId`）→ 分订单」两级，聚合全在 `src/purchase/history.js`（`buildOrderHistory()` / `filterHistory()`），页面不再自己算一遍。
- 版式是**单表头 + 与子行同列对齐的批次分组带**（子行缩进 24px + 左侧引导线，默认只展开最近一个批次）；不要加第二张表或第二套表头。
- 作废单灰显但不进合计，默认只显示有效单。
- 不加写入口：到货 / 改单 / 作废仍走 `stores/purchase.js` 与订单弹窗（见采购下单流程.md 第 3.4 节）。
- Excel 导出用 `src/utils/xlsxWrite.js` 的 `saveWorkbook(sheets, fileName)`（`sheets = [{ name, rows, widths }]`）；主面板「本次采购清单」那份历史导出暂未迁移，新页面别再造第三种写法。

## 9. 屏蔽列表（`/hidden`）

- 内容在 `src/components/HiddenSkusPanel.vue`；导航入口不带数字，数量在页面工具栏按 **SKU 计**：整组屏蔽的品名按当前数据里该品名的 SKU 数展开。
- 列表是按品名分组的树，可按品名 / 颜色 / 唯一标识搜索；品名可展开看 SKU；品名与 SKU 都能多选后统一解除，也支持逐个解除或全部解除。

## 10. 手验清单

1. 主面板筛选 → 切到采购下单 → 切回：筛选、展开、勾选、滚动位置、未采纳的「需安排」草稿都在（含「已下单」开关）。
2. 主面板点「已下单」chip：只剩「累积下单 > 0」的 SKU，chip 高亮且计数与行数一致；与「紧急」等预警 chip 叠加时取交集；点「全部」后恢复整表。
3. 勾选若干行：右下角「屏蔽选中」出现且计数正确；确认后主面板行消失、父行合计与预警计数同步；`/hidden` 能解除并回来。
4. 导入一次 5 张分表：Worker 清洗完成 → 预览弹窗显示总表与销售表行数 → 确认后主面板与销售表都有数据。
5. 主面板点颜色格旁的方形按钮：弹窗显示模式 / 评分 / 1-12 月图表；销售表同一 SKU 弹窗内容一致。
6. 「添加SKU」填最小必填项：新行出现在表格里并高亮，唯一标识是 `MANUAL-00xx`，toast 能打开弹窗。
7. 设置页改任一参数不点「确定」直接切页：有未保存提示；点「确定」后主面板对应数值变化。
